## 结论

本轮达到当前近似 Demo 的预览目标：前段小幅测量波动没有改变期望 TCP 姿态，明显转动时出现连续的姿态和位置绕转响应，短暂质量问题保持目标、长时失效归零。第七步真实只读预览可据此继续推进第八步软件开发；没有完成实际机械臂姿态跟随或绝对角度精度验证。

| --- | ---: | ---: | ---: |
| 位置距离 | 0.69 mm | 0.34 mm | 0.34 mm |
| 姿态角度 | 2.91° | 0.72° | 0° |

期望 TCP 姿态没有在这段随原始倾斜噪声转动，位置仍允许约 0.56 mm 的最大波动，符合用户允许误差的 Demo 要求。

约第 32 秒后，测得目标转动开始明显增大，期望姿态逐步改变到最大约 22.3°，同时出现位置绕转。记录的目标到 TCP 偏移长度约 154 mm，因此方块转动带来数十毫米的期望 TCP 位移是相对变换的预期行为，不等于方块中心移动了相同距离。

源码与记录均使用 `T_mapped_target × T_target_tcp_offset` 生成期望目标；离线重算位置与日志一致。本结论验证计算与观测响应，不宣称每个实际手持轴的符号、转角或真实机械臂执行已经验收。

## 为什么打印 22°和末尾约 10°不表示相机误差

`rotation_error_deg` 的定义是期望 TCP 与实际 TCP 的旋转差。实际机械臂被要求保持不动，所以期望目标改变后，该差不会由机器人运动消除；同理，终端中的 20 mm/s、3°/s 也是一步预览速度，不是实际机器人运动。暂停状态原来缺少角差字段，却被终端默认打印为 0；现已改成 `TCP angle gap=unavailable`，有数据时显示真实角差，JSON 字段保持不变。

用户说已大致回到原位，但数据最后 3 秒的期望角差仍经历约 3.3–14.6°变化，结束前没有长时间稳定平台。末帧测得的原始目标相对记录姿态仍差约 6.36°，滤波后约 8.31°，期望 TCP 相对静止实际 TCP 约 9.75°。未精确回位、末段仍在变化、观测偏差和滤波滞后都可能贡献；不能仅凭此记录分离，也不能把全部 9.75°归因于约 2°死区容差。

按当前近似 Demo 要求，本轮不因回位未精确到零要求重做整组。后续动作结束多停留数秒便于看收敛；需要在新姿态重新记录关系时可用 T。精确回位的误差上限仍没有测定。
