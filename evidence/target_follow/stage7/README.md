# 第七步位姿预览证据

日期：2026-10-09。本步为只读数据计算，没有发送机器人运动指令。软件/模拟验证没有连接真实设备；用户另提供一轮 90 秒真实相机/反馈的只读预览，分析见 [20261009_122550_231933](20261009_122550_231933/analysis/README.md)。现场操作见 [第七步说明](../../../docs/目标跟踪第七步位姿预览操作-20261009.md)。

## 实现与验证范围

- 目标到 TCP 完整相对变换、记录时重合、三轴旋转与位置绕转、平移和组合运动。
- SO(3) 姿态低通、真实观测间隔、3°/2°累计旋转死区、±180°与四元数符号等价。
- 1.0 与 0.5 映射同时作用于姿态和位置偏移，完整非零 TCP 旋转换算法兰参考。
- 参考从真实反馈出发，线/角速度及加速度限幅，不累计虚拟机器人运动。
- 质量暂时无效时冻结原目标；可信图像过期、丢失、显著跳变、无效输入或反馈过期时速度归零。
- 恢复保留滤波/死区基准；重新按 T 才重设记录关系，自动记录只执行一次。
- 独立只读话题与记录服务，保留外部合成源，采样完成关闭自有节点；窗口只有 T 记录客户端。

构建日志 `build.log`，几何及旧链路回归 `regression.xml`（43 项通过、1 项 GUI 单独用例未在纯检查中启用）。最终四项 ROS/窗口模拟记录见 `ros_final.xml`、`ros_contract/states.jsonl`、`launch_full/`、`launch_half/` 与 `launch_gui/`。窗口集成使用合成画面并检查客户端仅有 `/target_follow/pose_preview/teach`，没有 S/X 运动客户端。

早期一轮重新记录检查固定等待 20 ms 后读到旧状态（`teach_count=1`）；记录服务已经成功，但异步状态尚未收到。测试改为等待实际 `teach_count=2` 的新预览，产品记录计算无需为此改变。另由历史静止回放发现质量间断后重设姿态滤波基准会造成目标变化，已改为继续沿用旧滤波/死区基准，并新增回归验证。

## 用户历史静止数据的离线预览

`replay_static_preview.py` 使用第六步原始静止数据，按 Demo 0.10 px、2 帧质量重算；通过观测为 303/226 个，与第六步阈值回放一致。固定 TCP 使用该组第一条法兰反馈和实际 TCP 配置近似，输入目标为真实记录值；不模拟在线配对、保持时序或伺服执行。

| 预测目标相对记录时 TCP 的偏差 P95 | 原静止组 | 靠近后静止组 |
| --- | ---: | ---: |
| 未滤波完整关系：位置 | 20.52 mm | 10.74 mm |
| Demo 滤波/死区后：位置 | 6.58 mm | 0.74 mm |
| 未滤波完整关系：姿态 | 4.84° | 3.81° |
| Demo 滤波/死区后：姿态 | 1.22° | 0° |

这些是原始测量生成的假想 TCP 目标偏差，包含首次记录的测量偏差，不是实际机器人位移、绝对精度或相对自身均值的抖动指标。靠近组未触发死区，旧静止组有一次约 1.22°的目标姿态调整，之后保持；这说明 Demo 处理减少了无意义变化，没有证明姿态测量本身变准。
