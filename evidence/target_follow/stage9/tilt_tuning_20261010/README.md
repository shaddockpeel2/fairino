# 第九步倾斜暂停与恢复阈值修正

现场会话：`20261010_134555_196814`。用户确认平移可正常跟随，一倾斜就停止。本次读取原日志、修正配置并构建/模拟，未连接真实机械臂或相机、未发送新的硬件运动。

实际原因是两层观测阈值连锁触发：

1. 原基坐标连续性用 6°抖动余量加 60°/s × 图像间隔，约 68 ms 一帧时只允许约 10°变化。记录中 14 帧被判 orientation_jump，触发暂停与重新确认。
2. 第二次暂停恢复时，原始目标姿态变化约 20.242°，刚超过旧 20°恢复阈值，于是 paused_reteach 保持到退出。位置变化只有约 1.738 mm，半幅映射后的旋转差约 10.125°。

本轮已有 619 条 ServoCart，全部返回 0；两次暂停、一次恢复；停止、结束、关闭均返回 0。最终 report 为 stopped/signal，因为用户退出，不能据此忽略此前等待重记录的状态。原始日志保持不变。

## 修正

- 第九步独立 `orientation_check_pose_demo.yaml`：观测抖动余量改为 25°，另加原有 60°/s 速率项；2 帧确认和 350 ms 可信年龄限制仍生效。旧只读 Demo 的 6°余量不变。
- 驱动原始目标恢复转角容差改为 40°，与默认半幅映射匹配；位置恢复容差仍为 40 mm。
- 实际位姿运动范围仍为开始 TCP 周围 200 mm/20°，姿态滤波 0.8 s、死区 6°/4°、映射 0.5、角速度 3°/s 和加速度 10°/s²继续生效。新观测容差不会直接生成相同大小的机器人旋转。
- 自动恢复仍需新的可信图像和可用反馈，从实际 TCP 重新锚定并清零速度，保留原相对关系。超出独立运动范围或大幅重定位仍提示 S 重新记录。
