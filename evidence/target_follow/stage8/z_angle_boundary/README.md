# Z 轴跨 180°表达被 SDK 拒绝的修复（2026-10-10）

用户报告 Z 轴 2.5°测试没有动静。两轮实机记录 `20261010_105736_71024`、`20261010_105759_71329` 都是 fault，GetInverseKinRef 在预检第 3 个点返回 112，真实伺服命令数为 0；没有进入 ServoMoveStart。

SDK 的本地 `robot_error.h` 将 112 定义为“目标位姿无法到达”。本轮已用相同目标、相同参考关节作只读对照，定位到 RPY 表达范围：

| 预检路径点 | 原始邻近 Yaw | 同姿态规范 Yaw | 原始 / 规范逆解返回码 |
| --- | --- | --- | --- |
| 0 | 179.7515° | 179.7515° | 0 / 0 |
| 2 | 179.8963° | 179.8963° | 0 / 0 |
| 3（原失败点） | 180.1592° | −179.8408° | 112 / 0 |
| 10（转出终点） | 182.2515° | −177.7485° | 112 / 0 |

规范表达的 11 个点全部返回 0；跨过 180°后的 8 个原表达全部返回 112。`readonly_comparison.json` 保存全量参数、返回码、关节解及启动前 ROS 发布者情况。`check_z_angle_boundary.py` 唯一调用的机器人方法是 GetInverseKinRef，没有开始、运动、使能或停止调用，真实伺服命令数为 0。该对照使用已记录的路径和关节种子，不宣称新一轮实机运动已经通过。

修复保留内部 SO(3) 与邻近 RPY，在 NativeClient 的绝对位姿 GetInverseKinRef 和 ServoCart 边界将三个角度规范到 ±180°，物理变换不变。TCP 补偿、原 2.5°轨迹、关节连续性和停止限制仍按原定义执行。Mock 反馈也按规范表达输出。每个预检/伺服样本新增 `target_sdk_mm_deg`，失败报告提供具体点和实际 SDK 编码，明确运动尚未开始。
