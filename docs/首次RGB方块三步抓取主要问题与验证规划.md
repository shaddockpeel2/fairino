# 首次 RGB 方块三步抓取：主要问题与验证规划

> 日期：2026-09-10
> 对象：FR3-C、DaBai DCW2、YDI-J22，30×30×30 mm 彩色方块。
> 目的：逐项关闭影响首次抓取的主要问题，不把长期可靠性验收全部作为首次试验前提。
> 本文是待验证清单；勾选必须有实际结果，不代表已经执行真机验证。

## 1. 当前结论与范围

本体碰撞、运动学核对、相机接入、手眼和 TCP 已有基础；文档记录了 RViz 多组真机 Plan/Execute 成功。下一阶段可以集中做首次抓取联调，无需重做整个底层。

但当前源码尚未形成“真实方块定位 → 三段运动 → 真实夹爪闭合 → 携物提升”的完整流程。夹爪实心碰撞包络和硬件错误传播也会直接影响执行，必须处理。

首次范围固定为单个静止方块、人工清场、低速、分段执行。首次完成后保持夹持，不自动松爪或循环。后续放回和释放需单独安排。

## 2. 先明确三个动作的几何定义

所有位置使用米；竖直方向统一使用已核对的 `base_link` +Z，不直接用工具局部 Z 代替上下方向。末端目标统一为 `grasp_frame`。

设方块顶面中心为 `(x, y, z_top)`，抓取 TCP 相对顶面的下降深度为 `d`：

| 阶段 | TCP 目标 | 动作 |
| --- | --- | --- |
| 1. 接近 | `(x, y, z_top + 0.015)` | 夹爪预张开，朝下并对齐方块；通过 MoveIt 到达目标上方 |
| 2. 抓取 | `(x, y, z_top - d)` | 保持姿态竖直下降，再闭合夹爪 |
| 3. 提升 | `(x, y, z_top - d + 0.150)` | 确认夹持后竖直抬升 150 mm，并持续保持 |

**第二步下降距离为 `0.015 + d`，不一定是 15 mm。** 若把 TCP 设在方块半高，则 `d=0.015 m`，下降 30 mm；但当前 TCP 定义为柔性指共同闭合尖端，不保证它就是实际夹持中心，因此该数值只能作为几何示例，不能直接作为真机参数。

- [ ] 现场确认“上方 15 mm”指 TCP 相对方块顶面的距离。
- [ ] 确定夹爪朝下的姿态和绕竖直轴的对齐角。
- [ ] 实测确定 `d`、预张开开度、闭合开度、停留时间。
- [ ] 确认抓取高度下最低指尖不会碰桌，张开时也有净空。

记录：`d=____ mm；张开=____ mm；闭合=____ mm；停留=____ s；姿态依据=____`。

## 3. 主要问题与逐项验收

### P1：执行错误必须能够阻断后续动作

现状：`fairino_hardware_interface.cpp` 中 `ServoJ` 返回非零时仅打印日志，`write()` 仍返回 OK；有限值检查的结束指针为第六个元素，按半开区间规则遗漏第六轴。控制频率配置为 100 Hz，但 `ServoJ` 参数写死为 0.008 s。

源码：[`fairino_hardware_interface.cpp`](../src/fairino_hardware/src/fairino_hardware_interface.cpp)、[`ros2_controllers.yaml`](../src/fairino3mt_v6_moveit2_config/config/ros2_controllers.yaml)。

- [ ] 修复位置和扭矩命令检查范围，覆盖全部六轴。
- [ ] 将 SDK 发送失败传递为控制/轨迹执行失败，并验证上层不会继续下降、闭爪或提升。
- [ ] 对照本地 V3.9.2 SDK 核对 Servo 模式生命周期、启动和退出行为。
- [ ] 核对实际控制周期与 ServoJ 参数，依据对应版本接口要求确定一致配置，不盲目只改一个数字。
- [ ] 先通过离线测试或模拟返回错误验证失败分支，再在现场验证低速短轨迹与取消；故障注入不携带物体。

通过条件：六轴异常命令被拒绝；执行失败或取消后任务不进入下一阶段；低速短轨迹无持续 SDK 错误，控制周期有核对记录。

### P2：夹爪开口与桌面碰撞需要真实可用的处理

现状：夹爪碰撞体为 180×100×200 mm 实心盒，填满抓取开口。法兰到包络末端约 203 mm，而 TCP 为 178 mm；垂直向下时，包络比 TCP 多伸出约 25 mm。TCP 在顶面上方 15 mm 时，包络已进入方块约 10 mm。这是当前模型的几何推算，实际规划还需检查运行场景。

源码：[`ydi_j22_placeholder.xacro`](../src/fairino_description/urdf/ydi_j22_placeholder.xacro)、[`模型总入口`](../src/fairino3mt_v6_moveit2_config/config/fairino3mt_v6_robot.urdf.xacro)。

- [ ] 核对实物夹爪张开/闭合时的最低点、外侧范围及相机/支架突出范围。
- [ ] 将夹爪本体与必要的手指接触区域拆开建模，使抓取开口不再被整块实体填满；首版可采用经过实测核对的简化几何。
- [ ] 在 PlanningScene 中加入实际桌面、方块和本次轨迹附近的实体障碍物；RViz 网格不算桌面碰撞体。
- [ ] 只针对目标方块与预期接触手指配置必要接触许可；保留桌面、本体、相机和其他障碍物检查。
- [ ] 验证接近、下降、携物提升均可规划；提升时方块作为 attached object 参与碰撞检查。
- [ ] 修改后重载 MoveIt/RViz，确认运行模型与源码一致，并回归本体碰撞检查。

通过条件：合理抓取不再被实心占位盒误拦；人为设置的桌面穿透和非接触部位碰撞仍被拒绝。不得通过全局关闭碰撞来通过验收。

### P4：确认 30 mm 方块能够夹住并持续保持

现状：真实 `GripperCommand` 已接入，开度映射已测量；但硬件没有位置、力或夹持反馈，action 完成不等于已抓住。驱动退出也不保证持续保持。

参考：[`夹爪驱动说明`](../src/fr3c_gripper_driver/README.md)。

- [ ] 在方块有支撑、机械臂不提升的情况下，验证预张开、抓取深度与闭合开度组合。
- [ ] 依据实物夹持效果确定闭合量，不把 30 mm 物体宽度直接当作最终闭合命令。
- [ ] 持续保持至少 30 秒，观察是否松脱、延迟开合或输出异常。
- [ ] 首次提升前由现场观察确认夹住；记录该确认是人工完成，不能标为自动夹持检测通过。

## 4. 推荐验证顺序

1. **冻结参数定义**：先完成第 2 节，避免把顶面、物体中心与夹持中心混为一谈。
2. **修正执行链与碰撞**：处理 P1、P2；P3 静态视觉和 P4 有支撑夹持验证可独立开展。
3. **实现三步任务**：处理 P5，先仅规划，审查全部路径和失败分支。
4. **核对现场与落点**：完成 P6，先较高净空验证，再到顶面上方 15 mm，停住核对。
5. **分段实测**：下降到抓取位 → 闭合 → 人工确认 → 可先小幅试提观察滑落，再完成从抓取位置累计 150 mm 的提升。
6. **记录首次结果**：确认三步完成后，在相同条件下重复 3 次，记录偏差与失败原因；这属于首次联调，不等于长期成功率验收。
