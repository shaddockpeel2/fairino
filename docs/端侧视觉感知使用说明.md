# 端侧视觉感知：独立演示与接口

更新日期：2026-10-08（北京时间）。

本功能新增在现有 Tk 界面的“端侧视觉感知”页签，支持物体分类、颜色识别、单人人脸追踪。只输出二维视觉结果和画面，不控制机械臂、夹爪，不生成抓取坐标，不依赖手眼标定或深度图。

## 1. 在现有界面使用

当前相机已启动时，保留原有系统，使用原来的方式重新打开 GUI：

```bash
cd /home/industio/fairino_ws
scripts/voice/start_dialogue_gui.sh
```

切到“端侧视觉感知”后，页面按需启动独立后台并订阅 `/camera/color/image_raw`。默认显示原始画面，不做识别。选择功能后点击“开始识别”；切换功能或离开本页会停止当前识别，再次开始需要点击按钮。

重开 GUI 是为了载入新代码；本次开发没有重启现有相机、机器人或模型进程。启动器不会自动打开相机设备，也不会重启原有感知。

页面包含实时标注画面、目标列表、类别/颜色数量、人脸 ID/中心点/短轨迹、处理帧率及耗时。保存截图会同时保存标注图和该帧的 JSON 结果，目录为 `evidence/vision/captures/`。

相机、后台和 GUI 必须处于相同的 `ROS_DOMAIN_ID`。默认完整系统通常使用域 0；相机独立 bench 启动脚本默认使用域 187。后台 socket 也按域区分，避免串用其他相机环境。


## 3. 三项算法与范围

### 物体分类

复用 `src/fr3c_camera/models/best.rknn` 和现有 `RKNNDetector` 的前处理、RKNNLite 推理及后处理。模型输出 16 类具体物品；新适配层允许同时展示多个检测结果，并按旧项目映射归并四大类：

| 大类 | 模型已有物品 |
|---|---|
| 可回收物 | 报纸、易拉罐、书本、旧书包 |
| 厨余垃圾 | 鱼骨、蛋壳、苹果核、西瓜皮 |
| 有害垃圾 | 注射器、过期化妆品、废电池、过期药品 |
| 其他垃圾 | 卫生纸、桃核、烟头、一次性筷子 |

沿用原项目的演示映射；不将其描述成各地垃圾分类规则。检测置信度属于具体物品检测，四大类由映射得到，没有另外训练的“四分类置信度”。模型未覆盖的物品不能保证正确归为“其他”。

### 颜色识别

读取现有 `color_target_2d.yaml` 中的红黄蓝绿 HSV 阈值、形态学设置和轮廓筛选参数，调用 `find_color_candidates`。支持同时展示多个目标，包括同色多个目标。保持既有轮廓筛选范围，优先用于当前方块等演示对象；不是任意物体全图主色识别器。没有模型概率，UI 不伪造置信度。

### 人脸追踪

使用 OpenCV 官方 YuNet 2023mar ONNX 模型，通过 OpenCV DNN 在 CPU 本地运行。最大检测边长 320，检测框映射回原图。模型及 MIT 许可证包含在 `assets/vision/`，运行不访问互联网。

初次选最大人脸；随后用速度预测、检测框重叠、中心距离、尺寸门限进行关联，平滑人脸框，并记录短轨迹。短暂丢失时不跳到无关人脸，超过默认 0.8 秒结束该轨迹；重新捕获分配新 ID。长时间断流、功能切换或优先任务暂停都会清除旧轨迹。

ID 仅表示一段连续轨迹，不识别身份。检测可看到多张脸，但第一版仅跟踪其中一人。相邻人脸交叉、严重遮挡和快速移动下不能保证 ID 始终稳定，后续可以升级多人关联。

## 4. 与原系统的边界

- 本模块没有修改原有抓取感知、决策、Action、视觉伺服、Qwen 调度或启动脚本。对已有文件的接入限于 UI 页签挂载/清理、workspace 保存及相机包的新可执行入口；保留工作区内其他正在进行的改动。
- 新后台独立进程、独立节点与 `/edge_vision/*` 接口，使用现有相机图像话题，不发布到旧感知话题，也不创建机器人服务/Action 客户端。
- 只读取 `/fr3c_first_grasp/state`、`/perception/blue_cube_localizer/status` 和 `/fairino/control_state`；通过现有 Qwen `health` 接口读取资源状态。UI 同时报告本窗口是否正在处理对话、录音或机械任务。
- 原任务或视觉伺服忙碌、大模型推理/恢复、既有感知暂停时，新模块自行暂停。原有 RKNN 感知已经使用 NPU 时，新物体分类暂停，避免重复 NPU 感知。既有 CPU 颜色感知空闲时可同时演示。
- 完全未出现过的旧状态允许独立演示；曾经出现但失去心跳的旧状态会让新模块暂停。视觉伺服的原状态是持久化字符串事件，不按心跳处理。
- 新进程 `nice=10`，OpenCV/BLAS 单线程，最大 8 FPS，仅保留最新输入帧。不开启识别时不加载模型；关闭/切换识别后由工作线程释放模型。
- 这是读取状态并逐帧避让的机制，不是设备级原子锁。状态检测有约 0.5 秒轮询延迟，已经开始的一帧会自行完成。原系统不会等待新模块，但无法承诺任何并发场景的性能影响为零。涉及机械运动的正式展示，推荐先停止新识别；页面本身没有任何机械运动入口。

页面离开后停止识别；纯预览在没有 UI 拉取后停止图像处理。外部启动的后台在 GUI 关闭后保留，GUI 启动的后台只由该 GUI 清理，不关闭原有系统。

## 5. 独立接口

手动启动后台（仍然只订阅已有相机）：

```bash
cd /home/industio/fairino_ws
scripts/vision/start_edge_vision.sh
```

配置校验无需启动设备：

```bash
scripts/vision/start_edge_vision.sh --validate-only
```

可使用 `--config /绝对路径/config.yaml`、`--image-topic /其他/image_raw`，或通过 `FR3C_EDGE_VISION_PYTHON` 指定新后台 Python。默认复用 `.venv-yolo`，不安装或升级旧依赖。参数来自 `config/vision/edge_vision.yaml`。

### ROS 2

| 接口 | 类型 | 用途 |
|---|---|---|
| `/edge_vision/objects/start`、`stop` | `std_srvs/srv/Trigger` | 物体分类开关 |
| `/edge_vision/colors/start`、`stop` | `std_srvs/srv/Trigger` | 颜色识别开关 |
| `/edge_vision/faces/start`、`stop` | `std_srvs/srv/Trigger` | 人脸追踪开关 |
| `/edge_vision/{objects,colors,faces}/results` | `std_msgs/msg/String` | JSON 结果 |
| `/edge_vision/{objects,colors,faces}/debug_image` | `sensor_msgs/msg/Image` | 标注图，保留原图 header |
| `/edge_vision/status` | `std_msgs/msg/String` | JSON 状态、暂停原因或错误 |

一次只有一个功能运行；启动另一项会替换上一项。停止一个未运行的功能不会停止另一项。`start` 返回成功表示请求已接受，不代表模型已加载或当前允许推理；具体看状态。图像只在收到有效新帧时发布，消费者应同时检查状态、时间戳和 `epoch`。

```bash
source /opt/ros/humble/setup.bash
source /home/industio/fairino_ws/install/setup.bash
ros2 service call /edge_vision/colors/start std_srvs/srv/Trigger '{}'
ros2 topic echo /edge_vision/colors/results --once
ros2 service call /edge_vision/colors/stop std_srvs/srv/Trigger '{}'
```

JSON 包括 `mode/state/epoch/sequence/ros_stamp_ns/frame_id/targets/counts`，有效帧还包括尺寸和时间指标。目标包含 `bbox_xyxy/center_uv/label`；物体额外包含物品类、四大类和检测置信度，颜色额外包含颜色和面积，人脸额外包含轨迹 ID。暂停、停止和断流会清除目标，不把旧框当作新结果。

### 本地 socket

路径：`evidence/vision/runtime/edge-vision-<ROS_DOMAIN_ID>.sock`，权限 0600。

每次连接发送一行 JSON，返回一行 JSON，然后关闭连接：

```json
{"op":"start","mode":"objects"}
{"op":"stop"}
{"op":"status"}
{"op":"snapshot","foreground_busy":false}
```

`snapshot` 返回 `{schema_version, ok, result, jpeg}`；`jpeg` 是标注画面的 Base64，与 `result` 来自同一处理帧。`status` 不返回 JPEG。`foreground_busy=true` 对新模块施加短期暂停，不改变旧模块。Python 客户端为 `fr3c_voice.edge_vision_page.EdgeVisionClient`。

同工作区、同 ROS 域的后台使用文件锁防止重复启动。后台日志在 `evidence/vision/runtime/edge-vision.log`。

## 6. 验证记录与现场验收

完成：相机/对话套件在本轮回归中 300 项通过；之后补充并通过慢消费者、ROS 发布版本检查用例，最终新增模块独立测试合计 28 项通过。新增测试覆盖四色多目标、四大类映射、单人短时丢失与重建、停止/切换丢弃旧结果、断流清空、任务优先级、本地接口、节点构造、中文标注截图和发布与停止解耦。相机包已完成 `colcon build --symlink-install --packages-select fr3c_camera`。

YuNet 已在当前 OpenCV 4.10 环境真实执行，用 OpenCV 测试人像的五帧平移验证同一个轨迹 ID；该记录是测试图片验证，不等同于真人相机验收。模型资产不需要重新训练。

ROS 域 230 的模拟联调通过独立 Trigger 服务启动/停止、四色结果话题、人脸追踪、原任务忙碌后的暂停/恢复，以及断流结果清除。记录为 `evidence/vision/acceptance/ros-smoke.json`。GUI 按需启动实际后台和 socket 开关也已通过，关闭时只清理自己启动的进程。集成 UI 模拟画面截图为 `evidence/vision/acceptance/ui-color-demo.png`，不作为真实相机识别证据。

物体分类的新增适配层已用模拟检测结果验证类别、多个目标和置信度，底层继续调用原有 RKNN 检测器。本轮没有为新页面重新进行真实物品 NPU 推理或抓取验收。

现场验收建议：现有相机下依次摆放模型覆盖的垃圾物品、红黄蓝绿方块，并由真人左右移动/短暂遮挡；确认目标框、标签、数量和人脸轨迹。再检查功能切换、停止、断流和原有任务忙碌后的暂停/恢复。新功能的真实相机效果、整机并发性能及实际物品识别准确率应由现场测量记录，不从离线测试推断。
