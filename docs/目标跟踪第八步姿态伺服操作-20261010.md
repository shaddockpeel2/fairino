# 第八步：独立小角度 TCP 姿态伺服

第八步已增加独立 `rotation_probe` 执行端和 `rotation_demo.sh` 入口。它不接相机、标签或第七步预览目标，只按本次开始时的实际 TCP 位姿做小角度往返。初始位置与上次不同也可以重新运行，不需要回到历史“最好位置”。软件/模拟与实机验证分开记录；2026-10-10 首轮 X 轴 2.5°实机往返已完成，用户确认机械臂成功运动，日志确认 TCP 补偿、返回和正常结束停止。随后 Y 轴 2.5°往返日志也正常完成。Z 轴首轮在跨 180°的逆解预检被拒绝，修复 SDK 编码后两轮往返均正常，用户确认无问题。随后组合往返及预定中途停止也正常完成，第八步达到当前 Demo 检查范围；下一项进入第九步真实视觉位姿闭环开发。

按本轮要求，以方向正确、明显平滑、尖端没有明显意外绕动、停止可用作为 Demo 判断；不要求逐度精确或毫米级回位。视觉静止时的几度波动允许被忽略。相关质量/稳定参数已放宽，见文末。

## 先只读，再逐轴往返

只读检查，**不加 `--move` 就不会发送运动命令**：

```bash
/home/industio/fairino_ws/scripts/target_follow/rotation_demo.sh
```

报告 `motion_readiness_problem` 为空表示当前检查允许开始；非空按其具体提示处理。每轮会打印报告目录。

逐条运行，上一条结束且方向/尖端行为正常后再进行下一条：

```bash
/home/industio/fairino_ws/scripts/target_follow/rotation_demo.sh --move --axis x --angle-deg 2.5
/home/industio/fairino_ws/scripts/target_follow/rotation_demo.sh --move --axis y --angle-deg 2.5
/home/industio/fairino_ws/scripts/target_follow/rotation_demo.sh --move --axis z --angle-deg 2.5
```

X/Y/Z 是**基坐标轴**；正角按右手方向。默认缓慢转出 2.5°、保持 0.5 秒、回到本轮起始姿态、再保持 0.5 秒，随后执行 StopMotion/ServoMoveEnd。转动时会同步调整法兰 XYZ，使标定 TCP 尖端的位置基本保持；不能把法兰移动误认为 TCP 意外绕动。

默认角速度 3°/s、角加速度 10°/s²，SDK 周期参数 8 ms。参考每次最多前进一个发送周期，调用慢时动作相应变慢，不追赶补发。报告记录实际调用耗时和发送间隔，不宣称固定 125 Hz。

三个方向正常后，可做一次小幅组合转动（绕 `(1,1,1)/√3` 基坐标轴，整体角度 2°，不是每个欧拉角各加 2°）：

```bash
/home/industio/fairino_ws/scripts/target_follow/rotation_demo.sh --move --axis xyz --angle-deg 2
```

负角用 `--angle-deg -2.5`。需要转出后保持在该处可加 `--one-way`；默认往返更适合首轮操作。程序当前支持 0.1–5°、最高 5°/s 和 20°/s²；首次沿用默认即可。

2026-10-10 修复：当前法兰 Yaw 接近 179.75°时，Z 正向轨迹的邻近表达会超过 180°，原厂逆解对该表达返回 112，程序在运动开始前退出。只读对照确认换成相同姿态的负角表达后，整条 11 点路径可求解。现在内部保留 SO(3) 与邻近 RPY，绝对位姿的 GetInverseKinRef/ServoCart 请求统一将角度规范到 ±180°；运动目标、TCP 补偿和幅度不变，仍检查逆解与关节连续性。日志新增 `target_sdk_mm_deg`，可对照内部弧度和实际 SDK 编码。修复后直接重跑原 Z 命令，不需要先移动方块或重新摆放初始位置。

## 停止与重新开始

同一终端 Ctrl-C，或另一终端：

```bash
/home/industio/fairino_ws/scripts/target_follow/stop_servo.sh
```

组合往返正常后，检查预定中途停止（开始旋转约 1 秒后发出停止）：

```bash
/home/industio/fairino_ws/scripts/target_follow/rotation_demo.sh --move --axis z --angle-deg 2.5 --stop-after-s 1.0
```

2026-10-10 已有两轮真实预定中途停止：约 1 秒后停住，实际转角约 1.28°/1.23°，停止返回 0 且反馈确认。用户觉得动作不明显，这个小幅水平转动在保持尖端位置时可能不容易肉眼看清；以本轮反馈记录完成当前 Demo 检查，不需要反复重跑或加大角度。

中途停止后保持在停止处，**不会再自动回起点**。再次运行会从停止后的实际位姿重新建立中心；不需要精确恢复上一次起始位置。停止请求在当前 SDK 调用返回后处理，服务成功表示已接收，实际 SDK 结果看报告中的 `stop_motion_code`、`servo_end_code` 和停止反馈。

## 记录与必要限制

每轮保存到 `evidence/target_follow/stage8/<时间_进程号>/`，含 `tcp_used.yaml`、`samples.jsonl`、`report.json` 和 ROS 日志。可用 `--output-dir /绝对路径/新目录` 指定位置，用 `--tcp-file /绝对路径/标定文件.yaml` 指定完整 TCP 标定。

重点看 `result`、`max_observed_rotation_deg`、`max_observed_tcp_drift_mm`、`final_tcp_angle_to_start_deg`、停止返回码和实际发送间隔。这些数用于解释效果和调参，不作为精密验收表。`live_rotation_validated` 保持 false，现场结果另行记录，避免软件自动把 SDK 成功等同于演示通过。

开始前沿旋转路径采样 11 个点，以实际关节为种子调用原厂 `GetInverseKinRef`，检查能否连续求解；运动中记录关节并检查异常突变。邻近欧拉角表达覆盖 ±180° 和数学上的 Pitch ±90°，这并不消除机器人机构奇异位形。当前入口没有模型碰撞预测；第九步再适配旋转预测。

TCP 偏离中心超过 15 mm、参考比反馈超前超过 5°、关节单次反馈突变超过 15°、数据过期、控制器故障或 SDK 错误会停止。本步不以小误差判失败，但仍限制明显异常。发生 fault 时报告会写出具体原因，处理后重新运行。

## 已放宽的视觉稳定配置

第七步入口现在默认加载 `pose_preview_demo_stable.yaml`：

| 参数 | 当前默认 | 行为 |
| --- | --- | --- |
| 位置/姿态低通 | 0.25 s / 0.8 s | 接受更大的响应延迟以减少抖动 |
| 旋转死区 | 6°进入 / 4°退出 | 忽略几度变化，明显累计转动才响应 |
| 旋转映射 | 0.5 | 末端旋转和位置绕转一起减幅 |
| Demo 连续性抖动余量 | 6° + 60°/s × 图像间隔 | 正常测量波动较少导致质量重确认 |
| 歧义阈值/连续确认 | 沿用 0.10 px / 2 帧 | 复用已可用的 Demo 质量策略 |

6°死区作用于滤波后的相对变化，0.5 映射还会进一步减小动作；不要用很小的目标转角判断是否跟随。需要更明显响应时可用 `rotation_mapping_gain:=1.0`。原 `pose_preview.yaml` 保留，可显式 `params_file:=/home/industio/fairino_ws/src/fr3c_target_follow/config/pose_preview.yaml` 使用旧 0.4 s、3°/2°和 1.0 配置。

这个配置在第七步仍是只读预览，第八步运动也不消费视觉。相机位姿测量有初始偏差时，在当前合适位置按 T 重新记录关系即可；不同初始位置无需精密对齐。此前跨视角基坐标差异留待第九步接视觉时作一次合理性核查，不把追求绝对姿态精度作为第八步开发前置。
