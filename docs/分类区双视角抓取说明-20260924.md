# 分类区双视角抓取

2026-09-24 记录的分类区观察位是实机静止时 `/joint_states` 的 `joint1` 至 `joint6`，保存在 `src/fairino_mtc_demo/config/first_grasp.yaml` 的 `sort_area_observation_joints_rad`。这是一组固定关节目标，不是每次启动时临时读取的姿态。更换相机、底座或分类区布局后须重新确认观察位和视觉标定。

## 触发条件与动作顺序

仅当命令明确把分类区中的指定颜色方块作为**抓取来源**时，语音端才发送 `source_location: sort_area`。例如“把分类区里的红色方块放到蓝色方块上面”。“把红色方块放到分类区”“把红色方块放到 A3”发送空 `source_location`，沿用原动作。

跨视角码垛按以下顺序运行：

1. 在当前初始视角设置蓝色过滤，获取新鲜且唯一的蓝色方块与同帧几何信息，冻结为支撑目标。
2. 规划并执行一次到分类区观察关节位的运动；到位校验通过后切换红色过滤。
3. 在分类区视角获取新鲜且唯一的红色方块，验证它与已冻结的蓝块是否可安全码垛。
4. 从观察位直接规划抓红、放到蓝块顶面，完成后按原 Action 规则返航。不会为了重新观察蓝块而回初始视角。

`pick_hold`、`pick_sort`、`pick_place` 也接受显式的分类区来源；它们在观察位识别来源后继续各自原有的抓取和放置流程。`pick_stack_auto` 只处理单一初始视角的桌面库存，不接受分类区来源。分类区的目标识别失败时不会使用上一次分类放置的坐标盲抓。

## 调用和验证

ROS Goal 增加 `source_location`，合法值为空串或 `sort_area`。命令行示例：

```bash
scripts/grasp/send_color_task.sh stack red blue --from-sort-area
scripts/grasp/send_color_task.sh hold red --from-sort-area
scripts/grasp/send_color_task.sh place red A3 --from-sort-area
```

先用 `FR3C_FIRST_GRASP_EXECUTE=false` 运行：这时只规划并展示到分类区观察位的一段路径，返回 `PRECONDITION_FAILED`，说明后续视角必须实际移动后才能获取，**不会驱动机械臂**。检查路径和现场净空后，在执行模式中分别验证蓝块不可见、红块不可见、重名方块、观察位到位失败和成功码垛。现场未做实机跨视角运动验收前，不把软件编译通过视为抓取成功。
