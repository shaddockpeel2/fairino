# FR3C 离线大模型与语音抓取：10 阶段开发规划

日期：2026-09-16。状态：需求已明确，本文是后续逐阶段实施与验收依据；不表示以下功能已经实现。阶段实施状态见各阶段下的实施记录。

部署条件：RK3588、8GB 内存、完全离线。复用参考项目中已在此板运行的 Qwen3-VL-2B 量化模型与匹配的 RKLLM/RKNN 运行库。当前工作区为 `/home/industio/fairino_ws`，参考项目为 `/home/industio/DofbotPro_JetsonNano_0106/dofbot`。

**已经确认的产品行为**

| 用户表达 | 预期行为 | 结束条件 |
|---|---|---|
| 抓取红色方块／把红色方块拿起来 | 选择红色方块，接近、下降、闭爪、抬升 | 抬升完成后保持夹持，不分类、不自动放下 |
| 抓取红色方块分类／把红色方块放到分类区 | 选择红色方块，抓取、抬升、放到红色对应区域、释放、返回 | 本次指定红色目标处理完成，不继续抓其他颜色 |
| 帮我拿一下那个红色的小方块 | 归一化为同一抓取任务 | 与“抓取红色方块”相同 |
| 你看到了什么／看看桌面上有什么 | 截取当前相机画面交给 Qwen3-VL 简单回答 | 只回答，不触发抓取 |
| 停止抓取 | 直接请求任务取消 | 根据机械任务实际状态反馈停止结果 |
| 停止播报 | 取消当前语音播放 | 不改变已经开始的机械任务 |

同时有红、黄、蓝、绿时，按命令筛选目标；不存在红色时明确报告未找到，不自动改抓其他颜色。第一版不实现同色多目标选择；若现场意外出现两个合格红色目标，则报告目标不唯一，不任意抓一个。明确且校验通过的抓取命令直接执行，不增加逐次人工确认。

界面只保留大模型对话页，包含必要的语音、截图、运行状态和停止控件；新项目不保留点动页。参考项目作为迁移来源保留原状。大模型用于理解意图和画面描述，实际三维坐标、轨迹与动作结果以当前视觉和抓取系统为准。

**可调整的默认值**：用户尚未指定的细节暂按“点击语音按钮开始，再次点击结束；也允许静音自动结束；定稿后自动发送”“文字和语音回复默认都播报，可关闭”“先实现按钮打断，语音打断后续扩展”“唤醒后支持接着说问题”“知识库先导入当前机械臂说明书和本项目资料、界面显示出处”规划。可在对应阶段调整，无须重排整个开发顺序。

不穷举所有自然语言句子。Qwen 将同义表达归一化为有限任务与参数，程序只执行已实现的任务。第一版仅做单轮明确命令；“不要抓”“如果有红色再告诉我”“怎么抓红色方块”必须与真正执行请求区分。任意多步命令、模糊代词跨轮控制、同色多目标和任意物体抓取留作扩展。

**现状核查及设计依据**

- 当前 `first_grasp_node.cpp` 提供 `/start`、`/start_continuous`、分段授权与 `/cancel`，都是不带颜色参数的 Trigger 服务。`batch_mode_ = continuous && sort_enabled_ && execute_`，因此直接把 `/start_continuous` 当作“拿起一个红色方块”会混淆单次抓取和整批分类。
- 当前四色流程按固定颜色顺序提供目标，并使用 A4 标定的放置区域。沿用已验证的红→C、黄→B、蓝→A、绿→D 配置，不让模型编造放置坐标。
- 参考项目已具备 token 分段、Kokoro 回调、PCM 队列、ALSA 常驻播放和 NPU 协调，不应把现状误判为完全没有流式实现。
- 参考项目 `tts_metrics_20260902T155336_642341.jsonl` 的两条记录中，ASR final 到首音频写入约为 4.80 秒与 24.79 秒，TTS 首 PCM 约为 3.01 秒与 2.01 秒。第一条累计合成 9.69 秒、音频 8.56 秒，RTF 约 1.13，且存在两次生产断供。这些是少量异常样本，不能当作整体分位数，但足以要求重新做分段测量。
- 参考配置 `trailing_silence_ms=3000` 还会在说话结束后引入判停等待。24.79 秒异常不能仅用合成时间解释，需要补齐排队、事件门禁与各阶段绝对时间戳。
- 日志中的第一次 ALSA write 不等于扬声器真实可闻首声；验收必须区分软件指标和声学实测。

整体数据流：文字／按钮语音／后续唤醒 → 统一请求与会话管理 → Qwen 意图解析、普通聊天、单帧视觉或知识检索 → 结构化动作校验与任务执行；可朗读回答同步进入“增量文本 → TTS → PCM 队列 → 常驻播放器”。界面不承担 NPU 调度、音频状态机和机器人执行逻辑。

6. **接通 Qwen 到扬声器的流式管线**

   操作：实现“token 增量 → 首段快速切分 → 有界文本队列 → 常驻 TTS → 有界 PCM 队列 → 常驻音频播放器”。首段使用标点、字符上限与最大等待时间共同触发，后段适当增长以减少断句；对数字、单位与标点做保守处理。不能只等一个很久不出现的句号。

   每轮请求共享 request_id 和取消标识。Qwen 完成只表示文本结束，队列耗尽和播放器排空才表示播报结束；从创建请求起维护语音会话状态，防止首段尚未形成时监听线程抢占。文本、合成和播放独立运行，故障与背压有界处理。

   清洗不可朗读标记，不朗读意图 JSON；固定状态语直接使用已生成 PCM，并且必须由真实状态触发。语音停止清空软件和硬件队列，旧回调不得进入新一轮。保留声卡断开/重枚举重开处理。缓冲从小值测起，以实测供给稳定性调整，不复制旧项目的大缓冲默认值。

   交付：流式 TTS 服务、统一 PCM 播放器、事件时间线、取消与设备恢复测试。

   验收：对足够长、持续生成的回答，音频必须在最后一个 token 前开始；另用受控慢 token 源验证不会等全文。实际短回答若生成先于合成完成，不能仅据此认定非流式。20/60/120 字各至少 10 轮，记录段间非语义停顿和欠载；按钮停止播报暂定 P95 ≤ 250ms。固定“收到”不计作实际回答首声达标。

   验收：红黄蓝绿命令、普通聊天、空录音和噪声场景均有测试；语音与文字产生一致任务；连续 30 轮无麦克风占用、重复提交或上轮语音串入。单独报告“说完→final”和“final→实际回答首声”。

**统一响应目标与验收口径**

以下是待实测校准的工程目标，不是对 RK3588 已达到性能的承诺。预热后、正常负载测 P50/P95，冷启动单独报告；看图和知识检索分别统计，不混入普通短回答。

| 指标 | 初始目标 | 测量说明 |
|---|---|---|
| 按钮/文字操作的界面反馈 | ≤100ms | 界面接收反馈，不代表模型已回答 |
| 语音结束到 ASR final | P95 ≤1.0s | 包含自动判停；手动结束单独统计 |
| 首个可播文本段到实际可闻首声 | P95 ≤1.2s | 同时记录 TTS 首 PCM 与 ALSA write |
| 普通短回答：ASR final 到实际回答首声 | P50 ≤2s，P95 ≤3s | 不以固定提示音或“收到”代替回答 |
| 普通短回答：说完到实际回答首声 | P50 ≤3s，P95 ≤4s，并持续优化 | 明确包含 ASR 判停，视觉/RAG 单列 |
| 持续合成 RTF | P95 ≤0.8 | 在实际 CPU/NPU 并发负载下测 |
| 非语义播放断供 | 目标无可闻卡顿，P95 ≤150ms | 语义标点停顿单独处理 |
| 点击停止播报到声音停止 | P95 ≤250ms | 声卡排队须计入 |

真实可闻首声使用录音回采或其他声学测量与时间线对齐；软件 first write 只能作为中间指标。机械停止时间单独由现有控制链实测，不套用音频停止指标。通过本阶段检查后再进入后续阶段；如果第五、六阶段性能不达标，先处理瓶颈，不先堆上唤醒词和知识库。

每阶段均保留：改动文件清单、配置与依赖、启动方式、验证结果、实测指标、已知限制和下一阶段入口。后续可直接请求：“按本文实施第 N 阶段，先核对前置验收，只完成本阶段范围并更新记录。”
