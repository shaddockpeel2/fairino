# 第七步：只读位姿预览操作

本步显示方块转动时的期望 TCP 位置与姿态，机械臂保持不动。第七步软件、模拟、窗口及一轮 90 秒真实只读预览已完成，达到当前近似 Demo 检查范围；没有接入姿态运动执行端。实测分析见 [20261009_122550_231933](../evidence/target_follow/stage7/20261009_122550_231933/analysis/README.md)。

先退出原跟随 Demo 和上一轮姿态检查。2026-10-10 按用户要求放宽标准，入口默认使用 Demo 质量（0.10 px、2 帧确认，连续性抖动余量 6°）、0.8 秒姿态滤波、6°进入/4°退出的死区、0.5 旋转映射。原 `pose_preview.yaml` 的 0.4 秒、3°/2°和 1.0 配置保留可选。目标旋转引起的位置绕转也使用同一个映射。

## 本地窗口

```bash
export FR3C_FOLLOW_DOMAIN_ID=187
/home/industio/fairino_ws/scripts/target_follow/start_pose_preview.sh duration_s:=90
```

1. 机械臂和方块先保持不动。窗口出现 `ready_to_teach` 时按 T；成功后出现 `preview`，期望 TCP 应与当时实际 TCP 重合。
2. 静止约 5 秒，查看 `Filtered RPY` 和期望 TCP 是否比原始姿态稳定。
3. 保持机械臂不动，缓慢将方块在标签平面内转约 5–10°，停留数秒再回原位；随后分别小幅前后、左右倾斜约 5–10°。保持标签可见，不需要精确量角。
4. 观察 `Desired TCP mm/RPY` 和旋转误差是否随明显动作变化，小角波动是否被忽略。偏移平行于转轴时，位置绕转可能很小，属于正常几何结果。
5. 最后静止数秒，等待程序自动结束，或按 Q/Esc 结束。T 可以重新记录新的相对关系；本窗口的 S/X 不调用运动接口。

若 T 被拒绝，先保持方块不动，等可信状态恢复后再按一次。死区比较的是累计变化，缓慢转动不会因为每帧变化小而一直被忽略；默认死区允许滤波目标保留约 4°残差，半幅映射还会进一步减小末端响应，符合近似 Demo 要求。

## SSH 无窗口

`auto_teach:=true` 会在第一条可信位姿和新鲜反馈都到达时自动记录一次，仍不启动运动：

```bash
export FR3C_FOLLOW_DOMAIN_ID=187
/home/industio/fairino_ws/scripts/target_follow/start_pose_preview.sh --no-view \
  auto_teach:=true duration_s:=90
```

启动后先保持机器人和方块静止，等终端显示 `recorded=True`，再按上面的静止、小幅转动、停留和返回顺序操作。终端每秒打印预览状态和旋转误差，完整位置/姿态数据保存在记录中。

终端当前显示 `TCP angle gap`，表示期望与实际 TCP 的姿态差。机械臂保持不动时，这个数会随期望目标改变，不是相机测量误差；没有有效预览时显示 `unavailable`。返回原位后多停数秒便于观察滤波收敛，近似 Demo 不要求该数逐度归零。

现在默认已减幅。若希望更明显的完整幅度响应，在任一启动命令最后加：

```text
rotation_mapping_gain:=1.0
```

默认 0.5 时，目标累计转动经过滤波、死区后，期望 TCP 转动接近其一半，位置绕转同步减弱；改为 1.0 可恢复完整幅度。0.5 模式是减幅的近似跟随，不宣称保持与实物目标的精确相对变换。参数在启动时读取，切换时退出重启。

## 状态和数据

| 状态 | 含义 |
| --- | --- |
| `ready_to_teach` | 有新鲜可信位姿，可按 T 记录 |
| `preview` | 正常更新期望 TCP 与一步参考，机器人不动 |
| `holding_quality` | 短暂歧义/重新确认，冻结上一次接受的目标 |
| `stale_trusted_pose` | 上次可信图像超过 350 ms，预览线/角速度归零 |
| `target_not_found` / `orientation_jump` | 丢失/显著跳变，预览立即停止更新 |
| `stale_robot_feedback` | 实际机器人反馈过期，预览速度归零 |

短时保持不会用坏帧修改目标，也不会刷新可信图像时间戳。恢复后继续沿用滤波与死区基准，重新按 T 才重设记录关系。

记录保存在启动时打印的 `evidence/target_follow/stage7/<时间_进程号>/`，包含 `session.json`、`samples.jsonl`、`report.json` 与 ROS 日志；可用 `output_dir:=/绝对路径` 指定新目录。程序结束后把目录路径发给我即可，不必复制整份日志。报告内 `teach_count > 0` 表示已经记录，`status_counts.preview > 0` 表示已经得到预览。

预览话题均在 `/target_follow/pose_preview/` 下，服务只有 `/target_follow/pose_preview/teach`，不发布到执行端的期望话题。参考始终是从实际 TCP 出发的一步计算，不累计成假机器人运动；软件换算完整 TCP/法兰关系，包含非零 TCP 旋转。

## 后续顺序

这轮先看方向、明显响应、静止抖动和质量恢复，不要求逐度准确。第八步独立小角度执行端已实现软件/模拟验证，下一项按 [第八步操作](目标跟踪第八步姿态伺服操作-20261010.md) 做实际旋转，随后第九步接入视觉位姿跟随。此前约 40 mm 的跨视角位置差异仍需在接真实位姿运动前核查，可另用第六步的固定方块、机械臂往返采样；本次预览不会修复或掩盖该差异。

软件验证证据位于 `evidence/target_follow/stage7/`，包括几何/旧链路回归、模拟 ROS 记录/保持/过期/恢复、完整及半幅映射、只读窗口启动与退出。`static_replay/` 是用户历史静止数据的离线目标计算，不是实际机器人动作或绝对精度验证。
