## 2. 设备与软件基线

| 项目 | 实测值 |
| --- | --- |
| 用户标识 | Gemini Pro |
| SDK 枚举名称 | `SV1301S_U3` |
| 序列号 | `AY23B520016` |
| 固件 | `RD3013` |
| USB 接口 | 深度 `2bc5:0614`，彩色 `2bc5:0511` |
| 当前 USB 拓扑 | 深度 USB 3.0、5000 Mbit/s；彩色 UVC USB 2.0、480 Mbit/s |
| ROS wrapper | 1.5.15 |
| Orbbec SDK | 1.10.35，ARM64 |

`SV1301S_U3` 是 SDK 返回名称，结合厂家资料可对应 Gemini Pro 接入，但正式设备清单仍应补一张
铭牌照片。该相机枚举为两个 USB 功能：深度设备 `2bc5:0614` 当前经过 USB 3.x Hub、
以 5000 Mbit/s 连接，彩色设备 `2bc5:0511` 经过 USB 2.0 Hub、以 480 Mbit/s 连接。
不能用彩色 UVC 功能的 USB 2.0 速率代表整台相机链路。

驱动来自板上厂家资料包中的 `OrbbecSDK_ROS2-main.zip`。导入副本位于
`src/orbbec_vendor`，`SOURCE.json` 保存资料包路径、SHA256 和逐文件校验值；未保留
x64/arm32 库。本地资料包没有可验证的 Git commit，因此不能把压缩包版本写成某个
上游 commit。

## 3. 固定配置和接口

配置入口：`src/fr3c_camera/config/gemini.yaml`。

- 彩色：640×480@15 FPS，MJPG；
- 原始深度：640×400@15 FPS，Y11；
- 输出深度：硬件 D2C 后 640×480、`16UC1`，单位毫米；
- 彩色和对齐深度均使用 `camera_color_optical_frame`；
- 相机不支持 frame sync，保持关闭；
- 使用系统时间戳，并由融合层限制最大时间差和消息新鲜度；
- IR 和点云默认关闭，减少 USB、CPU 和 DDS 带宽；
- SDK 软滤波关闭；本机实测 15 FPS 下开启后原始及 D2C 深度会全部变为 0；
- ROS 台架默认使用隔离域 187 和 localhost-only。

主要话题：

```text
/camera/color/image_raw
/camera/depth/image_raw
/camera/color/camera_info
/camera/depth/camera_info
/tf_static
/fr3c_camera/probe_point
/fr3c_camera/diagnostics
```

`probe_point` 只是配置像素在相机光学坐标下的三维测试点，单位米，不是物体检测
结果，也不能直接下发抓取。正式感知应以检测区域内部的有效深度中位数生成带
时间戳、置信度和目标尺寸的消息。

相机输出的彩色 CameraInfo 含非零畸变，而 D2C 深度 CameraInfo 为零畸变。融合代码
会先把原始彩色像素转换到对齐深度像素，再取深度并反投影；不能只因为两者 K 和
frame_id 相同就直接使用相同像素索引。

## 4. 实测结果

第一轮天花板场景和桌面场景均完成 60 秒测试。最终单实例重复测试结果：

| 指标 | 彩色 | 对齐深度 |
| --- | ---: | ---: |
| 帧数 | 583 | 571 |
| 实测 FPS | 9.70 | 9.51 |
| 最大接收空窗 | 0.319 s | 0.325 s |
| 时间戳回退 | 0 | 0 |

共形成 552 组有效彩深配对，所有门禁通过；彩深时间差 P50 为 14.8 ms、P95
为 30.5 ms。硬件 frame sync 不受支持，因此后续检测必须继续按时间戳配对，不能
假设两路同时曝光。

在保持上述分辨率和硬件 D2C 配置不变的情况下，2026-09-08 又进行了帧率升级短测。
设备枚举的彩色模式只支持 5、10、15、30、60 FPS，`640×480@20 MJPG` 不存在；
配置为 20 FPS 时驱动会因找不到匹配 profile 而退出，因此未采用 20 FPS。最终配置改为
双方都支持的 15 FPS。两轮 30 秒测试中，彩色实测 14.48/14.58 FPS、对齐深度
14.60/14.57 FPS，分别形成 423/424 组格式及时间约束有效的彩深配对；后一轮最大接收
空窗为彩色 0.171 s、深度 0.203 s，时间差 P50 为 19.8 ms、P95 为 34.1 ms，无时间戳
回退。两轮之间的一次 15 秒复测出现 0.730 s 深度空窗，随后 30 秒重复恢复正常。进一步
对原始深度和 D2C 深度取值排查后确认，15 FPS 下启用 SDK `enable_soft_filter` 会使所有
深度像素变成 0，并非相机距离或 10% 有效率门槛所致。关闭软滤波后，最终 30 秒完整审计
通过：彩色 14.68 FPS、深度 14.47 FPS，最大接收空窗 0.190/0.206 s，共 427 组有效彩深
配对，整图有效深度中位比例 29.5%，时间差 P95 为 34.9 ms。原始深度诊断中有效率中位数
为 50.6%、中央半幅区域为 73.8%，有效深度中位数约 0.319 m，最近有效值约 0.149 m。
这些数值没有尺量真值，只证明当前场景能正常出深度；距离精度和 60 分钟稳定性仍待验收。

同日再次进行 60 秒 15 FPS 单实例复验，全部审计门禁通过：彩色收到 890 帧、
实测 14.82 FPS，深度收到 872 帧、实测 14.52 FPS；最大接收空窗分别为 0.201 s
和 0.273 s。共形成 865 组有效彩深配对，时间差 P50/P95 为 19.7/52.2 ms，
最大消息年龄 0.132 s，两路均无时间戳回退。消息级复核为彩色 `rgb8`、对齐深度
`16UC1`；驱动启用 depth scale，项目按毫米解释 `16UC1` 并以 0.001 换算为米。
彩色、深度和两份 CameraInfo 均为 640×480、`camera_color_optical_frame`，且内参
矩阵一致，确认 D2C 输出契约可用。现场复杂背景的整图有效深度中位比例为 29.6%；
这说明 15 FPS 下深度数据非全零且可用，但该场景无尺量平面，不替代抓取距离精度验收。

同一单实例的前一轮测试曾出现一次 1.103 s 深度接收空窗而未通过，立即重复后通过；
内核日志没有对应 USB reset/disconnect，驱动日志也没有流错误。这说明短测已经跑通，
但仍存在偶发长空窗，必须由后续 60 分钟测试判定稳定性。运行时新鲜度门禁会拒绝这段
空窗内的旧数据。

桌面场景并行写入未压缩图像 rosbag 时，彩色和深度最大接收空窗分别增加到 0.501 s
和 0.800 s，没有通过连续性门禁；停止并行录制后同一相机通过。该结果说明未压缩图像的
ROS 序列化、内存复制和磁盘写入会影响实时性，现有证据不能将其单独归因于 USB 速率。
生产抓取不应持续录制全部未压缩原始图像，或应改用压缩录制和独立写盘后重新测试。

15 秒桌面 rosbag 保存了 109 帧彩色、109 帧深度、对应 CameraInfo、TF、探针点和
诊断，共 592 条消息、约 160 MiB。离线读取通过，中心探针深度中位数为 0.224 m，
P05/P95 为 0.222/0.227 m。用户摆放距离估计约 0.4 m，但画面和深度显示镜头到中心
桌面约 0.22 m；没有尺量真值，因此本次不能声明绝对深度精度通过。

断流注入结果：暂停相机组件后，1 秒以外新增三维点为 0，收到 8 条陈旧数据诊断；
不会沿用相机停止前的旧点。

证据入口：`evidence/camera/20260908_bench/`。其中 `final_repeat/report.json` 是
原 10 FPS 的最终 60 秒合格报告，`fps_upgrade_summary.json` 汇总 20 FPS 不受支持及
15 FPS 短测结果，`final_clean/report.json` 保留前一轮偶发空窗失败，
`bag_readback.json` 是 rosbag 离线读取结果，
`stream_loss.json` 是断流验证结果。图像和 rosbag 保留在本机，但由 evidence 下的
`.gitignore` 排除大文件。

15 FPS 60 秒复验证据位于 `evidence/camera/20260908_15fps_revalidation/`，完整指标
见 `run_01/report.json`，同时保留彩色图、毫米深度 PNG 和深度伪彩预览图。

## 5. 构建与使用

```bash
cd /home/industio/fairino_ws
export PYTHONNOUSERSITE=1
source /opt/ros/humble/setup.bash
colcon build --packages-select orbbec_camera_msgs orbbec_camera fr3c_camera \
  --symlink-install --executor sequential --cmake-args -DBUILD_TESTING=OFF
```

终端一启动独立相机：

```bash
cd /home/industio/fairino_ws
scripts/camera/run_bench.sh
```

终端二执行 60 秒检查或录制 10 秒样本：

```bash
cd /home/industio/fairino_ws
scripts/camera/audit.sh
scripts/camera/record.sh /tmp/fr3c_rgbd_bag 10
```

台架脚本默认与机器人 ROS 图隔离。后续融合到机器人系统时，应显式配置共同 ROS 域，
并确认同一图中只有一个相机节点和一套 TF 发布者。

## 7. 2026-09-09 续测与实时审阅界面

再次通过 SDK 实时枚举确认当前连接设备为 `SV1301S_U3`、PID `0x0614`、序列号
`AY23B520016`、USB 3.0、端口 `2-1.1.2`；启动后的设备信息为固件 `RD3013`、
wrapper 1.5.15、SDK 1.10.35。上述信息能确认没有误接另一台 Orbbec，但 SDK 名称仍
不能代替零售铭牌上的完整商品 SKU，设备清单仍需补铭牌照片。

本次启动首次连流后约 1 秒出现一次 `onDeviceDisconnected`，驱动自动复位并重新连接，
随后完成 60 秒审计并通过全部消息级门禁。结果为彩色 856 帧、14.25 FPS，深度 839 帧、
13.97 FPS，最大接收空窗 0.276/0.268 秒，时间戳回退均为 0；形成 808 组有效配对，
彩深时间差 P50/P95 为 19.8/52.5 ms，最大消息年龄 0.121 秒。两路图像与 CameraInfo
均为 640×480、`camera_color_optical_frame`，彩色为 `rgb8`，深度为 `16UC1` 毫米；
两份 K 矩阵相同，彩色畸变非零而 D2C 深度畸变为零。证据在
`evidence/camera/20260909_live_review/audit_60s/`。

新增只读实时审阅工具 `rgbd_live_view` 和脚本 `scripts/camera/live_review.sh`。窗口同屏显示：

- 原始彩色图（单击选择测量 ROI）；
- 固定量程的毫米深度伪彩图，0/无效深度显示黑色；
- 按两份 CameraInfo 把彩色图校正到 D2C 网格后叠加的深度断层边缘；
- 分辨率、编码、frame、内参差、畸变、FPS、彩深时间差、消息年龄，以及 ROI 的中值、
  有效率、P05/P95、空间 robust noise 和最近 300 帧的时间 P95 跨度/标准差。

界面每 2 秒覆盖保存 `live_review.png` 和 `live_report.json`；按 `S` 可立即保存，按 `Q`
或 Esc 退出。使用方式：

```bash
# 终端一
scripts/camera/run_bench.sh

# 终端二；若已尺量真值，可追加 --expected-distance-mm 300
scripts/camera/live_review.sh
```

对实时画面中确认完全落在同一静止平面内的像素，可另做固定 300 帧机器判定：

```bash
ros2 run fr3c_camera rgbd_roi_quality --pixel-u 500 --pixel-v 200 \
  --frames 300 --expected-distance-mm 300 --output /tmp/roi_300mm
```

本轮先拍到天花板/灯具，之后改为桌面复杂场景；这两种画面均包含远处、高反光、低纹理、
黑色物体和多个深度断层。整图有效深度比例中位数为 31.6%，选中的混合 ROI 有效率低且
深度跨度大，实时门禁显示 `CHECK`。这解释了肉眼所见的空洞/散斑，但不是相机在抓取距离
下的绝对精度失败证据。P03-11/P03-12 仍需在 150、200、250、300、400 mm 放置尺量、
哑光、静止平面，每个距离采集 300 帧；计划验收门槛仍为 ROI 有效率至少 95%、静止平面
P95 波动不大于 5 mm，并单独记录距离偏差。没有镜头到目标面的尺量真值时不得标记精度通过。

随后使用新增的 `rgbd_roi_quality` 对桌面画面内两个固定 ROI 各采集 300 帧，均未通过：

| ROI | 深度中值 | 有效率中值 | 时间 P05/P50/P95 | 时间 P95 跨度 | 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| 蓝色垫 `(500,200)` | 290 mm | 41.6% | 229/290/411 mm | 182 mm | 不通过 |
| 木桌 `(600,200)` | 237 mm | 48.0% | 208/237/269 mm | 61.1 mm | 不通过 |

两轮的彩深时间与消息年龄契约均通过，没有配对失败；因此当前异常不能归因于 ROS 时间戳、
`16UC1` 毫米换算或陈旧数据。两个不同材质平面都远低于 95% 有效率、远高于 5 mm 时间
跨度，说明当前约 240～290 mm 画面下的对齐深度不满足抓取质量门槛，不能只解释为单一蓝色
材质问题。由于深度本身波动很大且没有尺量真值，这里的 237/290 mm 不能当作真实安装距离；
下一步应先尺量镜头到平面距离，再在 300/400 mm 复测，并临时关闭 D2C 对原始 640×400
深度做同 ROI 对照，以区分近距离/材质限制与 D2C 处理问题。
