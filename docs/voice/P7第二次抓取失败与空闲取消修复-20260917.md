# P7 第二次抓取失败与空闲取消修复

日期：2026-09-17。

## 现场原因

截图位于 `evidence/voice/P7/second-grasp/screen.png`，对应 GUI 日志为 `evidence/voice/P4/runtime/dialogue-20260917_152116.log`。

- 15:22:49，蓝色 `pick_sort` 返回成功，方块已释放并返回起点。
- 15:27:14，界面发起停止抓取，底层 Trigger cancel 在没有运行任务时仍将状态无条件改为 `canceled_holding_state_unchanged`。
- 15:27:46，红色命令成功归一化为 `pick_sort(red)`，但 Action 返回 BUSY，`executed=false`，原因是上述取消状态不允许启动。

中间另有 USB 声卡短暂不可用和语音误识别；它们不是最终红色 Action 失败的直接原因。界面只检查服务在线，错误显示了“任务：就绪”。

## 修复

`first_grasp_node.cpp` 的取消服务在 worker 与 Action 均不活动时成功返回“无活动任务，状态保持不变”。不设置取消标志、不调用机械臂/夹爪停止、不修改完成状态；因此分类完成后的场景归档路径和抓取保持后的持物锁都保留。存在活动任务时沿用原有即时停止路径，不等待启动互斥锁，不新增超时或确认。

`dialogue_gui.py` 根据底层 `action_active`、取消状态和 `retryable=false` 显示运行/待恢复/未就绪，不再将服务在线等同于任务可执行。

## 验证与生效范围

新增 C++ 取消处理回归：提取实际生产函数体，用记录调用的替身编译并执行，覆盖 9 种空闲/终态重复取消，以及 worker 活动、Action 活动、两者均活动时的停止行为。另覆盖 GUI 已取消、失败、持物、分类完成和外部任务活动状态。针对性测试 7 项通过；连同现有抓取检查、分区映射及 ROS Action 桥接回归，共 17 项通过（1 条既有 Python 兼容性 warning）。

两个包重新构建通过，记录见 `evidence/voice/P7/second-grasp/fix-build.txt`。

此修复防止再次发生空闲取消锁死，不会将既有的 CANCELED 状态自动改回可执行状态；真正执行中取消可能仍持物，不能一律自动解锁。本次未重启现场机器人进程或界面、未清除碰撞场景、未自动重试红色抓取。已运行的旧节点需要重启才能使用新代码；现场这次已知是蓝色分类完成后的空闲取消，可在原终端重启机器人启动脚本，并重新打开界面。机器人重新启动仍按既有 P6 检查运行。
