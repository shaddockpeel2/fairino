## 2. 调度架构

```text
GUI 统一文字入口
  → 原有动作/停止/看图安全路由
  → 普通聊天 chat_auto
      ├─ 寒暄和一般聊天：直接 Qwen，不加载、不运行 BGE
      └─ 资料型问题：一次 RAG_QWEN_TEXT 调度租约
           → 暂停并排空 NPU 感知（仅当前感知确实使用 NPU 时）
           → BGE RKNN 查询向量
           → CPU 对 595×512 float32 矩阵做精确点积
           → 最多 4 个片段、2200 字上下文
           → 同一租约内调用原 Qwen Worker
           → 恢复感知并确认新帧
```

没有增加第二个常驻服务。BGE Runtime 在 Qwen 服务进程中首次知识请求时懒加载；索引向量
使用 mmap，SQLite 以只读模式打开。当前规模全量精确点积比引入 ANN/向量数据库更简单，
热态检索只需几十毫秒。

## 3. 路由与安全边界

- 普通寒暄和一般常识默认不检索；明确提到资料、知识库、说明书、本项目、设备、阶段号或
  已有来源标题时检索。知识命中后的短追问可在 3 分钟内沿用最近来源标题补全查询。
- 机械动作仍先经过原 `intent.py` 的安全路由。只有最终判定为聊天的问题才可能进入知识
  检索，知识文本没有调用 Action、ROS 服务或 Shell 的代码路径。
- 检索片段在 Prompt 中明确标为“不可信的只读数据”；其中出现的命令、提示词和动作要求
  均不得执行。资料不足、数字对象不一致或来源冲突时要求模型明确说明资料不足。
- GUI 只朗读回答正文。检索版本、耗时、标题、章节和页码作为结构化系统消息显示，不进入
  TTS。
- 索引、RKNN 环境或查询失败时只禁用知识能力，当前问题继续使用普通 Qwen Prompt；动作、
  停止抓取、语音和截图入口不依赖知识模块。

## 4. 配置与运行环境

共享配置位于 `config/voice/qwen3vl.yaml` 的 `knowledge` 节。默认只读根目录可通过
`FR3C_KNOWLEDGE_ROOT` 覆盖。默认参数：

| 参数 | 当前值 | 说明 |
|---|---:|---|
| `top_k` | 4 | 最多送入 Qwen 的片段数 |
| `minimum_score` | 0.45 | 唯一的向量分数底线，保持宽松 |
| `maximum_context_chars` | 2200 | 防止知识上下文挤占 4096 模型窗口 |
| `npu_core` | 0 | 沿用旧 BGE 验证配置 |

RKNNLite 2.3.2 需要 NumPy 1.x，因此 Qwen 服务启动脚本改用参考项目已经冻结的：

```text
/home/DofbotPro_JetsonNano_0106/.venv-rk3588/bin/python
```

ROS 环境仍由原脚本 source，不影响 `rclpy`。隔离环境不存在时脚本回退系统 Python，知识
健康状态显示降级，普通 Qwen 服务仍可启动。

## 5. 使用方法

完整启动方式不变：

```bash
cd /home/industio/fairino_ws
scripts/voice/start_dialogue_full.sh
```

只检查知识包完整性，不启动模型：

```bash
scripts/voice/p10_knowledge_check.py
```

模型服务已经运行时，做一次完整知识回答检查：

```bash
scripts/voice/p10_knowledge_check.py \
  --question '苏开鸿科技（无锡）有限公司是哪一天成立的？'
```

GUI 顶部新增“知识”健康状态。回答结束后，聊天区显示知识版本、检索耗时和与回答引用编号
一致的出处列表。

知识内容仍由参考项目维护。旧项目发布新的 `knowledge/builds/current` 后，重启 FR3C Qwen
服务即可读取新版本；FR3C 工作区不维护第二份副本，避免两个索引发生版本漂移。
