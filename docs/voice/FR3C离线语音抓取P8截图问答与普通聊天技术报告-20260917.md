# FR3C 离线语音抓取 P8 截图问答与普通聊天技术报告

日期：2026-09-17

范围：十阶段规划第 8 阶段

结论：软件实现、板端文字长输出和静态实拍图视觉推理通过；真实 ROS 相机截图与实际 TTS 流播待整机在线补测，因此阶段暂不完全关闭。

## 1. 本阶段解决的问题

P7 页面虽然已有 `chat` 和 `vision` 路由，但普通聊天只显示意图 JSON 中最多 120 字的 `reply`，并没有再调用千问生成；截图按钮要求操作员手工选文件，也不是机器人当前画面。

P8 改为：

```text
文字 / ASR final
  -> 本地确定性安全路由（仅明确无控制含义的普通聊天、明确看图）
  -> 其余表达继续走 P4 严格 JSON 意图与语义校验
  -> chat：短上下文 + Qwen 文本流式生成
  -> vision：锁定本轮新鲜 RGB 帧 + Qwen3-VL 流式生成
  -> token 同时进入 GUI 和 P6 TTS
```

本地快速路由不处理任何包含抓取词、颜色、停止、取消或物体释放含义的句子；这些句子仍进入原有严格分类器。快速路由只可能把不确定表达送回模型分类，不能授权机械运动。

## 2. 普通聊天与短上下文

- “你好”“你是谁”“解释人工智能”等明确普通话题直接进入真实 Qwen 回答，不再先生成一轮 JSON。
- 包含“抓、拿起、分类、红黄蓝绿、停止、取消、物体已取下”等安全敏感线索的输入仍走 P4 协议。
- 最近 4 个成功问答轮次由 GUI 显式保存；默认提示总预算 6000 UTF-8 字节，超预算时从最旧完整轮次开始淘汰，不截断当前问题。
- 每次底层请求仍 `reset_before=true`，上下文完全由程序重建，动作请求、旧图片位置和上个进程不会隐式进入新会话。
- 模型 token 到达后立即进入界面事件队列，并在自动播报开启时同时进入 P6 流式 TTS；文字结果完成后即可继续输入，不等待长音频完全播放。

## 3. 当前相机截图

GUI 的 ROS bridge 订阅 `/camera/color/image_raw`（可在配置修改），使用 sensor-data QoS 缓存最近一帧。发起视觉问题时先检查接收时间，默认只接受 1 秒内的 `rgb8` / `bgr8` 帧，再进行 JPEG 编码；因此 Qwen 暂停 NPU 感知前已经锁定本轮图片。

快照默认最长边 1280、JPEG 质量 88，保留源尺寸、ROS 时间戳和接收墙钟时间。文件写入 `evidence/voice/P8/runtime/captures/`，最多保留最近 20 张；GUI 显示的缩略图与送给模型的是同一个 JPEG。无帧、帧过期、编码异常或图像缓冲不完整都会明确失败，不退回旧文件。

自然语言“你看到了什么”与“截图问答”按钮共用该路径。视觉回答提示明确禁止坐标、轨迹、关节角和控制命令；回答中出现颜色或“抓取”字样只作为文本显示，不回送意图入口。

## 4. 输出上限与超时

配置由：

```yaml
max_new_tokens: 256
max_context_len: 4096
request_timeout_s: 90
```

调整为：

```yaml
max_new_tokens: 2048
max_context_len: 4096
request_timeout_s: 600
```

2048 是现有 4096 上下文的一半，也是允许上限，不是要求每次生成的长度。模型仍可按自然结束符提前完成。GUI 客户端总超时同步为 660 秒，流式 TTS 完成等待为 900 秒，避免 Worker 仍在正常生成而上层连接先断开。配置校验要求输出上限小于上下文上限，仍拒绝超过已验证 8192 的上下文配置。

没有伪造“结束原因”：当前 RKLLM Worker 的 `RKLLM_RUN_FINISH` 不区分自然结束和 token 上限，所以日志只能记录实际字符数与完成事件，不能声称运行时提供了 finish_reason。

## 5. 板端实测

为避免影响现场残留 GUI，Qwen 服务使用隔离 Unix socket 和临时 runtime，加载本工作区的新配置；测试结束后正常发送 shutdown。

结构化结果保存在 `evidence/voice/P8/model-acceptance-20260917.json`。

| 用例 | 输出 | 首 token | 总耗时 | 结果 |
|---|---:|---:|---:|---|
| 一句中文自我介绍 | 27 字符 | 11.122 s（冷） | 12.893 s | 正常结束 |
| 不少于 600 字、必须有结尾总结 | 1236 字符 | 0.237 s（热） | 71.206 s | 以完整总结句和句号结束 |
| 既有相机实拍 PNG 简述 | 123 字符 | 12.191 s（冷） | 18.753 s | Qwen3-VL 正常描述 |

长回答明显超过旧 256-token 配置常见的截断长度，且本次正常形成完整结尾。它验证了新上限确实生效，但不等于所有提示都保证自然结束；若输入与输出合计触及 4096 上下文，运行时仍可能终止。

## 7. 启动与现场补测

先关闭残留旧 GUI，确保只有一个实例：

```bash
pgrep -af dialogue_gui
```

本次检查发现两个旧 GUI 进程同时存在，开发过程没有替用户终止。关闭旧窗口后，从主工作区启动：

```bash
cd /home/industio/fairino_ws
scripts/voice/start_dialogue_full.sh
```

生产启动脚本已去掉 Qwen 的 `--no-ros`，使真实视觉请求继续使用 P3 的机器人动作门禁和 NPU 感知暂停/恢复；`--no-ros` 只保留给隔离模型维护测试。

现场依次验证：

1. 输入“你好”“你是谁”，确认直接得到千问正文。
2. 再问“刚才你说的助手叫什么”，确认只引用最近对话。
3. 点击“截图问答”，确认缩略图时间与当前桌面一致。
4. 说“你看到了什么”，确认 ASR final 自动走同一当前画面路径。
5. 开启自动播报，提一个较长问题，确认最后 token 前已经开口；点击停止播报确认立即静音。
6. 在回答中提到“红色方块”后确认不会产生 Action；再发送明确抓取命令，确认仍走 P4/P2 路径。
