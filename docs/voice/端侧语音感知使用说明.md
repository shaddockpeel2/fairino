# 端侧语音感知

当前 Tk UI 新增“端侧语音感知”标签页，提供独立的单句 ASR 和文本朗读。
继续使用项目当前的本地 Sherpa-onnx/RKNN Zipformer 与 Matcha + Vocos，
不安装新模型；识别 Worker、术语纠正规则、唤醒 Worker、意图解析和合成播放管线保持原实现。
现有 GUI 增加页面挂载与资源占用判断。

## 使用

沿用原启动方式。已有模型、TTS 和机器人服务运行时，在 GUI 已关闭后运行：

```bash
bash scripts/voice/start_dialogue_gui.sh
```

需要完整启动时继续使用 `scripts/voice/start_dialogue_full.sh`。
运行中的旧窗口需要重新打开才能显示新增标签页；先结束当前业务任务。

1. 切到“端侧语音感知”，等待原任务结束及麦克风释放。
2. 点击“开始录音”，说一句话。静音后自动定稿，也可点击“结束说话”。
3. 识别结果只显示在本页；点击“复制文本”复制最终原文。
4. 点击“填入 TTS”将结果填入文本框，或手动输入需要朗读的文本。
5. 点击“开始朗读”；需要中断时点击“停止朗读”。

单次朗读最多 2000 字，沿用当前音色和语速。没有导出文件、连续听写或自动朗读。
ASR 内部诊断录音仍由原 `asr.json` 配置管理；本页没有新增录音导出入口。
TTS 未运行时显示服务状态，并允许继续使用 ASR。
ASR 使用原静音阈值、录音时间限制和模型路径；识别效果取决于现有模型和环境。

## 隔离规则

- 原对话、按钮录音、已经唤醒的问题接收/追问、机器人任务优先。
  它们未结束时，新页可以查看，但不启动录音或朗读。
- 原系统空闲后，新页使用期间暂停唤醒，保留“唤醒监听”勾选状态。
  离开本页并完成释放后，按原设置恢复唤醒。
- 录音与朗读互斥；新录音仍使用原跨进程麦克风锁。
- 实验 ASR 使用独立 `VoiceInput` 实例、事件队列和请求编号。
  只显示原识别文本，不调用 `send_text()`、大模型、意图路由或 ROS Action。
- 切页取消录音并忽略迟到的结果。即使原 `close()` 的等待超时，
  也继续检查录音线程存活状态，释放前禁止重启另一轮输入。
- TTS 复用原 Unix socket 和 `begin/feed/finish/status/stop`，使用 `replace=False`。
  忙碌时不替换已有播报，停止前检查本页请求编号。
  停止时通过现有定稿接口等待服务工作线程；状态无法确认时保持占用并重试。
- 返回原页面时，释放期间暂缓新业务提交；“停止抓取”按钮和文字停止快捷指令仍可用。
- 端侧视觉页的忙碌判断包含新页音频操作；原视觉页仍按其原逻辑在离开时停止识别。

会话协调的保证范围是当前 GUI。原 TTS `stop` 是全局接口，
外部客户端在“查询归属”和“停止”之间替换会话的竞争不能由当前协议完全消除。
部署时应保持一个控制 GUI，避免外部程序同时替换同一服务的会话。

## 实现与验证

- `src/fr3c_voice/fr3c_voice/edge_speech_page.py`：界面、独立事件处理、现有接口调用。
- `src/fr3c_voice/fr3c_voice/speech_resource_coordinator.py`：占用和唤醒恢复。
- `dialogue_gui.py`：挂载页面、原请求入口与唤醒的占用判断。
- `src/fr3c_voice/test/test_edge_speech_page.py`：模拟音频的隔离与界面测试。

开发验证覆盖原业务优先、原唤醒设置保留、原始 ASR 文本、重复/迟到结果、
录音取消、快速切页、ASR/TTS 互斥、TTS 忙碌拒绝、启动响应丢失或延迟、
状态失败后恢复、停止会话归属、原业务入口与停止快捷指令、真实 Tk 页面。
原语音模块回归同时运行。真人识别、扬声器试听及断网使用需在现场完成。

运行回归时需允许本地 Unix socket 和 X11 显示器访问。
新增页面的测试使用模拟音频，不打开麦克风或扬声器：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m pytest -q -p no:cacheprovider \
  src/fr3c_voice/test/test_edge_speech_page.py
```

原 `test_p6_streaming.py` 会探测真实声卡，可用时会执行 ALSA 硬件用例；
在现有语音业务空闲时运行完整回归。既有播放取消用例可能报告 `PcmCancelled` 线程警告。
