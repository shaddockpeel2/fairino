# FR3C 离线语音抓取 P8 实施计划

日期：2026-09-17

阶段：十阶段规划第 8 阶段（截图问答与轻量普通聊天）

状态：该计划已先于开发固化；现已按计划实施，真实结果见 P8 技术报告。

## 1. 承接现状

- P2 已提供 `pick_hold` / `pick_sort` Action；P4 的严格意图协议继续作为动作安全边界。
- P3 已有 Qwen3-VL 文本、单图流式服务和 NPU/动作资源协调。
- P6 已有 token 到 TTS 的流式播报与即时停播。
- P7 已把按钮 ASR final 接到和键盘相同的 `send_text` 入口。
- 当前普通 `chat` 只显示意图分类 JSON 里的短 `reply`，不是真正的千问聊天；“截图问答”仍要求手工选择文件，不是当前相机截图。这两项是 P8 的主要缺口。

## 2. 本阶段目标

1. 继续先做安全路由；只有验证为 `chat` 的输入才进行第二次普通生成，动作请求不能绕过现有协议。
2. 文字和语音共用普通聊天、自然语言看图及按钮截图问答入口。
3. 从 `/camera/color/image_raw` 取得本轮新鲜 RGB 帧，保存带时间戳的 JPEG，界面显示缩略图；没有新鲜帧时明确失败。
4. 普通聊天保留少量最近轮次，由程序组装上下文并在每次模型请求前重置底层 KV，避免动作、图片位置或旧会话隐式污染。
5. 普通聊天和视觉回答的 token 在生成时直接进入 P6 TTS；文字结果完成后写入对话区，TTS 故障不影响文字回答。
6. 将 `max_new_tokens` 从 256 提高到 2048（现有 4096 上下文的一半），并同步增大模型客户端和 Worker 总超时，减少回答因固定小上限被截断。该值是上限，不要求模型每轮用满。

## 3. 设计边界

- 图片回答仅描述画面，不生成机器人坐标，不作为抓取目标确认，也不自动触发动作。
- 图片快照必须来自本轮相机缓存且满足新鲜度；模型服务仍复制到自己的受控临时目录并在推理后删除。
- 对话只保留最近若干轮，并按提示字节预算从旧到新裁剪；不做跨进程永久记忆，不进入 P9 连续唤醒和 P10 RAG 范围。
- 回答默认简洁；用户明确要求展开时允许更长。输出上限增大后仍保留“停止播报”和关闭界面取消模型请求。
- 不更改机械臂速度、规划、P6 门禁、目标新鲜度或 Action 取消语义。

## 4. 开发顺序

1. 新增独立、可单测的短上下文管理和聊天/视觉提示构造。
2. 在 ROS Action bridge 中缓存最新 RGB 帧并提供线程安全快照接口。
3. 改造 GUI 路由：`chat` 二次生成；`vision` 自动截图；按钮直接使用当前相机帧；加入缩略图预览。
4. 接入生成期 token→TTS，补齐取消、错误和会话提交语义。
5. 调整 token/超时配置，增加配置关系校验和回归测试。
6. 完成软件回归、构建、板端服务/相机可用时的真实问答验证，并输出 P8 技术报告。

## 5. 验收口径

- “你好”“你是谁”“继续说明”等普通文字与语音输入得到真实 Qwen 回答，而不是分类器预置短句。
- 聊天可引用最近对话，但超出窗口的历史被确定性淘汰；新进程不继承旧会话。
- 点击截图和说“你看到了什么”使用请求发生时的新鲜相机帧；无帧或过期帧明确提示。
- 图像缩略图、捕获时间和模型所用 JPEG 对应同一帧；视觉回答中的动作词不派发 Action。
- 开启播报时，聊天/视觉 token 在生成结束前进入流式语音；关闭播报时不建立语音会话。
- 配置实际为 `max_new_tokens=2048`、`max_context_len=4096`，长回答测试不再在旧的 256 token 上限处结束；如模型仍因上下文或运行时终止，日志如实保留而不伪称完整。
- 既有意图、Action、P6 和 P7 软件回归不退化。
