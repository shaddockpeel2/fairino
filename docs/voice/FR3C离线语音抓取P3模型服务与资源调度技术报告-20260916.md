# FR3C 离线语音抓取 P3 模型服务与资源调度技术报告

日期：2026-09-16  
阶段：10 阶段规划第 3 阶段  
结论：**阶段完成并关闭，可供第 4 阶段单页对话 GUI 和文字意图链路复用。**

## 1. 完成范围

本阶段把 P1 锁定的 Qwen3-VL-2B W8A8 资产接入当前 FR3C 工作区，保留原生 C++ Worker 和 Unix Socket 进程边界，新建 `fr3c_voice` 包负责唯一实例、输入边界、请求串行、总超时、取消、故障恢复、统一追踪和 ROS 资源门禁。

已交付：

- 文本生成与单帧 JPEG/PNG/WebP 视觉生成；
- 本机 `0600` Unix Socket 服务，流式返回 token，未开放 TCP/HTTP；
- Worker 单实例文件锁、服务单实例文件锁和外部同资产 Worker 检测；
- UTF-8 prompt、图片大小、图片格式、上下文长度和最大输出 token 上限；
- 总请求期限，而不是每次 `recv` 都重新计算的滑动超时；
- 并发请求 fail-fast，不在内存中无限排队；
- 取消、超时、Worker 退出后的显式清理和自动恢复；
- 机器人 Action 活动门禁、可用内存门禁、NPU 感知暂停/排空/恢复；
- P1 `CLOCK_MONOTONIC` JSONL 追踪字段；
- 前台启动、停止、CLI 请求和三组板端验收脚本。

本阶段没有接机械 Action、意图解析、GUI、ASR、TTS 或 RAG，避免提前混入第 4～10 阶段范围。

## 2. 相对原规划补充的设计

### 2.1 取消需要回收 Worker

参考原生 Worker 的协议只有 `chat/reset/ping`，RKLLM 同步生成中没有取消操作；客户端断开后 Worker 仍会完成本轮推理。因此本实现将取消事件以 100 ms 以内的轮询粒度传到客户端连接，随后终止本项目拥有的 Worker 进程组，清理 Socket/PID/临时图片，再按下一请求显式重载。

这样能保证旧 token 不进入新请求，并能真正释放异常推理；代价是取消后的下一次请求包含约一次模型加载时间。后续第 6 阶段“停止播报 P95 ≤250 ms”只约束音频停止，不应误套到本阶段的模型重载时间。

### 2.2 区分 CPU 感知与 NPU YOLO

`colors` 和 `blue` 是 CPU HSV/深度路径，不会因为名字里含“视觉”就被当成 NPU YOLO，Qwen 请求不暂停它们。只有 `detection_mode=yolo` 且状态明确 `npu_inference=true` 时，协调器执行：

```text
动作状态/内存/状态时效检查
  → 禁止新 YOLO 处理
  → 等待 active_inferences=0
  → Qwen 获得 NPU owner
  → Qwen 结束或失败
  → 恢复 YOLO
  → 等待 frames_inferred 增长且 last_success_ns 更新
```

感知暂停会清除稳定目标；恢复后先进入 `perception_resumed_waiting_for_fresh_rgbd`，不会继续发布暂停前的稳定位姿。第 2 阶段 Action 随后还会通过颜色过滤代次重新获取稳定、唯一的新鲜目标，两层约束共同避免旧目标复用。

### 2.3 动作和重复实例门禁

服务监听 `/fr3c_first_grasp/state`。状态新鲜且 `action_active=true` 时拒绝新的 Qwen 加载和推理；曾经收到机器人状态但随后超时也拒绝，避免用未知状态推理。未启动机械栈时允许模型独立运行，便于维护和测试。

服务锁防止第二个 `fr3c_voice` 进程删除正在使用的 Socket；Worker 锁防止相同运行目录重复加载；启动前还检查 `/proc/*/cmdline`，若同一只读 Worker 资产已由其他进程加载则拒绝启动，不主动杀死未知进程。

## 3. 进程和接口

```text
GUI/CLI（第4阶段复用）
  │ JSONL over Unix socket：health/chat_text/chat_image/cancel/reset/recover
  ▼
fr3c_voice service
  ├─ robot/memory guard
  ├─ NPU coordinator ── ROS pause/status ── blue_cube_localizer
  └─ QwenController
       │ 有界二进制帧
       ▼
  qwen3_vl_worker（唯一进程）
       ├─ Qwen3-VL vision RKNN
       └─ Qwen3-VL language RKLLM
```

服务 Socket：`evidence/voice/P3/runtime/fr3c-qwen-service.sock`。Worker Socket 不作为上层公共接口。服务请求是一行 JSON，回复事件为 `accepted`、零到多个 `token`、最终 `result`，或 `error`。

常用命令：

```bash
cd /home/industio/fairino_ws

# 前台启动；生产使用默认 ROS 安全门禁
scripts/voice/start_qwen_service.sh

# 另一终端
PYTHONPATH=src/fr3c_voice python3 -m fr3c_voice.client health
PYTHONPATH=src/fr3c_voice python3 -m fr3c_voice.client \
  chat_text '请简短介绍你自己'
PYTHONPATH=src/fr3c_voice python3 -m fr3c_voice.client \
  chat_image '请描述图片' --image /absolute/path/example.jpg
PYTHONPATH=src/fr3c_voice python3 -m fr3c_voice.client \
  cancel --request-id <request_id>

scripts/voice/stop_qwen_service.sh
```

`--no-ros` 只供脱离机器人栈的模型维护测试，生产对话页不得使用它绕过动作和感知门禁。

## 6. RK3588 板端验收

### 6.1 主服务

证据：`evidence/voice/P3/20260916/acceptance.jsonl`。

| 项目 | 结果 |
|---|---:|
| 连续文字请求 | 30/30 |
| 单帧视觉请求 | 3/3 |
| 并发请求拒绝 | 1/1 |
| 取消后恢复 | 1/1 |
| Worker 强制退出后恢复 | 1/1 |
| 文字首 token | 0.125～0.176 s |
| 文字总生成 | 0.679～0.743 s |
| 视觉首 token | 4.819～5.065 s |
| 视觉总生成 | 6.662～6.939 s |
| 最低 MemAvailable | 2162.9 MiB |
| swap 使用 | 0 MiB |

30 次文字和 3 次视觉期间 Worker PID 保持不变。取消恢复和强杀恢复会按设计替换 PID；最终健康状态为 `ready`、无 active request、无协调 fault。

故障注入开发过程中发现过一次“进程刚退出但状态仍短暂为 ready”的健康检查竞态。最终实现要求 `state=ready` 后仍实际 `ping` Worker；ping 失败立即清理并重载。修复后完整验收从头重跑并通过。

### 6.2 真实总超时

证据：`evidence/voice/P3/20260916/timeout_recovery.json`。

将同一真实 Worker 的请求总期限临时缩短为 50 ms，实际得到 `Qwen request exceeded its total timeout`；旧 Worker PID `563181` 被回收，恢复后 PID 为 `563511`，回答“超时后恢复正常。”，健康检查通过。

### 6.3 真实 YOLO 串行切换

证据：`evidence/voice/P3/20260916/yolo_switch.json` 与对应 trace。

在独立 `/p3_yolo` 命名空间加载 `best.rknn`，不替换现有 `/perception/blue_cube_localizer`，不发送任何运动命令。Qwen 加载一次、文字推理三次，共完成 4 次真实暂停/恢复：

- `pause_generation: 0 → 4`；
- `frames_inferred: 201 → 210`，每次恢复均确认新帧；
- `error_count` 始终为 0；
- 最终 `inference_enabled=true`、`active_inferences=0`；
- 三次回答均为“YOLO恢复验证正常。”；
- 协调 fault 为空。

原有颜色抓取节点和机械任务全程保留，最终 `/fr3c_first_grasp/state` 为 `action_active=false`。测试创建的 Qwen/YOLO 进程已全部停止，未留下第二模型实例。

## 7. 已知限制与 P4 入口

- 取消需要回收并重载 Worker，不是原生 RKLLM 中止；GUI 应显示“正在恢复模型”，不要把取消后的加载等待误报为卡死。
- 本阶段测的是模型服务，不含 ASR、TTS、RAG 或 GUI；2162.9 MiB 余量不能代表完整产品余量。
- 视觉请求使用显式单帧文件。第 8 阶段才负责从相机截图、缩放和对话预览。
- 上下文默认由每个独立任务在请求前 reset；第 4/8 阶段的短上下文策略必须由上层明确管理。
- P1 中记录的权重独立许可资料缺项仍未改变，本阶段不声明可重新分发模型。

第 4 阶段应直接使用服务 Socket 或 `QwenServiceCore` 的受限接口，不自行启动 Worker、不直接访问 Worker Socket、不改写模型路径。机械意图必须先经过结构化协议和程序校验，再调用 P2 Action；停止抓取继续绕过模型排队直接走 Action cancel。
