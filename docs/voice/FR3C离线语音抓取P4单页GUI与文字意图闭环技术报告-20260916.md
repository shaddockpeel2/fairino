# FR3C 离线语音抓取 P4 单页 GUI 与文字意图闭环技术报告

日期：2026-09-16  
范围：10 阶段规划第 4 阶段  
结论：软件实现与板端文字意图验收通过；自动验收未发送机械臂运动命令。

## 1. 交付结果

本阶段新增唯一的 Tk 单页对话界面。页面只有对话历史、文字输入、发送、截图问答、语音预留、播报预留、停止播报、停止抓取，以及模型／视觉／任务状态；没有点动页、点动菜单、关节角或笛卡尔坐标输入。

X11 下显式启用 Tk XIM。启动脚本在用户会话没有继承输入法变量时自动识别 IBus 或 Fcitx，并补充 `XMODIFIERS`、`GTK_IM_MODULE`、`QT_IM_MODULE`，保证中文输入和输入法切换可用；已有的用户自定义变量不会被覆盖。

文字链路为：

```text
用户文字
  -> Qwen 严格 JSON 意图
  -> 格式、字段、枚举、语义、安全状态校验
  -> pick_hold 或 pick_sort Action
  -> accepted / feedback / 最终 Result
  -> 对话页显示真实终态
```

Action 接受 Goal 只显示“请求已接受”，不会显示“完成”。只有最终 Result 才显示完成；`success=true, executed=false` 单独显示“规划完成，但未执行真实运动”。快速重复发送同时由 GUI 禁用态和 `TaskDispatchGuard` 两层阻止。

## 2. 结构化意图协议

模型输出必须是单个 JSON 对象，并且字段只能为：

```json
{
  "schema_version": "1.0",
  "route": "action|chat|vision|clarify|stop_action|stop_playback",
  "task": "pick_hold|pick_sort|null",
  "color": "red|yellow|blue|green|null",
  "reply": "给用户看的短中文"
}
```

校验采用失败即关闭策略：禁止 Markdown 包裹、额外字段、未知枚举、动作缺参、非动作携带控制参数、超长回复以及回复中出现坐标、关节或 ROS 命令。程序还独立检查否定、咨询、条件句、引用／翻译、多步命令、多颜色、融合颜色、动作词、分类放置词和模型颜色是否与原文一致。

考虑到 2B 模型偶尔会输出格式正确但语义不一致的结果，最多进行一次带错误码的纠错重试。第二次仍不合格就拒绝请求，不调用 Action。截图问答使用独立 `chat_image` 请求，提示词明确禁止产生机器人控制内容。

## 3. 停止与并发

- “停止抓取”“请马上停止抓取吧”等明确表达在模型之前识别，直接调用当前 Goal 的取消接口；本地没有 Goal 时调用 P2 `/fr3c_first_grasp/cancel` 服务。
- `pick_hold` 成功后继续保留 P2 持物锁。操作员真正取下／放稳物体后，可在对话页输入“物体已取下”“上一个任务已完成”或“解除持物状态”，直接调用 `/fr3c_first_grasp/acknowledge_object_released`；该同步不发送运动命令。不会仅凭机械臂姿态变化自动解锁，因为姿态变化不能证明夹爪已经空。
- `pick_sort` 成功回到初始状态后自动成为终态，不需要上述持物确认。
- 修复了 Goal 尚在提交时的取消竞态：取消标记只属于当前提交中的 Goal，不会遗留并误取消下一次任务。
- 停止播报保留独立入口。P4 尚无 TTS 播放，因此只返回真实状态，不伪造播放行为。
- 语音按钮和自动播报明确标注后续阶段，不加载 ASR/TTS。
- 动作期间不发起新的模型推理；这同时满足 P3 的 NPU／运动资源门禁。

## 4. 状态和日志

页面显示：

- 模型：每 2 秒通过本地 Unix Socket 健康检查更新；
- 视觉：读取 `/perception/blue_cube_localizer/status`，区分就绪、推理暂停、状态未知；
- 任务：读取 Action server 和本地 Action 阶段，区分就绪、未就绪、运行中。

模型原始 JSON、协议拒绝原因、Action accepted／feedback／result 和错误码写入 `evidence/voice/P4/runtime/dialogue-*.log`。日常对话区不刷入每一条 Action feedback，只保留请求接受、取消和最终结果等用户需要的信息。

## 5. 板端评测

语料文件为 `config/voice/p4_intent_corpus.json`，初始模型评测 72 条；现场联调后增加 4 条不经过模型的持物释放确认，当前共 76 条：

| 类别 | 条数 |
|---|---:|
| 抓取保持同义说法 | 16 |
| 分类放置同义说法 | 16 |
| 否定 | 10 |
| 咨询 | 10 |
| 缺参数 | 8 |
| 颜色混淆／条件／引用／多步 | 8 |
| 普通聊天／看图 | 4 |
| 明确确认物体已取下 | 4 |

使用真实 RK3588 Qwen3-VL-2B 离线服务完成初始 72 条全量评测，最终报告为 `evidence/voice/P4/evaluation/intent-eval-20260916_145553.json`：

- 72/72 最终输出通过协议和语义门；
- 32/32 动作正例的 Action 类型与颜色完全正确；
- 40/40 非动作反例没有产生 Action；
- 精确路由 66/72。其余 6 条只在 `chat`、`clarify`、`stop_action` 等非抓取路由间不同，不影响反例安全验收；
- 总耗时 576.463 秒。

新增的 4 条释放确认属于与停止同级的必要明确快捷入口，不占模型队列；单元测试同时验证模糊的“好了”不能解除持物锁。

评测程序只导入模型客户端和意图模块，不导入 ROS Action，不会向机械臂发 Goal。

## 7. 启动方式

### 7.1 当前部署目录

截至 2026-09-17，运行文件分布在两个工作区：

| 内容 | 启动目录 |
|---|---|
| P2 机器人、相机、MoveIt 和抓取 Action | `/home/industio/fairino_ws` |
| P3 Qwen 服务、P4 GUI 和意图评测 | `/home/industio/.codex/worktrees/9928/fairino_ws` |

两个工作区的进程通过同一 ROS 2 图通信。P4 尚未同步到主工作区，因此在 `~/fairino_ws` 执行 `scripts/voice/start_dialogue_gui.sh` 会得到“没有那个文件或目录”。在完成正式合并／同步前，必须从上述 Codex 工作树启动模型和 GUI。

### 7.2 三个终端分别启动

不要把三个脚本写在同一条命令中。机器人启动脚本会持续占用终端；如果把模型和 GUI 脚本路径接在其后，ROS 会把它们误解析为 launch 参数并报 `malformed launch argument`。

终端 1：启动 P2 抓取系统。首次联调必须保持仅规划模式：

```bash
cd /home/industio/fairino_ws
FR3C_FIRST_GRASP_EXECUTE=false scripts/run_moveit_camera_rviz.sh detection_mode:=colors
```

终端 2：启动离线模型服务：

```bash
cd /home/industio/.codex/worktrees/9928/fairino_ws
scripts/voice/start_qwen_service.sh
```

终端 3：启动 P4 GUI：

```bash
cd /home/industio/.codex/worktrees/9928/fairino_ws
scripts/voice/start_dialogue_gui.sh
```

GUI 输入框使用系统 IBus/Fcitx。启动脚本会自动补齐 Tk 所需的 XIM 环境；修改代码或输入法配置后，只需关闭并重新启动 GUI，不必重启机器人栈和模型服务。

### 7.3 维护命令

只检查配置、不创建窗口或 ROS 节点：

```bash
cd /home/industio/.codex/worktrees/9928/fairino_ws
scripts/voice/start_dialogue_gui.sh --validate-only
```

停止模型服务：

```bash
cd /home/industio/.codex/worktrees/9928/fairino_ws
scripts/voice/stop_qwen_service.sh
```

完整意图评测：

```bash
cd /home/industio/.codex/worktrees/9928/fairino_ws
scripts/voice/p4_intent_eval.py
```

### 7.4 `pick_hold` 后继续下一任务

`pick_hold` 成功后会保持夹持并进入 `complete_holding`。确认物体确实已经从夹爪取下或放稳后，在 GUI 输入以下任一句：

```text
物体已取下
上一个任务已完成
解除持物状态
```

该操作只调用状态同步服务，不发送运动命令。看到“上一持物状态已解除”并等待视觉重新稳定后，再发送下一条抓取命令。`pick_sort` 成功放置并返回后自动结束，不需要该确认。

### 7.5 执行模式说明

`FR3C_FIRST_GRASP_EXECUTE=true` 只表示允许进入真实执行检查，不会绕过 P6、目标新鲜度、MoveIt、碰撞和夹爪门禁。若 Action 返回 `PRECONDITION_FAILED`，应查看 GUI 日志中的最终 Result；例如首次 P6 门禁必须在生成后 600 秒内被当前抓取会话接受。不得通过延长时限或删除门禁来解决现场安全条件不满足的问题。

## 8. 现场边界和后续阶段

P2 已有两类 Action 的代表性真机证据；本阶段没有为了自动验收再次驱动机械臂。GUI 到真机的首次联调仍应先使用 `FR3C_FIRST_GRASP_EXECUTE=false`，确认界面显示“规划完成但未执行”，再按 P2 安全清单决定是否启用运动。

P5 选择并实测中文 TTS，P6 接入 ASR，P7 才形成语音播报和打断闭环。本阶段的预留控件不会伪装成已实现功能。
