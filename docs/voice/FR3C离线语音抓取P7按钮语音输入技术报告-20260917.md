# FR3C P7 按钮语音输入交接

日期：2026-09-17。范围以十阶段规划中的第 7 阶段为准：按钮 ASR，不包含唤醒词、连续对话、RAG。旧 P4 报告末尾的 P6/P7 顺序描述不作为本次阶段依据。

## 实现与使用

在 `/home/industio/fairino_ws` 完成实现，复用 P4 单页界面、意图校验和 P2 Action，以及 P6 独立 TTS 服务。

点击“开始说话”，显示“准备麦克风…”；出现“结束说话”后开始说话。转写内容在输入框实时替换，点击结束或静音判停后定稿并自动提交。final 和键盘输入调用同一 `send_text`，不会根据 partial 派发动作。建议现场先试“抓起红色方块”“抓起黄色方块”“抓起蓝色方块”“抓起绿色方块”“请把蓝色方块放到分类区”。识别有误时请重说，不做谐音强制替换。

录音开始前异步等待 TTS stop 确认，旧的未启动播报通过会话代次失效；录音期间不启动播报。麦克风和 RKNN Worker 退出后才提交 final，ASR 不与本轮 Qwen 推理重叠。任务执行中不启动第二轮语音请求，“停止抓取”仍可独立使用。关闭界面会终止录音；ASR 加载失败、麦克风断开或定稿失败均恢复按钮，不提交残留 partial。语音输入不修改机器人速度、感知稳定判据或现有机械执行检查。

## 运行库与参数

参考项目资产只读引用，没有升级运行库。Worker 从参考 `dofbot/tools/p17_streaming_asr_worker.py` 迁入新包，保留对应 ctypes C ABI、Zipformer RKNN 模型和独立 `LD_LIBRARY_PATH`；新增手动结束时的 0.5 秒零 PCM 尾部补齐（立即计算，不等待 0.5 秒现实时间），防止尾字因 decoder 窗口不足丢失。

配置：`config/voice/asr.json`。模型与库根目录为 `/home/industio/DofbotPro_JetsonNano_0106/rknn-llm-main/ASR`，模型为 `sherpa-onnx-rk3588-streaming-zipformer-small-bilingual-zh-en-2023-02-16`，库为 `.venv/lib/python3.9/site-packages/sherpa_onnx/lib/libsherpa-onnx-c-api.so` 和 `rknn-runtime/librknnrt.so`。系统 Python 3.10 运行 ctypes Worker，依赖 numpy，不将 P5 CPU sherpa wheel 当作 RKNN ASR 库。

| 参数 | 默认值 | 作用 |
|---|---:|---|
| USB 输入 | `plughw:CARD=Device,DEV=0` | 采用声卡名称，重枚举不依赖 card2 编号 |
| 输入格式 | 16000Hz / 单声道 / PCM16 | 50ms ASR chunk |
| 自动判停 | 650ms | 能量判停与 Sherpa endpoint 均支持 |
| 无语音退出 | 5 秒 | 静音不会送进模型 |
| 最大录音 | 30 秒 | 上限，不是固定等待 |
| 最短片段 / 有声累计 | 250ms / 120ms | 过滤点击瞬态和空录音 |
| 能量判定 | −45dBFS | 沿用参考配置，现场噪声仍需校准 |
| NPU 核选择 | −1，即 core1 | 沿用参考组合 |
| 解码 | modified_beam_search，4 paths | 热词分数 2.0，见 `asr_hotwords.txt` |

不加每次确认，不做多轮 ASR 重试，不扩大 TTS 缓冲。录音按会话创建 Worker，避免 8GB 整机常驻更多模型；实测加载约 0.3 秒，包含在“准备麦克风”阶段。输入暂存最多 1 秒，只有处理能力不足时才报错，不以持续积压掩盖延迟。

## 验证证据

证据目录 `evidence/voice/P7/`：

- `regression.txt`：80 项通过，排除 5 项播放器硬件相关测试，避免抢占现场扬声器。覆盖 30 轮录音控制器重复运行、每轮唯一 final、子进程释放、手动结束、取消、空录音、Worker 崩溃恢复、原生 endpoint 先关管道后返回 final 的竞态、停播失败禁止录音、partial 替换、过期事件拒绝、任务忙不启动录音，以及已有模型/意图/Action/TTS 软件回归。
- `build.txt`：`fr3c_voice` colcon 构建通过。真实 X11 下创建/关闭新界面通过；`start_dialogue_gui.sh --validate-only` 资产校验通过。
- `final-check.jsonl`：真实 RKNN Worker 连续 30 轮 WAV 回放，10 个样本各 3 次，全部正常退出且每轮恰有一个 final。四色“抓起…”均正确，分类句识别成“请把蓝色方块放到分类区域”，聊天句正确；否定句“不要抓…”识别成“不要装…”，咨询句“怎么抓…”识别成“怎么装…”，否定/咨询含义仍在。静音与低幅随机噪声均为空文本。
- `realtime-replay.jsonl`、`latency-summary.jsonl`：两条 WAV 以真实时间节奏送入实际录音控制器和 RKNN Worker，红色/绿色定稿正确；能量估计说完到 final 为 0.977 秒、1.058 秒（含 650ms 判停与清理），样本太少，不报告 P95 达标；这是管线回放，不是声学实测。
- `intent-check-local.jsonl`：8 条 ASR 定稿接入真实 Qwen，四色分别得到正确 `pick_hold`、蓝色分类得到 `pick_sort`，否定/咨询/聊天均未成为动作；没有调用 Action。当前意图解析实际耗时 8.08–9.15 秒，是原有模型链路的明显瓶颈，不能把 650ms 判停表述为整链路响应时间。最初探测旧工作树服务时服务已退出，失败探测保留在 `intent-check.jsonl`；随后临时启动本工作区服务完成验证并关闭。
- `asr-check.jsonl`、`beam-check.jsonl`：保留初始 greedy 和热词解码对比。“抓取…”合成音频存在“转起/折取/抓去”等误识别；启用热词后黄色样本改善，但不能宣称全面解决。
- `runtime/trace.jsonl`：包含一次真实 USB 麦克风无明确语音采集，正常关闭且空结果不提交。该场景检测到环境能量后约 1.9 秒结束，不代表所有房间静音都在该时长结束。

这些 WAV 是 Matcha 合成音频，不是真人录音。30 轮 Worker 回放和 30 轮控制器测试分别验证识别和生命周期，不能合并宣称已完成 30 轮真人麦克风抓取。未发送机械臂运动命令。

## 延迟记录与现场补测

P7 `runtime/trace.jsonl` 记录 `asr_recording`、`input_end`、`asr_final` 和最后有声帧的单调时钟时间。GUI 将同一 request_id 带入 Action 和 TTS 会话，P6 服务 trace 可按该 ID 合并。

```bash
python3 scripts/voice/p7_summarize.py \
  evidence/voice/P7/runtime/trace.jsonl \
  evidence/voice/P6/runtime/service-trace.jsonl
```

输出分开统计说完到 final、final 到首个有效设备写入。最后有声帧基于能量估算，会受噪声影响；设备写入不等于麦克风实际听到，`acoustic_first_sound_s` 保持空值，直到进行回采。自动静音与手动结束必须按 reason 分开统计。

只测试麦克风识别、不连接 Action：

```bash
python3 scripts/voice/p7_asr_check.py --rounds 1
```

该诊断程序不控制扬声器，运行前请先停止播报。文件回放使用 `--wav <单声道PCM16.wav> --rounds 30`；只有 GUI 路径自动执行半双工切换。
