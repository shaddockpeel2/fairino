# FR3C 离线语音抓取 P2 颜色任务 Action 技术报告

日期：2026-09-16  
阶段：10 阶段规划第 2 阶段  
结论：**阶段完成并关闭，可作为第 3 阶段 Qwen 服务与资源调度的稳定机械任务接口。**

## 1. 阶段目标与完成结论

本阶段把既有视觉抓取流程封装为大模型层可明确调用、可反馈、可取消、不会静默重试的任务接口：

- `pick_hold(color)`：抓取指定颜色方块，抬升后保持夹持。
- `pick_sort(color)`：抓取指定颜色方块，只放入该颜色对应区域，然后释放并返航。

阶段最低要求是提供两个带颜色的任务接口，并保证任务忙、目标不存在、不唯一、过期、规划失败、执行失败和持物未解除等状态不会误触发新动作。最终交付还增加了感知过滤代次、旧帧隔离、MoveIt 持物防覆盖、人工释放确认、全颜色过滤恢复、统一状态字段、命令脚本和完整证据链，超过了最初仅“封装两个接口”的范围。

真机证据确认：红色 `pick_hold` 成功；人工释放确认后红色 `pick_sort` 成功；蓝、黄、蓝三次指定颜色分类成功。共记录 5 次完整成功任务，最终在线状态为蓝色分类完成并返航。

## 2. 系统边界

大模型层后续只需选择任务类型和颜色，不生成坐标、不控制轨迹阶段：

```text
Qwen/GUI/测试命令
        │  PickColor Goal(task endpoint + color)
        ▼
fr3c_first_grasp Action Server
        │  set_target_color(color) → generation
        ▼
四色 RGB-D 感知 ── 新鲜、稳定、唯一、代次匹配的 Pose/Size
        │
        ▼
现有 MoveIt 抓取状态机 ── P6/工作区/碰撞/完整路径/到位检查
        ├─ pick_hold → 抬升并保持
        └─ pick_sort → 颜色区域放置、释放、返航
```

大模型不能覆盖实时坐标和颜色过滤结果；最终机械状态来自 Action Result 与 `/fr3c_first_grasp/state`。

## 3. Action 与辅助接口

### 3.1 Action

两个端点共用 `fairino_msgs/action/PickColor`：

| 端点 | Goal | 成功终态 |
|---|---|---|
| `/fr3c_first_grasp/pick_hold` | `color: red/yellow/blue/green` | `complete_holding` |
| `/fr3c_first_grasp/pick_sort` | `color: red/yellow/blue/green` | `complete_sorted_home` |

Feedback 为 `phase`、`detail`；Result 为 `success`、`error_code`、`message`、`color`、`executed`。错误码包括无效颜色、任务忙、目标不存在、不唯一、过期、前置条件失败、规划失败、执行失败、取消、仍在持物、感知不可用和内部错误。

Action 自动通过原先 `/descend_and_close` 与 `/confirm_grip_and_lift` 的人工等待点。为了复用既有状态机，Feedback 中仍可能短暂出现 `waiting_for_descend_command`、`waiting_for_manual_grip_confirmation`，但 Action 模式的授权标志已提前设置，不会在这些状态阻塞。

### 3.2 感知过滤服务

`/perception/blue_cube_localizer/set_target_color` 接收颜色并返回递增 `generation`。切换过滤时清除旧稳定窗口、位姿、尺寸和跳过记录。抓取节点只接受以下字段一致的快照：

- `detection_mode=colors`
- `target_filter_color=requested_color`
- `filter_generation=request_generation`
- `color=requested_color`
- `requested_color_physical_count=1`
- Pose、Size 与 `sample_stamp` 匹配且未过期

因此不存在“请求黄色却沿用上一帧红色坐标”或“没有红色就改抓蓝色”的降级路径。

### 3.3 持物释放确认

`pick_hold` 后保持 `complete_holding`，新 Action 返回 `HOLDING_OBJECT`。操作员真实放稳／移除物体并确认夹爪不再持物后调用：

```bash
ros2 service call /fr3c_first_grasp/acknowledge_object_released \
  std_srvs/srv/Trigger '{}'
```

该服务不移动机械臂、不驱动夹爪；它清除 MoveIt 附着物、恢复全颜色感知并回到 `waiting_for_target`。这一接口修复了首次现场联调中“实物已人工移走，但软件仍认为持物”的状态不同步问题。

## 4. 任务行为与安全约束

- 每个 Goal 只执行一次，失败不静默重试，不切换其他颜色。
- 同色两个三维有效目标返回 `TARGET_NOT_UNIQUE`。
- 请求颜色不存在时返回 `TARGET_NOT_FOUND`。
- 新 Goal 并发到达时以结构化 `BUSY` Result 结束。
- `pick_hold` 不进入放置路径；`pick_sort` 只处理当前指定颜色。
- 分类映射继续使用已验证配置：蓝→A、黄→B、红→C、绿→D。
- P6 执行门禁、目标工作区、桌面高度、碰撞检查、完整路径规划、关节硬限制和到位检查全部保留。
- 夹爪闭合仍是开环控制。成功表示命令与运动链完成，不表示力／位置传感器证明抓牢。
- Action 取消停止 MoveIt 与夹爪目标，但不自动张爪、释放或重试。

## 7. 异常与恢复记录

现场调整期间有 3 次夹爪 `pre_open` 返回 `result_code=6`、`reached_goal=false`。三次均发生在机械臂运动开始前，状态进入 `retryable_failure_before_arm_motion`，没有继续执行下降或抓取；条件恢复后新 Goal 成功。这验证了“失败不继续动作、无运动前可显式重试”的安全策略。

部分成功分类路径超过配置的 joint6 90°软偏好，事件中记录了 `joint6_soft_preference_overrun`；所有路径仍通过 URDF 硬限制、碰撞和完整轨迹检查。该软偏好不是线缆实测额定值，后续提高速度或扩大工作区前仍应评估腕部累计旋转。

首次红色 `pick_hold` 后发现感知过滤仍停留在红色。修复后，人工释放确认会同时清除 MoveIt 持物状态与单色感知过滤。该修复已重新编译；现场后续黄、蓝任务证明颜色 Action 能正确重设过滤。

## 9. 阶段关闭与下一阶段入口

P2 已形成稳定的机械任务边界，可供 P3 模型服务及后续 GUI/语音层调用。下一阶段只应依赖以下契约：

1. 模型输出有限意图和颜色，不输出机械坐标。
2. 程序完成枚举和语义校验后发送一个 Action Goal。
3. 停止抓取直接请求 Action 取消，不经过模型推理排队。
4. 以 Action Result 判断完成／失败，不以 Goal accepted 或自然语言回复判断。
5. `pick_hold` 后必须等待操作员释放确认，不能自动开始下一机械任务。

本阶段至此关闭。绿色补测、更多循环耐久性和实际夹持检测属于后续整机验证或硬件增强，不回退 P2 完成状态。
