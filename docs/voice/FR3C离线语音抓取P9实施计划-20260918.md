# FR3C 离线语音抓取 P9 实施计划

日期：2026-09-18

阶段：十阶段规划第 9 阶段（唤醒词与简单连续对话）

状态：本计划先于开发固化，后续实际结果记入 P9 技术报告。

## 1. 承接现状

- P7 已有单轮按钮录音、RKNN 流式 ASR、650 ms 尾静音判停、7 秒等待开口能力所需的底层参数，以及与 TTS 的半双工切换。
- P8 已将文字、ASR final、普通聊天、看图和流式播报接入统一 GUI 入口。
- 参考项目已验证 Sherpa-Onnx CPU KWS 模型可在本板运行，模型与 Python 运行库保持只读复用。

## 2. 快路径设计

1. 空闲时只运行 CPU KWS，唤醒发音为“九五二七（9527）”；命中前不加载 RKNN ASR。KWS 保留标准 `j iǔ w ǔ èr q ī`，另加入“就吴尔器”整句变调及四个音节分别跑调的有限变体；不展开四个音节的全部声调笛卡尔积。ASR 输出“九武贰妻”“就吴尔器”等同音或变调汉字时也会归一化为唤醒词。
2. KWS 采集保留 2 秒 PCM 前滚。命中后把前滚与后续音频送入现有 ASR Worker，保留“唤醒词＋问题”同句输入。
3. 仅说唤醒词时显示并播报“我在”，播放结束后打开完整 7 秒开口窗口；唤醒词后同句已有问题时不插播。开口后继续采集到 650 ms 尾静音或 30 秒上限。
4. 由唤醒发起的聊天或看图回答播放完后，只打开一次 7 秒追问窗口；静音超时即回到 KWS。
5. 机械动作期间不开麦，任务结束后回待唤醒，不自动打开追问。
6. 按钮录音优先：先停止空闲 KWS 并释放麦克风，再走 P7 原路径。文字、停止抓取和停止播报始终保持可用。
7. 只暴露一个“唤醒监听”开关和一条独立唤醒状态；状态明确显示是否已唤醒，以及问题窗口还剩几秒。不新增确认弹窗、分数融合或多级失败门槛。

## 3. 实施顺序

1. 新增独立 CPU KWS Worker，不将 Sherpa-Onnx 动态库加载进 ROS/Tk 主进程。
2. 新增唤醒采集控制器，与 P7 共享同一麦克风文件锁，完成前滚、KWS 到 ASR 切换、跟读窗口和取消释放。
3. 接入 GUI：状态显示、开关、同句问题去除唤醒词、回答后追问、动作/播报/按钮录音半双工门禁。
4. 增加解析、生命周期、前滚、取消、静音回退和 GUI 契约回归；构建后再做本板 KWS 资产加载冒烟。

## 4. 默认参数

| 参数 | 默认值 | 用途 |
|---|---:|---|
| 唤醒词 | 9527（九五二七） | 接受九/就、五/吴、二/尔、七/器等有限同音与变调表达，不做全部声调组合或无边界编辑距离模糊匹配 |
| KWS 分块 | 100 ms | CPU 实时解码 |
| 前滚 | 2.0 s | 保留完整唤醒词和紧接问题开头 |
| 等待开口 | 7.0 s | 仅唤醒/追问时使用 |
| 尾静音 | 0.65 s | 开口后快速定稿 |
| 最长话语 | 30 s | 安全上限，不是固定录音时长 |
| 播报后冷却 | 0.5 s | 避免扬声器尾音进入追问 |
| 异常重试 | 2.0 s | 固定恢复等待，无失败次数门槛 |

## 5. 验收口径

- 连说“九五二七，你看到了什么”时，问题开头不丢失，且只提交一次；ASR 转写为“九武贰妻”时行为相同。
- 只说“九五二七”后，在 7 秒内开口可提交问题，不开口自动回待唤醒。
- 由唤醒发起的回答播放完后可直接追问一轮；追问超时回待唤醒。
- 按钮录音可抢占待唤醒麦克风；按钮、KWS、ASR 和 TTS 不同时占用声卡。
- 模型生成、播报、停止播报、机械动作、取消和异常结束后都能回到正确监听状态。
- 至少完成 50 轮唤醒/问题/恢复现场循环；扬声器外放不能在半双工门禁下变成新命令。
