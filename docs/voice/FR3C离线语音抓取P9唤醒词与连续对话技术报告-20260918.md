# FR3C 离线语音抓取 P9 唤醒词与连续对话技术报告

日期：2026-09-18

范围：十阶段规划第 9 阶段

结论：软件开发、回归、真实 KWS 资产加载、USB 麦克风占用/释放和真实 RKNN ASR 静音追问通过；真人 50 轮、外放回答后追问和语音真机抓取待现场验收，因此 P9 暂不标记完全关闭。

## 1. 实际交付

P9 现在的统一路径为：

```text
空闲 -> CPU KWS（9527／九五二七发音）
     -> 命中：2 秒前滚 + 后续 PCM -> RKNN 流式 ASR
          -> 同句有问题：去掉唤醒词 -> P4/P8 统一入口
          -> 只有唤醒词：7 秒问题窗口
     -> 聊天/看图回答播放完：0.5 秒冷却 -> 7 秒追问窗口
     -> 追问静音超时 -> CPU KWS
```

当本轮 ASR 只有唤醒词时，界面显示并播报固定短句“我在”，等待播放真正结束后再打开 7 秒问题窗口；若唤醒词后已经带有同句问题，则不插入“我在”，避免覆盖问题后半句。同句问题、单独唤醒后问题和回答后追问最终都调用现有 `send_text`，不增加第二套意图或 Action 路由。

GUI 顶部增加独立唤醒状态条，明确区分“未唤醒·等待 9527”“已唤醒·正在识别”“已唤醒·等待播报结束”和“已唤醒·正在接收问题·N 秒后退出”。7 秒倒计时以问题麦克风实际打开事件为起点，不把“我在”的播放时间或 ASR Worker 加载时间算入用户回答时间；一旦识别到有效 partial，状态改为“正在识别问题”，不再显示开口倒计时。

## 2. 快而简单的边界

- 只保留一个可配置唤醒词、一个“唤醒监听”开关和一条语音状态。
- 不加确认播报、不加模糊编辑距离、不加多轮失败计数或多级分数。
- 等待开口为 7 秒；真正识别到文字后，尾静音为 650 ms，话语最长 30 秒。
- 追问窗口不依赖环境能量触发来认定“真的开口”；在 7 秒内没有 ASR 文字就回 KWS，避免普通底噪把窗口拖到 30 秒。
- 机械 Action 期间不开麦，Action 结束回 KWS 而不开追问；按钮录音会先取消空闲 KWS。
- KWS、按钮 ASR 和追问 ASR 共享 `/tmp/fr3c-button-asr.lock`，不会同时抢占麦克风。
- 取消、播报完成或异常后统一恢复；异常只使用固定 2 秒后重试，不累加判定层。

## 3. 进程和资源

CPU KWS 在独立 `kws_worker.py` 中加载 Sherpa-Onnx，ROS/Tk 主进程不导入该动态库。空闲等待不启动 RKNN ASR；KWS 命中或进入追问窗口时才创建现有 `asr_worker.py`。

资产只读复用参考项目的 `sherpa-onnx-kws-zipformer-wenetspeech-3.3M-2024-01-01` 和 Python 环境，KWS encoder SHA256 仍为 `dd784973fc9d2fabb3b800d6dcd20fc3b0ca84f8e2415afe54b032878e447f4d`。运行日志和 trace 归属当前工作区 `evidence/voice/P9/runtime/`。

## 4. 默认配置

配置文件为 `config/voice/wake.json`：

| 项 | 值 |
|---|---:|
| 唤醒词 | 9527（九五二七），支持“就吴尔器”等有限变调及同音转写 |
| KWS chunk | 100 ms |
| KWS score / threshold | 1.8 / 0.20 |
| PCM 前滚 | 2.0 s |
| 问题/追问开口窗口 | 7.0 s |
| 尾静音 | 0.65 s（沿用 P7） |
| 最长录音 | 30 s（沿用 P7） |
| 播报后冷却 | 0.5 s |
| 异常恢复等待 | 2.0 s |

当前 KWS 词表以 `j iǔ w ǔ èr q ī @9527` 为标准，增加 `j iù w ú ěr q ì`（“就吴尔器”）整句变调，以及九、五、二、七四个音节分别跑调的四条变体。没有生成全部声调组合，避免关键词数量和误唤醒面无界扩大。后续 ASR 如转写为“九武贰妻”、“就吴尔器”、“九五二期”或数字 `9527`，程序会按四个位置的受限同音字集合去掉唤醒段，不把它们当问题送入 Qwen。这不是任意模糊匹配，也不会因为句中普通提到该数字而从非句首触发。

## 5. 验证结果

1. `fr3c_voice` 全包回归：123 项通过，1 项跳过；P6 已有“取消写线程抛出 `PcmCancelled`” warning 仍在，本阶段未修改播放器。
2. 全工作区 Python 回归首次为 193 通过、1 失败；唯一失败是现场已运行机械臂在全局 `/joint_states` 中混入 6 轴消息，与 P9 无关。使用隔离 `ROS_DOMAIN_ID=97` 重跑该文件后 6 项全通过，因此有效结果为 194 项通过。
3. `colcon build --packages-select fr3c_voice --symlink-install` 通过。
4. `start_dialogue_gui.sh --validate-only` 通过，同时校验 P7 ASR 和 P9 KWS 资产。
5. 真实 Sherpa-Onnx CPU KWS 进程加载 INT8 模型成功；1 秒全零 PCM 只返回 `ready`，没有误唤醒。
6. 真实 USB 麦克风 `plughw:CARD=Device,DEV=0` 进入 `wake_waiting`，取消后线程结束且声卡占用释放。
7. 真实 RKNN ASR 追问窗口在当前环境未识别到文字，7.888 秒返回 `wake_empty/no_speech`，接近“7 秒窗口 + Worker 加载/定稿”的预期，结束后声卡释放。

本轮没有发送机械 Action，没有播放扬声器。开发时已有一个旧 GUI 进程在运行，本次没有替用户关闭；该进程需重启后才会使用 P9 代码。


现场按以下最短清单补测：

1. 连说“九五二七，你看到了什么”，确认开头不丢且只提交一次；日志中即使转写为“九武贰妻”也应直接去掉。
2. 只说“九五二七”，看到“请继续说（7秒）”后再问问题。
3. 等回答真实播完，不再说唤醒词，直接追问。
4. 追问窗口保持安静，确认约 7 秒后回“待唤醒”。
5. 在待唤醒时点“开始说话”，确认按钮 ASR 正常；完成后自动恢复 KWS。
6. 用唤醒语音发起一次仅规划抓取，确认 Action 期间不开麦，结束后回待唤醒。
7. 完成至少 50 轮唤醒/问题/回答/恢复循环，记录漏唤醒、误唤醒和问题首字丢失。

## 8. 已知限制

1. 尚未做真人“九五二七”声学命中和 50 轮长时循环，不声称唤醒命中率已达标。
2. 仍是严格半双工；播报期间不支持语音打断，需要时使用“停止播报”按钮。
3. 当前 KWS Worker 在每次重回 KWS 时重新加载小模型，冷加载冒烟约 2.4 秒；追问窗口不需要 KWS，所以不影响回答后立即追问。若现场认为追问超时后的这段恢复间隔明显，可在后续仅将 KWS 改为常驻 Worker，不改 GUI 流程。
4. KWS 词表配置标准发音、用户指定的“就吴尔器”整句变调和四条单音节变调；没有穷举全部声调组合，也没有降低 KWS 阈值。若现场仍有稳定漏唤醒，应基于真人录音增加明确变体，而不是继续全局放宽。
