# 2D 方块居中跟踪五步开发规划

更新日期：2026-09-21  
工作区：`/home/industio/fairino_ws`

## 1. 目标

新增一个持续运行的 ROS 2 Action，根据机械臂末端相机中的方块中心位置，控制机械臂在桌面 XY 方向低速移动，使方块保持在画面中心附近的矩形区域内。

第一版只实现二维图像居中：

- 跟踪红、黄、蓝、绿中的一个指定颜色方块；
- 只控制桌面 XY 平移；
- 保持启动时的末端高度和姿态；
- 方块进入中心区域后输出零速度，但 Action 保持运行；
- 方块再次移出中心区域时自动恢复跟踪；
- 目标丢失、图像过期、控制器异常、碰撞、奇异点、取消或超时后安全停止；
- 与现有抓取、分类、指定区域放置、码垛及 RViz 轨迹执行互斥。

第一版不实现目标距离保持、Z 方向跟踪、方块姿态跟随、自动抓取或完整六自由度跟踪。2D 闭环通过后，再复用本规划中的 Action 状态机、控制权仲裁、MoveIt Servo 和安全看门狗升级到 3D。

## 2. 当前基础与约束

### 2.1 可复用能力

- `fr3c_camera/cube_perception.py` 已有 HSV 分割、颜色区域、轮廓和候选方块筛选逻辑。
- DaBai DCW2 当前彩色流为 `640×480@10 FPS`，话题为 `/camera/color/image_raw`。
- MoveIt Servo 已安装，支持接收 `TwistStamped` 并输出 `trajectory_msgs/JointTrajectory`。
- `fairino3mt_execution_controller` 已使用六轴位置接口。
- `fairino_hardware` 在控制器占有全部六轴位置接口时，以 125 Hz 调用 FAIRINO `ServoJ`。
- `trajectory_control_bridge.py` 已负责现有 MoveIt 轨迹执行时的控制器启停和自动控制释放。

### 2.2 不能直接作为闭环输入的现有能力

现有 `blue_cube_localizer.py` 面向静态抓取定位，不直接作为本任务的实时观测节点，原因包括：

- 机械臂运动时会因 `robot_not_stationary` 拒绝定位；
- 默认采样周期约为 `0.18 s`；
- 位姿更新依赖 RGB-D 同步、TF、深度质量和稳定窗口；
- 输出重点是抓取所需的基坐标系三维顶面位姿，不是低延迟图像中心误差。

因此新增独立轻量 2D 检测节点，只订阅彩色图像和 `CameraInfo`，但复用已有纯视觉算法。

## 3. 总体架构

```text
/camera/color/image_raw
          │
          ▼
color_target_2d ──目标中心、有效性、调试图──► track_2d_action_server
                                                     │
                                      像素误差、滞回、限速、看门狗
                                                     │ TwistStamped
                                                     ▼
                                               MoveIt Servo
                                                     │ JointTrajectory
                                                     ▼
                              /fairino3mt_execution_controller/joint_trajectory
                                                     │
                                                     ▼
                                      fairino_hardware → 125 Hz ServoJ
```

控制权分为两种互斥模式：

- `TRAJECTORY`：现有 MoveIt 抓取、放置、码垛和 RViz 轨迹；
- `SERVO_TRACKING`：本规划的连续视觉跟踪。

任何时刻只能有一个模式持有六轴自动控制权。

## 4. 建议接口

### 4.1 跟踪 Action

建议新增：

```text
/fr3c_visual_servo/track_2d
fairino_msgs/action/TrackTarget2D
```

建议 Action 定义：

```text
# Goal
string color
float32 max_duration_s       # 0 表示持续到取消
---
# Result
uint16 OK=0
uint16 INVALID_COLOR=1
uint16 BUSY=2
uint16 TARGET_NOT_FOUND=3
uint16 TARGET_NOT_UNIQUE=4
uint16 TARGET_STALE=5
uint16 CONTROL_UNAVAILABLE=6
uint16 SERVO_FAULT=7
uint16 SAFETY_LIMIT=8
uint16 CANCELED=9
uint16 INTERNAL_ERROR=10

bool success
uint16 error_code
string message
float32 final_error_x_px
float32 final_error_y_px
float32 elapsed_s
---
# Feedback
string phase
string detail
float32 target_u_px
float32 target_v_px
float32 error_x_px
float32 error_y_px
float32 command_x_mps
float32 command_y_mps
float32 observation_age_s
bool centered
```

Action 到达中心后进入 `CENTER_HOLD`，不自动成功退出；取消、达到非零 `max_duration_s`、持续丢失或安全故障时才结束。

### 4.2 Action 状态

| 状态 | 行为 |
|---|---|
| `ACQUIRING` | 等待唯一且连续稳定的指定颜色目标，不申请机械臂控制权 |
| `TRACKING` | 目标在中心区外，持续发布受限 XY 修正速度 |
| `CENTER_HOLD` | 目标位于中心区内，持续观测并发布零速度 |
| `LOST_HOLD` | 观测暂时无效，立即发布零速度并等待短时恢复 |
| `STOPPING` | 发布停止序列、停止 Servo、释放控制器和控制权 |

### 4.3 第一版初始参数

以下值仅作为低速联调起点，最终值必须依据实测日志调整：

| 参数 | 初始值 | 说明 |
|---|---:|---|
| 图像尺寸 | `640×480` | 运行时仍需从消息核对 |
| 中心点 | `CameraInfo` 主点 | 缺失时退回图像几何中心 |
| 进入区半宽/半高 | `40/30 px` | 连续 3 帧满足后进入保持 |
| 退出区半宽/半高 | `55/45 px` | 连续 2 帧超出后恢复跟踪 |
| 首次实机最大速度 | `0.005 m/s` | 方向验证通过后最多提高到 `0.01 m/s` |
| 最大线加速度 | `0.03 m/s²` | 对控制周期逐步限幅 |
| 观测立即停止年龄 | `0.25 s` | 超过后进入 `LOST_HOLD` |
| 持续丢失终止时间 | `1.0 s` | 终止 Action 并释放控制权 |
| 最大相对 XY 位移 | `0.08 m` | 相对 Action 启动位姿 |
| 控制输出频率 | `50 Hz` | 观测仍受相机 10 FPS 限制 |

控制律第一版采用带死区、饱和和加速度限制的比例控制，不使用积分项：

```text
ex = (u - cx) / image_width
ey = (v - cy) / image_height

camera_vx = Kx * ex
camera_vy = Ky * ey
```

将相机平面速度通过实时 TF 转换到 `base_link`，再限制为桌面 XY 分量：

```text
linear.x = base_vx
linear.y = base_vy
linear.z = 0
angular.x = angular.y = angular.z = 0
```

像素误差与机械臂运动方向必须通过第四步的短脉冲实测确认，不能只依据坐标系名称推断符号。

## 5. 五步开发计划

## 第一步：建立独立 2D 方块感知

### 5.1 目标

在机械臂完全不运动的情况下，稳定输出指定颜色方块的中心像素、候选质量、时间戳和调试图，为后续闭环提供低延迟观测。

### 5.2 开发内容

1. 新增 `color_target_2d.py`，订阅：
   - `/camera/color/image_raw`；
   - `/camera/color/camera_info`。
2. 复用 `cube_perception.py` 的颜色掩膜和候选筛选，不复制另一套 HSV 参数。
3. 支持 `red/yellow/blue/green` 目标过滤。
4. 只有指定颜色恰好存在一个合格候选时才输出有效观测。
5. 增加短窗口连续性检查：
   - 时间必须递增；
   - 相邻中心跳变不得超过配置阈值；
   - 至少连续 3 帧才进入有效状态。
6. 发布：
   - 目标中心和包围框；
   - `valid`；
   - JSON 诊断状态；
   - 带中心区、轮廓、中心点和错误原因的调试图。
7. 此阶段禁止创建任何机械臂命令发布器。

### 5.3 预计文件

- 新增 `src/fr3c_camera/fr3c_camera/color_target_2d.py`
- 新增 `src/fr3c_camera/config/color_target_2d.yaml`
- 新增 `src/fr3c_camera/test/test_color_target_2d.py`
- 修改 `src/fr3c_camera/setup.py`
- 修改或新增对应 launch 文件

### 5.4 测试

- 纯函数单元测试：无目标、单目标、多目标、面积越界、中心跳变和时间倒退。
- 录包或静态图像回放：分别验证四种颜色。
- 手动缓慢移动方块，确认中心轨迹连续且方向与画面一致。
- 遮挡、移出画面、放入第二个同色方块，确认立即转为无效。
- 连续运行至少 5 分钟，确认无持续增长的延迟和内存占用。

### 5.5 通过标准

- 单个指定颜色方块连续稳定发布中心位置。
- 同色目标不唯一时不盲选。
- 图像停止后状态在 `0.25 s` 左右变为过期。
- 调试图能够明确显示中心容差区、目标中心和拒绝原因。
- 节点不调用任何运动接口。

第一步通过前，不进入控制算法开发。

## 第二步：实现 Action 状态机和无运动 dry-run

### 6.1 目标

实现完整的跟踪 Action 生命周期和二维控制算法，但只输出计算结果，不向 MoveIt Servo 或机械臂发送指令。

### 6.2 开发内容

1. 新建 `fr3c_visual_servo` 包。
2. 新增 `TrackTarget2D.action` 并注册消息生成。
3. 实现以下状态转换：
   - `ACQUIRING → TRACKING`；
   - `TRACKING ↔ CENTER_HOLD`；
   - 任意活动状态 → `LOST_HOLD`；
   - 短时恢复回到 `TRACKING` 或 `CENTER_HOLD`；
   - 持续丢失、取消、超时或内部错误 → `STOPPING`。
4. 实现：
   - 像素误差归一化；
   - 比例增益；
   - 速度饱和；
   - 加速度限制；
   - 进入/退出双阈值滞回；
   - 观测新鲜度和最大位移判定。
5. 增加 `execute=false` 参数。该参数为 false 时只发布预计速度、反馈和调试信息，不创建真实 Servo 输出。
6. Action 启动时记录目标、参数快照和唯一运行 ID，便于后续证据关联。

### 6.3 预计文件

- 新增 `src/fairino_msgs/action/TrackTarget2D.action`
- 修改 `src/fairino_msgs/CMakeLists.txt`
- 修改 `src/fairino_msgs/package.xml`
- 新建 `src/fr3c_visual_servo/`
- 新增 `track_2d_action_server.py`
- 新增 `config/track_2d.yaml`
- 新增状态机和控制律单元测试

### 6.4 测试

- 发送非法颜色，Action 应拒绝。
- 无目标时保持 `ACQUIRING`，不产生非零命令。
- 目标在中心区外时，反馈中的命令方向连续且受限。
- 目标进入中心区后转为 `CENTER_HOLD` 并输出零速度。
- 在进入阈值和退出阈值之间移动时不频繁切换状态。
- 短时遮挡进入 `LOST_HOLD`，恢复后继续原目标。
- 持续遮挡、取消和超时均进入统一停止流程。

### 6.5 通过标准

- 所有状态转换有自动化测试覆盖。
- dry-run 中手动向四个画面方向移动方块，预计速度方向符合设计。
- 任何无效或过期观测都只能产生零速度。
- 取消延迟不依赖新图像到来。
- `execute=false` 时没有任何机械臂控制话题输出。

第二步通过前，不连接 MoveIt Servo。

## 第三步：接入 MoveIt Servo 和统一控制权仲裁

### 7.1 目标

打通 `TwistStamped → MoveIt Servo → JointTrajectory → ServoJ` 控制链，并确保连续跟踪与现有轨迹 Action 绝不并发控制机械臂。

### 7.2 开发内容

1. 新增 FR3-C MoveIt Servo 配置：
   - move group：`fairino3mt_v6_group`；
   - planning frame：`base_link`；
   - end-effector frame：`grasp_frame`；
   - 输出类型：`trajectory_msgs/JointTrajectory`；
   - 输出话题：`/fairino3mt_execution_controller/joint_trajectory`；
   - 开启关节限位、奇异点和碰撞检查；
   - 输入超时不大于 `0.15 s`；
   - 初始最大速度采用第四步的低速值。
2. 扩展 `trajectory_control_bridge.py`，统一管理：
   - `TRAJECTORY` 所有者；
   - `SERVO_TRACKING` 所有者；
   - 控制器激活和停用；
   - 跟踪心跳；
   - 异常超时自动释放。
3. 跟踪 Action 在得到稳定目标后才申请控制权。
4. 获得控制权后启动 MoveIt Servo；未获得时返回 `BUSY`。
5. 跟踪期间新的轨迹目标必须在入口处拒绝。
6. 现有轨迹执行期间新的跟踪目标必须拒绝。
7. 停止流程固定为：
   1. 停止生成非零命令；
   2. 连续发布若干零 Twist；
   3. 确认 Servo 停止；
   4. 停用执行控制器；
   5. 发布控制状态；
   6. 释放控制权。
8. 若控制器无法停用，进入锁存故障状态，不允许启动下一项自动运动。

### 7.3 预计文件

- 新增 `src/fairino3mt_v6_moveit2_config/config/fr3c_servo.yaml`
- 新增 Servo/跟踪 launch 文件
- 修改 `trajectory_control_bridge.py`
- 修改 `spawn_controllers.launch.py` 或组合启动文件
- 修改 `fr3c_visual_servo` 的 Action 服务节点
- 必要时修改 `first_grasp_node.cpp`，使其在跟踪占用时立即返回 `BUSY`

### 7.4 测试

优先使用 fake/mock hardware，不连接真机运动：

- 跟踪申请成功时控制器只激活一次。
- 跟踪期间轨迹 Action 被拒绝。
- 轨迹运行期间跟踪 Action 被拒绝。
- Action 取消后输出归零、Servo 停止、控制器停用并释放控制权。
- 杀死跟踪节点、停止心跳或停止图像，桥接节点能够自动停止。
- MoveIt Servo 报碰撞、奇异点或关节限位时，Action 进入安全停止。
- 重复执行至少 30 次申请—释放循环，无控制权泄漏。

### 7.5 通过标准

- mock/fake hardware 下控制链完整工作。
- 自动化测试证明 `TRAJECTORY` 和 `SERVO_TRACKING` 不会同时成立。
- 取消、超时、节点异常和 Servo 故障都能完成停止序列。
- 停止失败会锁存故障，不会静默进入下一任务。
- 所有测试完成后控制器回到当前项目既有的手动拖动可用状态。

第三步通过前，不允许闭环真机运行。

## 第四步：真机低速方向和停止能力验证

### 8.1 目标

不运行完整闭环，只使用受限短脉冲逐项确认机械臂运动方向、图像误差变化、TF 映射、速度限制和紧急停止行为。

### 8.2 实机前门禁

必须同时满足：

- 前三步全部通过并保存测试记录；
- 机械臂和相机 TF 正常，无时间戳过期；
- MoveIt 规划场景含机器人、夹爪、相机和桌面碰撞边界；
- 操作者确认工作区、线缆和相机运动空间无障碍；
- 已知并现场验证停止方法；
- 不存在其他运动源或未结束的抓取 Action；
- 最大速度设置为 `0.005 m/s`；
- 单次脉冲预计位移不超过 `3～5 mm`；
- 初始姿态远离关节限位、奇异点和桌面边缘。

### 8.3 验证顺序

1. 零速度验证：获得控制权后持续发布零命令，机械臂不得漂移。
2. `base +X` 短脉冲：记录实际关节、TCP、图像中心和 Servo 状态。
3. `base -X` 短脉冲。
4. `base +Y` 短脉冲。
5. `base -Y` 短脉冲。
6. 分别把方块放在画面左、右、上、下区域，发送一次由控制律计算的短脉冲。
7. 每次确认脉冲后目标像素误差减小，而不是增大。
8. 验证脉冲中取消、遮挡图像和停止心跳，确认机械臂及时停止。
9. 检查 Z、高度和末端角度没有非预期变化。

任意方向第一次出现误差增大时立即停止，修正符号或 TF 变换后从零速度验证重新开始。

### 8.4 证据

每个脉冲至少记录：

- 命令方向和持续时间；
- 起止目标像素和误差；
- 起止 TCP 位姿；
- 实际最大速度；
- MoveIt Servo 状态；
- 控制器申请和释放时间；
- 是否触发限位、碰撞或奇异点减速；
- 操作者现场结论。

### 8.5 通过标准

- 四个方向的图像误差均按预期减小。
- 单次位移不超过设定边界。
- 取消或观测失效后不再产生非零运动。
- Z 和末端姿态无持续漂移。
- 每次结束后控制器均成功释放。

第四步通过后，才允许第五步完整闭环。

## 第五步：完整 2D 闭环和验收

### 9.1 目标

让操作者在桌面上缓慢移动指定方块，机械臂持续调整相机位置，使方块保持在中心区域，并完成正常、异常和互斥场景验收。

### 9.2 联调顺序

1. 最大速度保持 `0.005 m/s`，目标初始位于中心区附近。
2. 启动 Action，确认从 `ACQUIRING` 进入 `CENTER_HOLD`。
3. 缓慢将方块移出一个方向，确认进入 `TRACKING` 并重新居中。
4. 分别验证左、右、上、下及斜向移动。
5. 确认中心附近不存在持续反向切换或明显抖动。
6. 在安全范围内逐步扩大方块移动距离。
7. 只有低速验收稳定后，才允许把最大速度提高到 `0.01 m/s`。

### 9.3 必测场景

1. 静止方块保持 30 秒。
2. 四个方向缓慢移动并重新居中。
3. 斜向和往返移动。
4. 短时遮挡后恢复同一目标。
5. 持续遮挡后终止并释放控制权。
6. 方块移出画面。
7. 放入第二个同色方块，系统停止而不是切换目标。
8. Action 主动取消。
9. 非零 `max_duration_s` 到时停止。
10. 跟踪运行时发送抓取或 RViz 轨迹，确认被拒绝。
11. 抓取轨迹运行时发送跟踪目标，确认被拒绝。
12. 接近最大相对位移边界，确认系统停止追赶。
13. 模拟 Servo 警告、心跳中断和节点退出。

### 9.4 验收指标

- 目标进入中心区后保持在 `±40 px × ±30 px` 范围，且不持续抽动。
- 目标缓慢移动后能够重新进入中心区。
- 图像或目标观测超过 `0.25 s` 未更新时，`0.3 s` 内停止非零运动。
- 持续丢失超过 `1.0 s` 后 Action 终止并释放控制权。
- 取消、超时和故障均走同一安全停止流程。
- 最大速度、加速度和相对位移均未超过配置上限。
- 跟踪期间无主动 Z 和角速度命令。
- 轨迹模式和跟踪模式不存在并发控制。
- 连续运行 2 分钟无控制状态泄漏、图像积压或持续振荡。

### 9.5 完成判定

以下条件全部满足后，2D 跟踪阶段关闭：

- 单元测试、回放测试、mock 控制测试和真机测试均通过；
- 五步的参数、日志、调试图、Action 结果和控制器状态均已保存；
- 有明确的启动、取消、故障恢复和操作说明；
- 默认启动不自动运动，必须由显式 Action Goal 开始跟踪；
- 现场人员确认方块居中效果和停止行为符合预期。

## 10. 建议开发进度

| 阶段 | 预计时间 | 真机运动 |
|---|---:|---|
| 第一步：2D 感知 | 0.5 天 | 否 |
| 第二步：Action dry-run | 0.5 天 | 否 |
| 第三步：Servo 与控制权仲裁 | 1 天 | mock/fake 优先 |
| 第四步：低速方向验证 | 0.5 天 | 是，短脉冲 |
| 第五步：闭环验收 | 0.5 天 | 是，低速闭环 |

预计 2～3 个工作日形成第一版可演示结果。若第三步发现当前 `JointTrajectoryController` 对 MoveIt Servo 流式单点轨迹的行为不满足要求，应暂停真机阶段，先在 mock 和控制器日志中解决，不通过提高速度或绕过控制权仲裁来推进。

## 11. 3D 升级接口

2D 验收后，按以下顺序升级，不推翻本次基础设施：

1. 保留 Action 生命周期、互斥控制、Servo 输出和安全停止。
2. 将观测从 `(u,v)` 扩展为相机坐标系目标位置 `(x,y,z)`。
3. 增加 Z 距离误差和三维平移控制，末端姿态仍固定。
4. 使用 AprilTag 或经过运动状态验证的 RGB-D 位姿观测增加目标旋转。
5. 最后再实现六自由度相对位姿保持，并单独验收姿态翻转、杠杆臂补偿和抓取衔接。

2D 跟踪成功只证明图像中心闭环、实时控制链和安全仲裁可用，不等同于三维定位、抓取位姿或六自由度跟踪已经完成。
