系统已经完成过一次真实方块的“接近—下降—闭爪—提升”全链路执行，方块被实际夹起，证明坐标链、

2026-09-11 16:13 的“不运动”事件不是 P6 权限未释放，也不是机械臂执行失败。事件发生时：

- P6 已于 16:12:52 完成检查并写入 `passed=true`；

## 4. 每轮目标更新设计

方块可以在每轮测试之间改变位置，但不能在机械臂运动过程中持续追踪并修改执行目标，否则腕部相机
自身运动会改变观测，导致任务目标漂移。因此采用“**每轮重新采集，运动期间冻结**”策略：

1. 操作者摆放方块；
2. 调用 `/fr3c_first_grasp/start`；
3. P5 自动调用 `/perception/blue_cube_localizer/reset`；
4. P3 清除上一轮冻结坐标；
5. 机械臂保持静止，P3 采集 8 个稳定 RGB-D 样本；
6. P5要求 `frozen=true`，并要求图像时间戳晚于本轮 reset；
7. P5锁定本轮新坐标，随后才预张开、规划和接近；
8. 运动期间不再更新本轮坐标。

该握手已经在线 plan-only 验证：目标时间戳从 `1789111807` 更新为 `1789112342`，事件顺序为
`target_reset -> target_acquired -> planning`，未发送硬件动作。证据位于
`evidence/P5/runs/1789112340234563231/events.jsonl`。

## 6. P6 状态解释

本次 P6 报告：`evidence/P6/runs/1789114372964694016/report.json`。

| 检查项 | 结果 |
| --- | --- |
| P6 总结果 | `passed=true` |
| 控制器主/副故障 | `[0,0]` |
| 急停 | 0 |
| 硬件组件 | active |
| 执行控制器 | inactive，等待任务按需占用 |
| 轨迹桥 | `monitoring_manual_ready` |
| ROS FK 对控制器法兰 | 0.00864 mm / 0.00065° |
| 负载 | 原型阶段按操作者决定保留有记录豁免 |

P6 gate 是执行条件快照，不是状态机复位信号：

```text
P6 passed=true  -> 允许处于空闲态的 P5 接受任务
P5 state=FAILED -> 当前任务实例拒绝继续推进
```

因此，“P6 最后变成 true”与“FAILED 的 P5 仍不运动”并不矛盾。

完整栈启动时会先把旧 gate 写成：

```text
passed=false
report_path=full_stack_startup
```

随后延迟 12 秒并采样 5 秒生成新 P6 报告。在自动 P6 输出 `passed=true` 之前调用 `/start`，会看到
`inspect full_stack_startup`。这是为了避免重启后错误沿用上一次启动的通过结果。

## 8. 软件问题与改进建议

### 8.1 P3采集超时策略过于刚性

当前 15 秒适合目标已经清晰可见的情况，但当深度有效率、目标轮廓或尺寸需要短时间恢复时，会把
可恢复的“等待视觉稳定”升级为任务终态失败。

建议改为：

- 默认等待时间提高至 60 秒，或持续等待直到成功/操作者 cancel；
- 等待阶段保持机械臂静止且不发送夹爪命令；
- 超时返回可重试的 `waiting_for_target`，不要进入不可恢复 FAILED。

### 8.2 FAILED 状态缺少显式复位入口

当前 P5 是一次性状态机，任何失败后重复 `/start` 都会被拒绝，需要重启 P5 进程。完整栈已统一到一个
launch 后，为恢复一个任务节点而重启相机、MoveIt 和硬件没有必要。

建议新增：

```text
/fr3c_first_grasp/reset
```

该服务只清除终态、旧运行上下文和 MoveIt 中的 `target_cube` attachment，不自动运动机械臂、不自动
松爪。活动轨迹期间应拒绝 reset。

### 8.3 采集失败信息未向 P5 保留

P5 最终只报告“等待 8 个样本超时”，没有输出 P3 最后一次具体原因。建议在超时响应中附带 P3
最后状态，例如 `insufficient_valid_depth_fraction` 或 `target_count_0`，让操作者能立刻调整方块和视野。

### 8.4 启动就绪状态应更直观

一键启动已自动运行 P6，但从启动到 P6 完成存在约 17 秒窗口。建议在 P5 state 中区分：

- `startup_preflight_pending`
- `waiting_for_target`
- `acquiring_target`
- `waiting_for_descend_command`
- `waiting_for_grip_confirmation`
- `complete_holding`
- `failed`

这样不必通过 gate 文件路径推断系统是否就绪。

## 9. 当前恢复方法

在尚未实现 P5 reset 服务前，当前 FAILED 实例需要重启。使用完整启动方式时：

1. 在运行 `scripts/run_moveit_camera_rviz.sh` 的终端按 `Ctrl+C`；
2. 重新执行同一脚本；
3. 等待日志输出 P3 节点启动和 P6 `passed=true`；
4. 保证方块在相机中完整可见并保持静止；
5. 调用 `/fr3c_first_grasp/start`；
6. P5 会自动 reset P3 并重新取得本轮位置；
7. 到达方块上方后再调用下降闭爪与确认提升服务。

控制命令：

```bash
ros2 service call /fr3c_first_grasp/start std_srvs/srv/Trigger '{}'
ros2 service call /fr3c_first_grasp/descend_and_close std_srvs/srv/Trigger '{}'
ros2 service call /fr3c_first_grasp/confirm_grip_and_lift std_srvs/srv/Trigger '{}'
```
