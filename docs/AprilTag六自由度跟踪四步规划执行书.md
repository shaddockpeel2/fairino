# AprilTag 六自由度跟踪四步规划执行书

更新日期：2026-09-20  
工作区：`/home/industio/fairino_ws`

## 1. 任务目标

在被跟踪物体上刚性安装一个 AprilTag，通过末端相机实时获得标签相对于相机的六自由度位姿，并控制机械臂使相机/TCP 与标签保持设定的相对位置和相对姿态。

整个任务分四步完成：

1. 建立并验证 AprilTag 六自由度位姿感知。
2. 实现固定末端姿态的三维位置跟踪。
3. 实现位置与姿态同时跟踪的六自由度闭环。
4. 接入 Action、语音、抓取任务和实机安全验收。

MoveIt 负责进入初始观察姿态、全局恢复和抓取规划；连续跟踪使用 MoveIt Servo，不逐帧调用 OMPL 重新规划。

## 2. 对亚博参考程序的结论

亚博 `apriltag_follow_VC.py` 可以参考标签检测、标签 ID、图像中心闭环和语音启动流程，但它不是真正的六自由度 AprilTag 跟踪：

- 检测器调用中关闭了 pose estimation。
- 跟踪阶段主要使用标签中心像素。
- 前后位置来自 RGB-D 中心深度。
- 抓取角度主要来自标签一条边在图像中的二维角度。
- 没有使用完整的标签旋转矩阵控制机械臂姿态。
- 直接按像素误差修改舵机角度，缺少 MoveIt 的碰撞和奇异点保护。

参考项目的 `arm_calibration/fiducial.py` 提供了更适合本项目的思路：使用已知标签尺寸、相机内参和 `SOLVEPNP_IPPE_SQUARE` 从四个角点解算标签位姿，并计算重投影误差。

本机现有 OpenCV 4.10 已具备：

- `cv2.aruco.DICT_APRILTAG_36h11`
- `cv2.aruco.ArucoDetector`
- `cv2.SOLVEPNP_IPPE_SQUARE`

当前没有安装 `apriltag`、`dt_apriltags` 或 `pupil_apriltags` Python 包。第一版建议直接使用已有 OpenCV 能力，减少新依赖；如后续实测检出率不足，再对比专用 AprilTag 3 检测器。

## 3. 坐标与标定定义

### 3.1 必须明确的变换

采用 `A_T_B` 表示将 B 坐标系中的点变换到 A 坐标系：

- `camera_T_tag`：视觉检测得到的标签六自由度位姿。
- `flange_T_camera`：现有手眼标定。
- `flange_T_tcp`：现有 TCP 标定。
- `tag_T_object`：标签与被跟踪物体之间的固定安装关系。
- `tag_T_grasp`：标签到期望抓取位姿的固定关系，仅抓取阶段使用。
- `camera_T_tag_desired`：跟踪时希望保持的相机—标签相对位姿。

AprilTag 检测只能直接给出标签坐标系位姿。要获得方块中心、物体姿态或抓取位姿，必须测量或标定 `tag_T_object`、`tag_T_grasp`，不能默认标签中心就是方块中心，也不能默认标签平面就是夹爪抓取平面。

### 3.2 标签制作要求

- 标签族固定为 `tag36h11`。
- 每个被跟踪物体使用唯一 ID，Action 按 ID 锁定目标。
- 标签必须平整、无翘曲、无透明反光覆膜，并刚性固定在物体上。
- 配置中的 `tag_size_m` 必须采用检测算法要求的有效黑色方形边长，不能直接填写纸张外框尺寸。
- 使用卡尺测量实际打印尺寸并记录，禁止直接沿用亚博示例中的 `0.025 m`。
- 标签尺寸、ID、安装面和 `tag_T_object` 应写入配置文件。

### 3.3 跟踪距离

跟踪距离定义为相机光学中心到标签原点的距离。初始建议值为 `0.35 m`，配置范围先限制为 `0.25～0.50 m`。

`15 mm` 不作为相机跟踪距离。若后续要求 TCP 距离物体表面 15 mm，应通过 `tag_T_object` 和 `tag_T_grasp` 生成抓取前目标位姿，并在停止实时跟踪后由 MoveIt 规划执行。

# 第一步：建立 AprilTag 六自由度位姿感知

## 4.1 阶段目标

在机械臂不运动的条件下，稳定发布指定标签的完整位置与姿态，并给出可用于拒绝错误位姿的质量指标。此阶段只做感知，不向机械臂发送运动命令。

## 4.2 检测与位姿解算

建议在 `fr3c_camera` 中新增 `apriltag_pose_tracker.py`，订阅彩色图像和 `CameraInfo`，按以下流程处理：

1. 使用 OpenCV AprilTag 36h11 字典检测标签 ID 和四个角点。
2. 对角点进行亚像素优化。
3. 根据准确的 `tag_size_m` 构造标签平面三维角点。
4. 使用 `solvePnPGeneric(..., SOLVEPNP_IPPE_SQUARE)` 获取平面标签候选解。
5. 只保留标签位于相机前方的解。
6. 根据重投影误差、历史姿态连续性和标签法向方向选择正确解。
7. 使用 Rodrigues/四元数发布 `camera_T_tag`，内部不使用欧拉角做姿态滤波和闭环误差计算。
8. 可选使用注册深度对 `tvec.z` 进行交叉验证，但不以单个中心深度替代 PnP 位姿。

建议发布：

- `geometry_msgs/PoseWithCovarianceStamped`：标签在相机光学坐标系中的位姿。
- `std_msgs/Bool`：当前位姿是否有效。
- 诊断状态：标签 ID、重投影误差、标签像素面积、深度差、位置/角度跳变和时间戳。
- 调试图像：四角、中心、坐标轴、ID、距离和质量状态。
- 可选 TF：`camera_color_optical_frame → tracked_apriltag_<id>`。

## 4.3 位姿质量门限

初始建议门限：

- 目标 ID 必须与 Action 请求一致。
- 重投影均方根误差不大于约 `1.5 px`。
- 标签像素面积不得低于实测可稳定解算阈值。
- PnP 深度与 RGB-D 标签内部深度中值差不大于约 `0.03 m`。
- 相邻有效帧位置跳变不大于约 `0.03 m`。
- 相邻有效帧姿态跳变不大于约 `15°`；超出后重新获取，不能直接送入控制器。
- 位姿消息年龄不大于 `0.20～0.25 s`。

位置可使用低通或 α-β 滤波；姿态使用四元数球面插值或 SO(3) 滤波，禁止直接平均欧拉角。对平面 PnP 的镜像/翻转候选必须做时间连续性判断。

## 4.4 第一步验证

1. 生成已知 ID 和准确尺寸的实体标签。
2. 在若干已测距离、平移位置和倾斜角度下采集数据。
3. 比较 PnP 深度与 RGB-D 深度。
4. 静止保持 30 秒，统计位置和姿态抖动。
5. 缓慢旋转标签，确认四元数连续，无 180° 突跳。
6. 多标签同时出现时，只发布请求 ID，不按 ID 排序后盲选第一个。

## 4.5 第一步通过标准

- 能稳定识别指定 `tag36h11` ID。
- 发布完整平移和四元数姿态，不只发布中心像素和二维边角。
- 静止标签无频繁姿态翻转。
- 错误尺寸、错误 ID、低质量角点和过期图像均被拒绝。
- 记录可复现的距离误差、姿态抖动和重投影误差结果。

第一步通过前不得连接视觉结果到机械臂运动控制。

# 第二步：实现三维位置跟踪

## 5.1 阶段目标

使用 AprilTag 的平移向量控制机械臂三轴平移，使标签原点保持在设定的相机相对位置；末端姿态暂时固定。

默认期望关系为：

- 标签中心位于相机主光轴附近。
- 相机到标签距离约 `0.35 m`。
- 只控制位置，不使用标签旋转控制腕部。

## 5.2 控制误差

设检测结果中的标签位置为 `t=[x,y,z]`，期望位置为 `t*=[x*,y*,z*]`，位置误差为：

`e_t = t - t*`

通常 `x*=0`、`y*=0`、`z*=desired_distance_m`。控制器在相机坐标系计算期望相机线速度，再通过 TF 和相机/TCP 偏置换算为 MoveIt Servo 末端命令。

第一版采用带饱和的比例控制，不使用积分项：

- 横向最大速度：`0.03 m/s`。
- 光轴方向最大速度：`0.02 m/s`。
- 首次实机测试总速度限制为 `0.01～0.02 m/s`。
- 最大线加速度：`0.08 m/s²`。
- MoveIt Servo 控制输出建议 `50 Hz`，底层控制器保持 `125 Hz`。

## 5.3 防抖和滞回

位置保持使用双层容差，而不是要求误差严格为零：

- 进入保持区：横向误差小于约 `8 mm`，深度误差小于约 `15 mm`，连续满足 `0.4 s`。
- 退出保持区：横向误差超过约 `15 mm`，或深度误差超过约 `25 mm`，连续 `2～3` 帧。
- `CENTER_HOLD` 状态输出零速度，但持续更新标签位姿。
- 小误差区速度连续衰减到零，不设置最小非零速度。
- 目标超过 `0.25 s` 未更新时立即输出零速度。
- 目标持续丢失超过 `0.8 s` 时终止 Action 并释放控制器。

这些门限应根据第一步得到的实测抖动调整，必须明显大于静止标签的测量噪声。

## 5.4 MoveIt Servo 与安全限制

新增 MoveIt Servo 配置，并启用：

- 关节限位检查。
- 自碰撞和规划场景碰撞检查。
- 奇异点减速和停止。
- 输入命令超时。
- 工作空间边界。
- 总速度和加速度限制。
- 相机—目标、TCP—物体的最小安全距离。

全局规划只用于进入安全观察姿态。实时跟踪期间不反复调用 OMPL。

## 5.5 第二步通过标准

- 标签沿相机左右、上下、前后三个方向移动时，机械臂跟踪方向正确。
- 静止标签进入保持区后，机械臂不持续抽动。
- 目标丢失、位姿跳变或质量不合格时在规定时间内停止。
- 达到工作空间、碰撞、关节或奇异点限制时拒绝继续追踪。
- 姿态控制关闭，末端保持启动时的固定姿态。

第二步通过前不得启用标签姿态跟随。

# 第三步：实现六自由度相对位姿跟踪

## 6.1 阶段目标

在三维位置跟踪稳定后，同时控制末端平移和旋转，使 `camera_T_tag` 收敛并保持在配置的 `camera_T_tag_desired` 附近。

当标签随物体旋转时，机械臂调整自身姿态，保持设定的相机—标签相对朝向。此阶段实现真正的 AprilTag 六自由度闭环，不再只根据标签中心或二维边角控制腕部。

## 6.2 位姿误差

姿态误差使用旋转矩阵、四元数或 SO(3) 对数映射计算，不直接相减欧拉角：

- 平移误差：当前标签位置与期望标签位置之差。
- 旋转误差：当前 `camera_R_tag` 与期望 `camera_R_tag_desired` 的最短旋转。
- 将六维误差转换为期望相机 Twist。
- 根据已标定的相机到 Servo 末端参考点偏置，将相机 Twist 换算为末端 Twist。
- 统一变换到 MoveIt Servo 要求的命令坐标系。

由于相机光学中心与 `grasp_frame`、`flange_link` 不重合，旋转时必须补偿杠杆臂产生的线速度，否则姿态修正会引起位置反复摆动。

## 6.3 姿态控制参数

初始实机上限建议：

- 最大角速度：`0.10 rad/s`。
- 最大角加速度：`0.25 rad/s²`。
- 姿态进入保持容差：约 `3°`。
- 姿态退出保持容差：约 `5°`。
- 大于约 `15°` 的单帧姿态跳变先判为观测异常，不立即跟随。

位置和姿态同时接近限位时应整体缩放六维速度，不能分别截断后改变 Twist 方向。接近腕部奇异点时优先降低或停止角速度。

## 6.4 跟踪模式

`TrackAprilTag` Action 应至少支持：

- `POSITION_ONLY`：只使用标签平移，行为与第二步一致。
- `FULL_POSE`：保持完整 `camera_T_tag_desired`。

期望位姿可以来自：

1. 配置文件中的安全默认相对位姿。
2. Action Goal 明确提供的 `desired_tag_pose_in_camera`。
3. “锁定当前关系”模式：启动时保存当前稳定相对位姿，之后跟随标签变化。

不接受缺少坐标语义的裸欧拉角或仅写“保持 15 mm”之类不完整目标。

## 6.5 第三步通过标准

- 标签做平移和缓慢旋转时，末端能够同时跟踪位置和姿态。
- 标签静止后，线速度和角速度均进入零输出保持状态。
- 标签正面、倾斜和旋转过程中无持续 180° 姿态翻转。
- 相机偏置补偿后，纯姿态调整不会造成明显的距离振荡。
- `POSITION_ONLY` 与 `FULL_POSE` 可以明确切换，且状态反馈正确。
- 目标丢失、取消或观测超时时，六个速度分量全部归零。

第三步通过前不接入自动抓取和语音任务编排。

# 第四步：Action、语音、抓取集成与实机验收

## 7.1 TrackAprilTag Action

在 `fairino_msgs/action` 中新增 `TrackAprilTag.action`，建议包括：

**Goal**

- `tag_id`
- `mode`：`POSITION_ONLY` 或 `FULL_POSE`
- `desired_tag_pose_in_camera`
- `lock_current_relative_pose`
- `max_duration_s`，`0` 表示持续到取消

**Feedback**

- `phase`：`ACQUIRING/TRACKING/CENTER_HOLD/LOST_HOLD`
- 当前标签位姿与质量状态
- 位置误差和姿态角误差
- 当前线速度和角速度
- 是否进入保持区
- MoveIt Servo 状态

**Result**

- 成功标志、错误码和结束原因
- 标签 ID、最终误差和运行时间
- 是否因取消、目标丢失、安全限制或控制器故障结束

达到期望位姿后 Action 不自动结束，而是进入保持状态，持续运行到取消或超时。

## 7.2 控制权互斥

扩展 `trajectory_control_bridge.py` 或新增统一自动控制管理器，为六轴机械臂提供独占控制模式：

- `TRAJECTORY`：现有 MoveIt 抓取、放置和 RViz 执行。
- `SERVO_TRACKING`：AprilTag 连续跟踪。

必须保证：

1. 两种模式不能同时控制关节。
2. 跟踪期间新的轨迹 Action 返回忙碌。
3. 抓取期间新的跟踪 Action 返回忙碌。
4. 跟踪控制具有心跳和看门狗。
5. Action 取消、节点异常和正常退出都执行零速度、确认停止、停用控制器和释放控制权。

## 7.3 语音接口

在 `fr3c_voice` 中增加：

- “跟踪机器码”或“跟踪 `<ID>` 号标签”：发送 `TrackAprilTag` Goal。
- “停止跟踪”：取消当前跟踪 Goal。

语音层只负责选择 ID、模式、启动和取消，不直接发布速度命令。

## 7.4 跟踪后抓取

如果需要实现“跟踪稳定后抓取”，必须按以下顺序执行：

1. 标签位置和姿态同时进入保持区，并连续稳定一段时间。
2. 取消 `TrackAprilTag`。
3. 确认 MoveIt Servo 已停止且控制器已释放。
4. 机械臂静止后重新检测一次稳定 `base_T_tag`。
5. 使用已标定的 `tag_T_grasp` 计算 `base_T_grasp`。
6. 由 MoveIt 重新进行碰撞检查、全局规划、接近和抓取。

不得直接把连续跟踪中的最后一条 Twist 延伸成抓取动作，也不得仅凭标签中心深度生成抓取姿态。

## 7.5 最终验收

至少完成以下场景：

1. 静止标签六自由度位姿稳定性测试。
2. 标签三轴平移跟踪连续运行 2 分钟。
3. 标签缓慢平移和旋转的六自由度跟踪连续运行 2 分钟。
4. 标签进入保持区后持续 30 秒，无长期抽动。
5. 短暂遮挡后恢复同一 ID；持续遮挡后安全终止。
6. 多个不同 ID 同时出现时只跟随目标 ID。
7. 同一 ID 的异常跳变、镜像解和低质量位姿不驱动机械臂。
8. 跟踪与现有四个抓取 Action 互相拒绝并发控制。
9. 取消、超时、节点退出、碰撞、奇异点和控制器异常均能停止并释放控制权。
10. 完成“语音启动 AprilTag 跟踪—语音停止跟踪”的完整演示。
11. 如启用跟踪后抓取，必须完成“停止跟踪—静止重定位—MoveIt 规划—抓取”的独立验收。

## 9. 完成判定

四步全部通过后，系统应具备：

- 根据指定 AprilTag ID 输出经过质量校验的六自由度位姿。
- 保持配置的相机—标签三维位置或完整相对位姿。
