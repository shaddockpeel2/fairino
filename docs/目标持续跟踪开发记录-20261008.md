# 目标持续跟踪开发记录

## 已确认的目标和开发顺序

- 沿用 30 mm 正方体方块，顶面是实机识别的 AprilTag 36h11 / ID 1。
- 用户测量标签边长为 20 mm，此尺寸用于 PnP；方块 30 mm 尺寸不替代标签尺寸。
- 位置、姿态都求解并输出。机械臂先接位置跟随，姿态暂不用于控制。
- 新包独立开发，保留现有相机、内参、手眼和 TCP 资源。

## 第一步：相机坐标下完整位姿测量

实现位于 `src/fr3c_target_follow/`，包括 OpenCV 检测/PnP、ROS 节点、实时图像查看器、采样工具、启动脚本和测试。

当前使用 DaBai DCW2 的 640×480 RGB、15 FPS 配置，内参来自实时 CameraInfo。节点兼容相机环境的系统 OpenCV 4.5.4，也通过用户环境 OpenCV 4.10.0 下的核心测试。

输出是 `T_camera_color_optical_tag`，位置单位米、姿态四元数 xyzw，原点在顶面标签中心。保留原图时间戳，同时发布图像年龄、重投影误差、候选解差异和姿态歧义。

丢失目标、重复 ID、过期图像和时间戳回退时不发布新位姿；恢复有效观测后重新发布。节点没有机械臂连接、Servo 接口或运动命令。

### 开发中解决的具体问题

1. 20 mm 标签在当前画面较小。对同一组 50 帧比较检测参数，默认参数识别 43 帧；阈值常量 13、步长 4 识别 50 帧。最终效果由上述独立实时采样评估，未以这 50 帧对比代替复测。
2. OpenCV 4.5.4 的 IPPE_SQUARE 在严格正对相机、居中的合成标记上可能退化。添加经过相同正深度和重投影检查的迭代 PnP 回退，并记录使用的求解器。
3. ROS Humble 的 Image.data setter 在传入 bytes 时逐字节检查一整张图像，阻塞检测回调。改用 `array('B')` 直接传递；实机帧率恢复到约 14.2 FPS，数据年龄下降，最终采样没有过期图像拒绝。
4. 使用标准传感器 DDS 接收缓冲，应用内部仍只保留最新图像。最后一轮收到、处理图像数相同，没有处理队列积压。

## 第二步：只读机械臂反馈、基坐标和位置预览

新增 `src/fr3c_follow_feedback/`，通过固定的 C++ SDK 读取状态包。只调用连接、读取、关闭接口，不设置机械臂模式、使能或运动。新的法兰反馈在 `base_link` 下发布，软件使用已接受的 `flange_link → grasp_frame` TCP 标定计算夹爪 TCP。

`fr3c_target_follow` 增加法兰位姿历史缓存和图像时刻插值，利用现有手眼与相机驱动的光学坐标变换换算标签基坐标。位置按线性插值、旋转按 SLERP 插值；没有包围图像时间的反馈时，不使用任意最新反馈替代。

控制器显示时钟比主机快约 330 秒。新反馈使用主机首次观察到新状态包的时间，控制器时间仅记录为诊断，不将不同的时钟直接相减。这个参考仍包含网络和轮询偏差，当前验证针对低速、小幅动作。

记录当前偏移后，期望 TCP = 标签基坐标位置 + 固定偏移，期望旋转保持记录时的 TCP 旋转。输出位置误差、限幅速度和从实际 TCP 出发的一步参考；未将这个参考当作“机器人已经移动”的反馈。

## 第三步：原厂伺服执行端——已完成

新增 `src/fr3c_follow_driver/`。一个 C++ 程序拥有一个 SDK 连接，直接调用原厂 `ServoMoveStart`、`ServoCart`、`StopMotion`、`ServoMoveEnd`，同时发布已有法兰反馈、机械臂状态和 TF。没有接入视觉目标控制，也没有调用模式切换、使能或故障复位。

默认运行只检查当前机械臂状态。追加 `--move` 才执行一次基坐标 X/Y/Z 固定姿态平移；默认 5 mm、速度上限 5 mm/s、五次曲线平滑起停，终点保持 0.5 秒后结束伺服。支持负方向、Ctrl-C、停止服务和指定时间的途中停止。单次位移限在 10 mm 内。

当前使用工具 0、工件坐标 0 零变换控制法兰。固定旋转时法兰与夹爪 TCP 的平移量相同，现有预览仍可通过 TCP 标定计算实际夹爪位置。8 ms 是待实测的候选发送周期，不是实机 125 Hz 能力的结论。
