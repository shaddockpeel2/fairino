# FR3-C 多轮 RGB 方块抓取状态机与 P6 门禁优化技术报告

日期：2026-09-11  
工作区：`/home/industio/fairino_ws`  
适用入口：`scripts/run_moveit_camera_rviz.sh`  
涉及模块：P3 蓝色方块定位、P5 三步抓取、P6 执行前门禁

## 1. 报告结论

本轮开发解决了三个连续运行问题：P3 稳定后永久冻结、P5 一轮完成后无法再次启动、P6 在同一
运行会话中固定 600 s 后过期。当前软件行为调整为：

1. P3 持续处理 RGB-D 数据并滚动更新最近稳定目标，不因第一次 `valid=true` 永久停止判断；
2. P5 在每次 `/start` 调用瞬间检查并复制一份目标快照，任务开始后不再受实时视觉更新影响；
3. 一轮抓取完成后的 `complete_holding` 可接受下一次显式 `/start`，并在接受新目标后清理上一轮
   MoveIt 附着物和世界碰撞物；
4. P6 gate 首次进入当前 P5 进程时仍必须新鲜，但被当前进程接受后，在同一次组合栈会话内不再
   因固定 10 分钟超时；gate 被删除、改为失败、改变控制路径或组合栈重启时仍会拒绝动作；
5. 所有运动仍由操作者显式分三步授权，不增加后台自动重试或自动循环。

已有真机证据表明一次完整抓取和 50 mm 提升成功。连续第二轮状态转换及新的 P6 会话有效期逻辑
已完成编译和离线验证，仍需在下一次现场运行中完成一次多轮实物复验。

## 2. 问题现象与根因

### 2.1 P3 永久冻结与每轮强制重新采样

旧实现积累 8 个稳定样本后进入 `frozen=true`，停止更新目标。P5 为避免使用旧位置，每次
`/start` 又先 reset P3，再等待最多 15 s 的全新 8 帧。该组合存在两个问题：

- 稳定目标不能随方块重新放置而自然更新；
- 一次坏帧或处理延迟可能令 15 s 等待失败，P5 随后进入终止状态，即使视觉稍后恢复也不能重试。

### 2.2 `complete_holding` 阻止第二轮

首轮完成后服务返回：

```text
success=False
Task is not idle; current state=complete_holding
```

这不是视觉失败。P5 原状态机只允许 `waiting_for_target`、可重试的运动前失败和 plan-only 完成状态
进入 `/start`，把 `complete_holding` 当作永久终态。同时，首次提升后 `target_cube` 仍保留为
MoveIt attached collision object。如果只把 `COMPLETE` 加入允许列表，第二轮会带着上一轮附着模型
规划，因此必须同时完成规划场景清理。

### 2.3 P6 在同一会话内超时

现场出现：

```text
Start refused: P6 gate is stale: age_s=2002.28, limit_s=600
```

2002.28 s 约为 33 分 22 秒。旧 P5 在每个授权阶段都用 gate 文件修改时间与 600 s 比较，因此正常
运行超过 10 分钟也会拒绝。组合栈启动时本来已经主动把旧 gate 写成 `passed=false`，随后自动运行
新 P6；在此机制下，再给同一 P5 进程设置任意 10 分钟寿命并不能准确表达“当前运行会话”。

## 3. 优化后的总体设计

```text
P3 持续观测
    │
    ├─ 当前不稳定 ──> valid=false，保存位置可保留但禁止新任务使用
    │
    └─ 当前稳定 ────> 更新最近稳定位置，valid=true
                              │
                        操作者调用 /start
                              │
                 P6 + 新鲜度 + 工作区 + 桌面高度检查
                              │
                       复制不可变目标快照
                              │
               预张开/规划/接近 → 人工下降授权
                              │
                    下降闭合 → 人工提升授权
                              │
                         50 mm 提升完成
                              │
                       complete_holding
                              │
          操作者放置方块、结束拖动、等待新目标稳定后再次 /start
```

关键边界是“视觉持续更新，任务目标一次复制”。P3 可以持续变化，但已接受的 P5 任务不读取变化后的
位置，从而避免腕部相机运动期间目标漂移。相反，尚未接受的 `/start` 只依据调用瞬间条件，失败后
不会因为视觉后来变好而自动执行。

## 4. P3 连续视觉定位

实现文件：`src/fr3c_camera/fr3c_camera/blue_cube_localizer.py`  
配置文件：`src/fr3c_camera/config/blue_cube_localizer.yaml`

当前稳定策略为：

| 参数 | 当前值 | 作用 |
| --- | ---: | --- |
| `stable_samples` | 8 | 稳定窗口样本数 |
| `stable_xy_std_m` | 0.003 m | XY 标准差上限 |
| `stable_z_std_m` | 0.003 m | Z 标准差上限 |
| `stable_sample_max_gap_s` | 0.75 s | 合格样本最大时间间隔 |
| `max_sample_jump_m` | 0.020 m | 相邻合格位置最大跳变 |

短暂被拒绝的帧不会立即清空已接受样本；下一个合格样本只要没有超过时间间隔和位置跳变门限，
即可继续完成窗口。超过门限时清空窗口，避免把两个物体位置混在一起。稳定后每个合格滚动窗口都
更新保存位置，并发布：

```json
{
  "valid": true,
  "stable": true,
  "tracking": true,
  "frozen": false,
  "has_stable_pose": true,
  "reason": "stable_target_updated"
}
```

当画面候选数错误、深度不合格、机器人运动、TF 失败或数据过期时，当前 `valid=false`；保存的旧
pose 可以继续用于显示，但 P5 不得以此启动新任务。

现场后续日志已经观察到新的稳定位置：

```text
base_link [-0.0817, -0.4474, 0.0356] m
```

这证明 P3 已不再停留在首次抓取位置。

## 5. P5 目标快照与多轮状态机

实现文件：`src/fairino_mtc_demo/src/first_grasp_node.cpp`  
配置文件：`src/fairino_mtc_demo/config/first_grasp.yaml`

### 5.1 `/start` 接受条件

每次 `/start` 依次检查：

1. P6 gate 是否可接受；
2. 状态是否允许启动且没有旧工作线程仍在结束；
3. P3 当前 `valid=true`；
4. pose 与 valid 心跳接收时间不超过 1.0 s；
5. pose 原始图像时间戳不超过 1.0 s；
6. XYZ 位于首次抓取工作区；
7. 30 mm 方块底面与配置桌面 Z 的间隙在 0～10 mm 内。

全部通过后把 pose 和 P3 status 复制到 `locked_target_`。接近、下降和提升都只使用该副本。

### 5.2 多轮转换

可接受新 `/start` 的状态为：

- `waiting_for_target`；
- `retryable_failure_before_arm_motion`；
- `plan_only_complete`；
- `complete_holding`。

从 `complete_holding` 开始下一轮时，P5 只有在新视觉目标已通过上述检查后才执行场景清理：

1. 删除上一轮 `target_cube` attached object；
2. 读回确认该对象不再附着；
3. 删除同 ID 的旧 world collision object；
4. 读回确认世界对象已消失；
5. 锁定新目标并开始本轮任务。

如果新目标不合格，上一轮场景状态保持不变。如果清理失败，服务返回 `Next trial refused`，不发送
夹爪或机械臂命令。并发 `/start` 使用独立互斥锁串行处理，防止两个请求同时修改规划场景。

### 5.3 失败边界

- 调用瞬间的 P3/P6 条件不合格：服务立即 `success=false`，状态保持可再次调用；
- 预张开、获取当前状态或规划在机械臂运动前失败：进入
  `retryable_failure_before_arm_motion`，修复条件后可再次 `/start`；
- approach 已开始后的执行故障：进入 `failed_holding_state_unchanged`，禁止自动重试；
- `/start success=true` 表示异步任务已接受，不表示运动已经完成，完成情况以
  `/fr3c_first_grasp/state` 和事件记录为准。

## 6. P6 会话门禁

P6 gate 文件包含签名、`passed`、生成时间、控制路径和证据报告路径。新 P5 的处理方式为：

1. 当前进程第一次遇到某个 gate 身份时，仍检查其文件时间不超过 `p6_gate_max_age_s=600`；
2. 通过后，以 `generated_at + report_path` 作为 gate 身份缓存在当前 P5 进程内；
3. 后续每次 `/start`、下降授权、提升授权和实际 approach 前仍重新读取文件；
4. 若还是同一个已接受身份，便不再应用 600 s 超时；
5. 文件缺失、格式损坏、`passed=false`、控制路径不是 `moveit_joint_servoj` 时立即拒绝；
6. 组合栈重启时 `full_first_grasp.launch.py` 先原子写入失败 gate，12 s 后重新执行 P6，因此旧会话
   授权不能跨组合栈重启复用。

如果工作区、线缆、停止方式或运动源在运行期间发生实质变化，操作者仍应主动重新运行 P6。新的
P6 结果会覆盖 gate 文件，失败结果会立即阻断后续授权。

## 9. 推荐现场流程

首次启动：

```bash
cd /home/industio/fairino_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
scripts/run_moveit_camera_rviz.sh
```

等待 P6 输出 `passed=true`，并检查：

```bash
ros2 topic echo /perception/blue_cube_localizer/status --once
ros2 topic echo /perception/blue_cube_localizer/top_pose --once
ros2 topic echo /fr3c_first_grasp/state --once
```

单轮三步：

```bash
ros2 service call /fr3c_first_grasp/start std_srvs/srv/Trigger '{}'
ros2 service call /fr3c_first_grasp/descend_and_close std_srvs/srv/Trigger '{}'
ros2 service call /fr3c_first_grasp/confirm_grip_and_lift std_srvs/srv/Trigger '{}'
```

下一轮前：

1. 确认机械臂处于安全停止状态；
2. 实际取下方块并重新放到桌面；
3. 结束法兰按钮拖动，确认不存在其他运动源；
4. 等待 P3 `valid=true`、`stable=true`，核对 top pose 已变为新位置且 Z 约为桌面方块顶面高度；
5. 再次调用同一个 `/start`，无需 reset P3 或重启抓取栈。

如果仍运行修改前的 P5 进程并出现 P6 600 s 过期，可在确认五项现场条件仍真实成立后重新运行
`p6_preflight`；新代码需要重启一次组合栈才能载入，此后同一会话不再按固定 10 分钟过期。

## 10. 安全限制

1. 软件无法检测操作者是否真的从夹爪取下方块；下一轮 `/start` 会预张开夹爪，调用前必须确认
   方块已安全放置；
2. P3 保存的 pose 不等于当前有效，任何新任务必须同时检查 `valid` 和时间戳；
3. P6 会话有效假设现场确认条件没有发生实质变化；条件变化时必须重跑 P6；
4. `success=true` 仅表示服务接受任务，必须继续监视状态和 MoveIt/控制器返回码；
5. 机械臂开始运动后的失败保持终止，不允许利用新视觉数据自动恢复旧命令；
6. 当前 payload/CoG 仍为有记录的低速原型豁免，精度、动力学或提速前必须实测并写入控制器和配置。
