# 机械臂运行速度与轨迹执行超时调整参考

## 1. 适用范围

本文用于 FR3-C 四色连续分拣任务，说明以下两个相互关联但不能混为一谈的参数：

- 抓取任务生成轨迹时使用的速度、加速度缩放比例；
- MoveIt 等待真实机械臂完成一条轨迹时允许的执行时间余量。

调整前必须先完成单块仅规划检查。真实执行时应保持工作区净空、急停可用且不存在第二个运动控制源。

## 2. 最近一次返航未完成的日志结论

最近一次四块连续分拣中，红、黄、蓝三块的返航均成功，最后一块绿色方块已经完成放置、张爪和放置后抬升，但返回初始关节位置时被 MoveIt 取消。

| 颜色 | 返航规划时长 | 实际等待时长 | 结果 |
|---|---:|---:|---|
| 红 | 20.711 s | 20.847 s | 成功 |
| 黄 | 4.325 s | 4.472 s | 成功 |
| 蓝 | 5.612 s | 5.754 s | 成功 |
| 绿 | 21.582 s | 24.279 s | MoveIt `-6` 超时 |

绿色返航使用了默认 MoveIt 执行上限：

```text
规划时长 × 1.1 + 0.5 s
= 21.582 × 1.1 + 0.5
= 24.240 s
```

实际在约 24.279 秒被取消，与默认上限吻合。取消时机械臂大约只到达返航轨迹的 17.8 秒位置，说明真实机械臂在这条大范围多关节返航中落后于时间参数化轨迹。该问题发生在返航执行阶段，与多目标识别顺序和“空场持续 10 秒结束”无关。

对应证据目录：

```text

```

## 3. 能否提高运行速度

可以适度提高，但不建议把“提高速度”作为这次超时的唯一修复。本次调整前的任务参数为：

```yaml
velocity_scale: 0.065
acceleration_scale: 0.065
```

配置位置：

```text
src/fairino_mtc_demo/config/first_grasp.yaml
```

建议分两步验证：

### 第一阶段：小幅提速

```yaml
velocity_scale: 0.075
acceleration_scale: 0.065
```

速度提高约 15%，先保持加速度不变，减少起停冲击和夹持方块晃动。

当前工程已采用该第一阶段值。运行脚本启动时会从
`first_grasp.yaml` 加载，不需要修改 C++ 内的备用默认值。

### 第二阶段：第一阶段稳定后再评估

```yaml
velocity_scale: 0.080
acceleration_scale: 0.070
```

只有在以下项目均通过时才进入第二阶段：

- 接近、下降和抬升没有明显振动；
- 方块在长距离搬运中没有滑动；
- 每段动作的到位误差检查持续通过；
- 真实关节跟随没有比当前更明显地落后；
- 相机支架、夹爪线缆和第六轴线缆余量正常。

如果提高速度后实际跟随落后增大，应退回上一档。规划速度更高会缩短轨迹标称时长，也会缩短默认执行超时上限，因此必须同时配置下一节的执行时间余量。

## 4. 显式增加 MoveIt 轨迹执行余量

建议在下面的文件中加入执行时间配置：

```text
src/fairino3mt_v6_moveit2_config/config/moveit_controllers.yaml
```

推荐起始值：

```yaml
trajectory_execution:
  allowed_execution_duration_scaling: 1.5
  allowed_goal_duration_margin: 2.0
  execution_duration_monitoring: true
```

含义：

- `allowed_execution_duration_scaling: 1.5`：允许实际执行使用规划时长的 1.5 倍；
- `allowed_goal_duration_margin: 2.0`：在缩放结果之外再增加 2 秒；
- `execution_duration_monitoring: true`：继续保留超时监控，不能关闭。

以本次绿色返航为例，新上限约为：

```text
21.582 × 1.5 + 2.0 = 34.373 s
```

该余量足以覆盖本次约 24.3 秒时仍未完成的情况，同时没有把超时设置成无限等待。增加时间余量不会绕过碰撞检查、控制器返回值检查或任务节点的最终到位误差检查。

不建议通过以下方式处理：

- 关闭 `execution_duration_monitoring`；
- 把执行余量一次提高到非常大的数值；
- 删除返航后的到位检查；
- 在执行失败后不确认机械臂状态就自动开始下一次抓取。

## 5. 编译、重启与参数确认

修改配置后重新构建：

```bash
cd /home/industio/fairino_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select fairino3mt_v6_moveit2_config fairino_mtc_demo \
  --symlink-install
```

关闭旧抓取栈并重新启动。MoveIt 参数只在启动时读取，不能依赖旧进程继续运行。

```bash
scripts/run_moveit_camera_rviz.sh detection_mode:=colors
```

启动后确认执行余量已经生效：

```bash
ros2 param get /move_group \
  trajectory_execution.allowed_execution_duration_scaling
ros2 param get /move_group \
  trajectory_execution.allowed_goal_duration_margin
ros2 param get /move_group \
  trajectory_execution.execution_duration_monitoring
```

预期分别得到 `1.5`、`2.0` 和 `true`。如果显示 `Parameter not set`，说明参数没有进入 `/move_group`，此时不要进行真实批量执行。

## 6. 推荐现场验证顺序

1. 使用当前姿态和一个方块做仅规划检查，确认抓取、放置、返航轨迹正常。
2. 使用第一阶段速度执行一个方块，优先选择会产生较长返航路径的位置和颜色。
3. 检查该次 `events.jsonl` 中 `execute_return_home_execute` 是否为 `return_code=1`。
4. 确认 `arrival_return_home_execute` 的位置和姿态误差通过。
5. 再执行四块连续分拣，确认最终进入 `batch_complete` 或 `batch_complete_with_skips`。
6. 第一阶段连续稳定后，再决定是否采用第二阶段速度。

监控命令：

```bash
ros2 topic echo /fr3c_first_grasp/state
ros2 topic echo /fairino/control_state
ros2 control list_controllers
```

正常完成时，最后一块应依次出现：

```text
returning_home
complete_sorted_home
batch_scanning
batch_complete（或 batch_complete_with_skips）
```

## 7. 回退值

若提速后出现振动、掉块、跟随落后或新的执行失败，先恢复抓取任务参数：

```yaml
velocity_scale: 0.065
acceleration_scale: 0.065
```

执行时间余量可以继续保留，因为它只允许真实控制器有更合理的完成时间，并且任务仍会执行最终到位检查。若需要完全恢复原行为，删除 `trajectory_execution` 配置块并重启整个 MoveIt/抓取栈。
