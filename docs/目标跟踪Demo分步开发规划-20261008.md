实现与现场验证的内容：

1. 沿用已有基坐标位置和误差计算，启动跟随前重新记录当前偏移与固定旋转。
2. 连续计算 `期望 TCP = 当前目标基坐标位置 + 记录的偏移`，利用实际 TCP 反馈产生平滑伺服参考。
3. 初版使用预览的低速起点，之后根据现场动作调整；目前执行端为位置增益 2.0/s、速度上限 20 mm/s、加速度上限 60 mm/s²，以当前配置文件为准。
4. 先移动一个方向，再验证另两个方向，最后组合移动。方块停下时，末端应逐渐收敛并停稳。
5. 目标遮挡或数据过期时停止推进；重新出现后平滑恢复，恢复前检查当前目标仍处于跟随范围。一次停止后重新开始，应重新记录偏移。

完成标准：方块缓慢移动时末端能跟上，固定偏移大致保持，没有明显持续来回振荡；停止、遮挡和恢复操作可用。

第四步沿用目标超时 350 ms、反馈超时 200 ms；当前跟随范围是开始时实际 TCP 周围半径 1.00 m，初版为 0.10 m，可根据现场空间调整。实际运动时检查停止与恢复是否合适后再确定参数，避免把正常一两帧未识别当故障，也不延用长时间丢失的目标。保持速度限制、有限跟随空间和明确停止操作即可。

## 7. 第六至第十步：完整位姿跟随扩展

### 7.1 思路选择与当前实现判断

采用 **标签六自由度测量 + 图像时刻基坐标换算 + 固定相对位姿 PBVS + 原厂 ServoCart**。这是在现有位置跟随链路上增加旋转目标、旋转反馈和相关限制，继续由同一个 C++ SDK 所有者负责反馈、发送与停止。

视觉伺服的经典路线包括基于图像误差的 IBVS、基于三维位姿的 PBVS，以及混合方案；取舍和视野问题可参考 [Hutchinson 的视觉伺服资料](https://www-cvr.ai.uiuc.edu/ResPages/vs.php)。本项目已具备有尺度的标签位姿、手眼/TCP 标定和可用的位置 PBVS，因此优先扩展 PBVS。MoveIt Servo 提供实时末端速度控制、奇异位形处理和碰撞检查，见 [Humble 官方说明](https://moveit.picknik.ai/humble/doc/examples/realtime_servo/realtime_servo_tutorial.html)；本阶段借鉴这些控制约束，执行仍沿用已验证的原厂接口。

| 当前资源 | 已有能力 | 位姿扩展需要补什么 |
| --- | --- | --- |
| `marker_pose.py` / `pose_node.py` | IPPE_SQUARE 候选解、连续性选择、完整四元数、歧义与重投影误差输出 | 姿态可用性判定、候选旋转间距、跳变检测、恢复确认 |
| `follow_geometry.py` / `preview_node.py` | 法兰位姿插值，完整目标基坐标变换，完整 TCP 标定加载 | 在基坐标验证旋转稳定性，按同一图像时间戳传递位姿与质量 |
| `PositionPreview` | 固定基坐标平移偏移、固定 TCP 旋转 | 完整相对变换记录、角度误差与无运动旋转预览 |
| `PositionFollow` / `position_follow.cpp` | 固定旋转的位置闭环，速度/加速度限制，连续参考与停止恢复 | 消费目标旋转，加入 SO(3) 控制，动态换算法兰目标 |
| `collision_guard.cpp` | 实测完整机器人状态与当前位置碰撞检查，固定旋转的平移预测 | 带旋转的未来位姿和附件扫掠预测，以及旋转方向变化后的结果有效性检查 |

**当前最需要先确认的是姿态测量，而不是是否能够输出四元数。** 第一步历史报告 `evidence/target_follow/20261008/live_pose_verified_45s/report.json` 中，620 帧有效检测有 619 帧标记 `orientation_ambiguous=true`，标签最短边中位数约 26.44 px；姿态相对首帧变化最大约 17.17°。这段记录可能包含目标真实运动，不能将该变化直接认定为静态噪声，也不能据此否定已有位置跟随；但尚不足以证明旋转适合用于控制。

平面小标签会出现两个接近的候选解。OpenCV 支持用 `solvePnPGeneric` 获取多解，见 [PnP 官方说明](https://docs.opencv.org/4.13.0/d5/d1f/calib3d_solvePnP.html)。[IPPE 作者的说明](https://github.com/tobycollins/IPPE#resolving-the-flip-ambiguity)指出，时间平滑能减少翻转，却不能保证正确消歧，需要额外几何或观测信息。因此不以放宽歧义阈值、只取最低重投影误差或增大低通作为姿态问题的解决办法。

### 7.2 明确跟随关系和坐标定义

用户已选择保持完整相对位姿。以现有标签中心为目标坐标原点，开始时记录：

```text
T_base_tcp_actual = T_base_flange_actual × T_flange_tcp
T_tag_tcp_offset = inverse(T_base_tag_initial) × T_base_tcp_initial
T_base_tcp_desired(t) = T_base_tag_filtered(t) × T_tag_tcp_offset
T_base_flange_reference(t) = T_base_tcp_reference(t) × inverse(T_flange_tcp)
```

旋转目标也会改变位置目标。假设记录的偏移在标签坐标中为 `d_tag`，则：

```text
p_tcp_desired = p_tag_filtered + R_tag_filtered × d_tag
R_tcp_desired = R_tag_filtered × R_tag_tcp_offset
```

例如偏移中有 200 mm 垂直于转轴的分量，方块绕该轴旋转 10°，期望 TCP 位置会沿圆弧变化，起终点直线距离约 34.9 mm；若偏移平行于转轴，该分量不产生绕转。因此，不能仅检查标签中心移动量，也不能把“方块只旋转”理解为机械臂只有腕部转动。

当前相机与法兰刚性连接，理想的完整相对位姿跟随也会保持相机与标签的相对观察视角，这适合末端相机的实际使用。但初始视角本身有歧义时，保持它不会自动消歧；执行滞后、目标过快旋转或遮挡仍可能让标签离开视野，第六步需要先确定合适的观察位置。

当前控制目标是标签中心，不是方块中心。单个标签刚性固定时，记录相对变换已经包含这个原点差异，无需为本次跟随额外估计方块中心。将来支持多面标签时，必须定义统一方块坐标系，并标定每个标签到该坐标系的固定变换；切换可见标签不能切换目标坐标原点或轴向。

拟保留 `follow_mode=position|pose` 两种启动模式，默认仍为现有 position，pose 为本次目标。`position` 保持现有基坐标位置偏移和固定末端旋转；`pose` 保持完整相对变换。停止并退出后再切换，每次 S/start 重新记录当前关系。现有 `tracking_mode=legacy|collision_guarded` 表示防碰撞选择，不能混用为位姿模式。

“固定基坐标位置偏移、仅改变末端姿态”与完整相对位姿不是同一种行为，本轮不将其作为默认，也不增加第三种必要运行模式。Yaw 单轴先作为调试/验证方式；只有现场明确限制方块始终平放时，才考虑增加带平面约束的 XYZ+Yaw 模式，不能用它冒充任意倾斜目标的六自由度跟随。

### 7.6 第九步：接入真实六自由度位姿跟随

目标：在第六步可信范围和第八步已验证的执行能力内，闭合完整位姿跟随。

2026-10-10 已实现 `pose_follow` 和独立 `start_pose_follow.sh`，并构建安装。沿用配对可信观测、唯一 SDK 所有者与 T/S/X；每次 S 从当前实际位姿重新记录完整关系。默认采用 0.8 s 姿态滤波、6°/4°死区、0.5 映射，允许延迟和残差。独立范围初版为 100 mm/20°；三轮现场测试后位置扩大到 200 mm；最新现场 20.36°误触发后扩大到 500 mm/90°，新增 4 mm/2°到位保持、8 mm/4°新目标阈值及 0.2 s 可信图像确认，并使用第九步单独的 35°候选差异容差，与旧位置及只读配置分开。开启模型时新增完整旋转路径及角制动预测；关闭时保留数据、范围、控制器和停止处理。

控制核心、质量暂停恢复、反馈异常、纯旋转附件扫掠、真实 Python 坐标/质量链接入模拟驱动及完整启动退出均已通过软件验证；所有执行测试使用 MockClient，真实伺服命令为 0。现场从静止、缓慢明显转动方块及小幅组合开始，操作见 [第九步位姿跟随操作](目标跟踪第九步位姿跟随操作-20261010.md)，验证证据见 [stage9](../evidence/target_follow/stage9/README.md)。此前约 40 mm 的跨视角基坐标差异仍保留为首轮运行合理性检查，未被软件测试解释。

控制起点：

```text
e_p = p_tcp_desired - p_tcp_actual
e_R = Log(R_tcp_desired × transpose(R_tcp_actual))^vee
v_base = Kp_position × e_p
omega_base = Kp_rotation × e_R
R_reference_next = Exp(hat(omega_base) × dt) × R_reference
```

`e_R`、角速度与旋转更新均采用基坐标表达，`Log` 取最短旋转；不能混用基坐标误差与工具坐标角速度。发送循环生成连续位置/旋转参考，闭环误差来自实际完整 TCP 反馈，视觉只更新低频目标。精确 180° 的方向歧义需要确定一致选择；首次实机使用小角度范围，不能直接测试大角度翻转。

要做的内容：

1. 将配对后的可信基坐标位姿接入驱动，新增完整位姿控制核心，保持现有 position 路径可用。T 记录但不运动；S/start 检查新鲜可信位姿后重新记录相对关系并开始；X/stop 继续走既有 SDK 停止路径。
2. 分别限制线速度、线加速度、角速度、角加速度。目标旋转造成的绕转速度约为 `omega × (R_tag × d_tag)`，应结合偏移长度协调线/角限速，避免大偏移下姿态已经转到而位置长期跟不上。增加旋转死区/滞回作为抖动调节，数值由第六步记录确定。参考相对实际反馈的超前同时检查位置和旋转；反馈跟不上时不持续积累旋转命令。
3. 对完整期望 TCP、实际 TCP 和发送参考检查位置范围，对姿态检查相对开始姿态的角度范围。原始可信目标与滤波目标都检查，不能由低通把越界掩盖。当前 position 的 1 m 半径不直接作为姿态实测空间的依据；位姿 Demo 使用独立 1 米 TCP 半径和 90° 转角范围。两项限制同时生效，偏移较长时位置范围可能先触发。
4. Demo 对短暂歧义/重新确认冻结上次接受的完整目标，在最后可信图像仍未超过 350 ms 新鲜度时允许继续向该固定目标收敛，避免每次质量波动都启停；坏帧和保持状态不能刷新可信时间戳，也不能更新旋转及位置绕转。长期无可信观测、标签丢失、显著跳变、目标超时或反馈异常时暂停整个 pose 跟随并结束伺服，不静默切换模式。恢复需连续可信、目标仍在原范围且位置/旋转变化可接受，从实际 TCP 重新锚定参考并清零线/角速度，保留原关系。大幅重定位需明确提示并由 S/start 重新记录，避免自动跳追。
5. 扩展可选防碰撞：现有检查能测当前完整机器人状态，但预测只覆盖固定旋转的平移。新预测沿实际 TCP 到未来 TCP 的平移+旋转路径换算法兰，包含参考超前、角速度、角制动与结果延迟，再检查关节连续性、夹爪和相机扫掠。纯旋转也必须触发预测；检查结果过期或旋转方向变化不能继续使用旧结果。
6. 保留 `collision_enabled=false/true` 的启动选择。开启时只有完成旋转预测适配后才允许 pose 运行；未适配时明确拒绝该组合。关闭时保留数据质量、位姿范围、速度/加速度、控制器状态与停止限制。新实现需关注原防碰撞频繁启停问题，避免每个微小方向变化都触发启停；不能据此继续使用已失效的检查结果。
7. 顺序验证：小幅 Yaw → 小幅 Roll/Pitch → 平移与旋转组合 → 方块停下后的收敛 → 遮挡/歧义/恢复 → 主动停止与重新开始。模拟覆盖这些状态和旋转附件碰撞，现场只检查新增的真实姿态行为，不重复要求前五步的全套验收。

产出：完整位姿闭环、质量暂停/恢复、角度范围、旋转预测适配及两种防碰撞选择的回归，建议证据目录 `evidence/target_follow/stage9/`。

完成标准：缓慢平移和转动方块时，末端位置与姿态共同跟随，记录的相对关系大致保持；停稳、歧义暂停、遮挡恢复和主动停止可用。若受单标签视野限制，只声明已验证的可见范围，不宣称全方位连续跟踪。
