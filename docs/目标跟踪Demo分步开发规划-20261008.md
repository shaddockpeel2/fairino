# FR3C 目标跟踪 Demo 分步开发规划

日期：2026-10-08。

目标：已有 30 mm 方块移动时，机械臂末端持续跟随并保持记录的距离和偏移。第一版固定末端姿态，先完成 XYZ 位置跟随。使用方块顶面的 20 mm AprilTag 36h11 / ID 1，沿用当前相机、手眼和 TCP 标定。

第四步按现场诉求追加机器人/夹爪/相机模型与固定 XY 桌面的轻量防碰撞，后台检查、前台减速或暂停，继续使用现有 SDK 跟踪链路。暂不加入点云/深度，也不增加额外性能达标门槛。操作见《目标跟踪轻量防碰撞使用说明-20261008.md》。

现场卡顿复测后，新增模型防碰撞改为启动时可选：`collision_enabled:=false` 使用之前的跟踪流程（当前默认），true 使用新增模型检查。两种模式共用原速度/加速度/范围配置，切换需停止并重启；仅影响目标跟踪链路。

按当前独立新链路继续开发：**前四步已完成，第四步真实测试效果由用户确认可用；第五步已实现统一 Demo 入口。** 第四步首轮的默认 100 mm 软件范围停止已有日志诊断；第五步沿用工作区当前执行端配置。日常操作见 [Demo 使用说明](./目标跟踪Demo使用说明-20261008.md)。

本规划以能运行、能演示为完成标准。每步只检查与当前功能直接相关的动作和结果，数值指标用于判断问题和调参，不作为必须逐项达标的严格门槛。

## 4. 第三步：原厂伺服执行端——已完成

已新增 `fr3c_follow_driver` 和 `scripts/target_follow/servo_demo.sh`，编译通过，6 项 C++ 测试及 6 项纯模拟 ROS 集成测试通过。用户切到自动模式并确认运动空间后，实机 X/Y/Z 各 5 mm 往返、保持和停止服务均通过，实测轴向位移约 4.99–5.03 mm。途中停止后返回，最终位置距离测试起点约 0.018 mm（控制器反馈）。详见 [执行端说明](../src/fr3c_follow_driver/README.md) 和开发记录。

要做的内容：

1. 建立独立 C++ 执行端，由同一个 SDK 所有者处理反馈与运动，沿用现有反馈的话题和时间戳处理方式。
2. 明确控制点转换：软件跟随点是夹爪 TCP，SDK 指令要与控制器实际工具、工件坐标对应。当前已记录工具 0、工件 0 均为零变换，可以在核对后使用法兰目标，并由软件换算 TCP。
3. 优先使用 `ServoCart`；先不接视觉目标，让末端固定姿态，做约 5–10 mm 的小幅平移、保持和停止。
4. 记录实际调用耗时、发送间隔和运动响应，据此确定发送周期。项目现有 `ServoJ` 的 8 ms 只作为参考；`ServoCart` 不合适时再换执行后端，上层目标计算保持一致。
5. 提供开始和停止操作，节点退出或反馈中断时结束当前运动。

完成标准：三个平移方向与指令一致，动作连续，停止确实生效，执行端可重复启动。做一轮低速小范围验证并留下日志即可，不要求长时间性能测试。

执行端按自己的实际发送周期生成参考。现有 50 Hz `preview_reference` 是从实际 TCP 出发的一步预览，不能直接把它当作任意伺服周期下的命令，也不能把它当作机器人已完成的运动。

当前 SDK 指令周期参数为 8 ms；这些实机测试中发送间隔中位数约 9.7–10.0 ms，P95 最大约 18.8 ms，不是严格 125 Hz。停止与结束接口全部返回 0，反馈确认机器人停止。本步已完成，下一步按该实际执行能力接位置目标。报告：`evidence/target_follow/stage3/live_summary.json`。

## 5. 第四步：接入真实位置跟随

已实现 `fr3c_follow_driver/position_follow`，复用第三步的原厂 SDK 客户端和停止清理，一个所有者负责反馈和运动。第二步的坐标换算在 `transform_only=true` 下继续使用，保留图像时刻插值与手眼/光学坐标链，不再管理执行偏移或发布执行目标。

执行端从基坐标标签位置计算固定偏移目标，使用实际 TCP 反馈和自己的发送周期产生连续参考；保持开始时的末端旋转，并按 TCP 标定换算工具 0 的法兰命令。沿用 Kp 1.5/s、速度 10 mm/s、加速度 30 mm/s²，加入轻量位置低通；启动保持待机，开始操作重新记录当前偏移。

新增 `start_follow.sh`、`follow_control.sh start|stop|teach`；查看器 S 开始、X 停止、T 在停止时记录偏移，并显示真实执行状态。目标超时停止伺服；恢复时检查原跟随范围，从实际 TCP 重新接续。主动停止后需要再次开始，并重新记录偏移。

验证状态：5 项新增 C++ 控制测试、5 项独立 ROS 模拟测试通过，覆盖三轴跟随与停稳、完整图像时刻坐标链、组合运动、遮挡与恢复、主动停止、重新开始和范围停止。原有 6 项 C++、28 项 Python/ROS 测试回归通过。模拟启动入口也验证了读取标定、待机零命令和 Ctrl-C 清理。所有模拟报告的真实伺服指令数为 0；实机首轮位置跟随已运行，补充结果如下，不以模拟结果替代。

运行方法见 [执行端说明](../src/fr3c_follow_driver/README.md#第四步固定姿态-xyz-跟随)，证据在 `evidence/target_follow/stage4/`。

实机首轮：用户确认方块移动时机械臂跟踪良好，约 320 秒内 39,283 条 ServoCart 返回码均为 0。随后方块相对开始位置的三维估计位移约 100.3 mm，触发默认 100 mm 软件范围停止；StopMotion 和 ServoMoveEnd 返回 0。范围以每次开始位置为中心，判断三维直线位移，不能理解为每个轴都可移动 100 mm。查看器已补充范围停止和具体原因提示；进入 fault 后重启执行端，再按 S 记录新的偏移。日志与诊断位于 `evidence/target_follow/stage4/20261008_160457_830413/`。


实现与现场验证的内容：

1. 沿用已有基坐标位置和误差计算，启动跟随前重新记录当前偏移与固定旋转。
2. 连续计算 `期望 TCP = 当前目标基坐标位置 + 记录的偏移`，利用实际 TCP 反馈产生平滑伺服参考。
3. 先沿用预览的低速起点：位置增益约 1.5/s、速度上限 10 mm/s、加速度上限 30 mm/s²。根据实际动作调整，优先得到肉眼可见的连续跟随。
4. 先移动一个方向，再验证另两个方向，最后组合移动。方块停下时，末端应逐渐收敛并停稳。
5. 目标遮挡或数据过期时停止推进；重新出现后平滑恢复，恢复前检查当前目标仍处于跟随范围。一次停止后重新开始，应重新记录偏移。

完成标准：方块缓慢移动时末端能跟上，固定偏移大致保持，没有明显持续来回振荡；停止、遮挡和恢复操作可用。

第四步沿用目标超时 350 ms、反馈超时 200 ms；跟随范围默认是开始时实际 TCP 周围半径 0.10 m，可根据现场空间调整。实际运动时检查停止与恢复是否合适后再确定参数，避免把正常一两帧未识别当故障，也不延用长时间丢失的目标。保持速度限制、有限跟随空间和明确停止操作即可。
