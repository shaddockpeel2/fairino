# 2D 方块跟踪「移动不明显」诊断与调参记录

日期：2026-09-22  
对象：第五步真机 2D 闭环（`fr3c_visual_servo` + MoveIt Servo + `fairino3mt_execution_controller`）

## 1. 结论

闭环没有坏，方向正确、误差单调收敛，但**太慢**，慢到肉眼判断为「没有移动」：

- 有效逼近速度实测约 `0.35 mm/s`，图像误差时间常数约 `77～87 s`；
- 像素误差小于约 `55 px`（≈33 mm）时，控制器按设计输出**零速度**，机械臂完全不动。

三项原因按影响排序：

1. **死区在桌面上太大**：`exit 55/45 px`，本相机约 `0.6 mm/px`（实测 0.68 mm/px），
   即方块偏离中心 33/27 mm 以内机械臂一律不动。
2. **比例增益太小**：`gain = 0.020 m/s per 640 px`；典型误差 40～80 px 只给出
   1.3～2.5 mm/s 指令，永远到不了 5 mm/s 上限（要到 160 px 才饱和）。
3. **控制链只兑现约 28% 指令速度**：Servo→JTC→ServoJ 稳态速度损失约 3.5 倍。
   该比例在第四步短脉冲、今日复核脉冲和 120 s 闭环三处独立复现，属系统特性，不是偶发。

第四项次要原因：相机 8 FPS、偶发 0.3 s 长间隔；`observation_stale_s=0.40` 时近一半时间
处于 `LOST_HOLD` 零指令（第一次 120 s 运行 532/1150 个采样），改 0.65 s 后降到约 3%。

## 2. 实测证据

### 2.1 两次 120 s 真机闭环（`execute:=true`）

| 项目 | `live_120s.json`（stale 0.40 s） | `live_120s_065.json`（stale 0.65 s） |
| --- | ---: | ---: |
| Action 结果 | 错误码 5 `target_stale` | `OK` 120 s |
| 中心静默时间 | 前 70 s 全为零指令 | — |
| 实际跟踪窗口 | 28.8 s | 34.8 s |
| 指令幅值 | 1.3～2.0 mm/s | 1.3～2.0 mm/s（max 1.99） |
| 累计指令位移 | 29.8 mm | 56.2 mm |
| TCP 实测位移 | — | **13.1 mm（23%）** |
| 结束误差 | — | `[-39.4, -7.7] px` |

`live_120s_065.json` 跟踪窗口内误差从 `-60.2 px` 单调降到 `-39.7 px`，用时 34.8 s：

```text
收敛速率 = 20.5 px / 34.8 s = 0.59 px/s ≈ 0.35 mm/s
链增益   = 0.35 mm/s ÷ 1.6 mm/s ≈ 22%
```

### 2.2 短脉冲复核（本次新增）

`tools/stage4_direction_pulse.py x+ --operator-ready`，0.005 m/s、0.5 s、名义 2.5 mm：

| 指标 | 2026-09-22 10:32 基线 | 本次复核 |
| --- | ---: | ---: |
| 沿指令方向 TCP 位移 | 0.715 mm | **0.698 mm（28%）** |
| Servo 关节目标最大增量 | 0.002017 rad | 0.002058 rad |
| JTC 输出最大增量 | 0.001607 rad | 0.001622 rad |
| 关节反馈最大增量 | 0.000771 rad | 0.000915 rad |
| Servo 状态 / 结束控制状态 | 0 / `monitoring_manual_ready` | 0 / `monitoring_manual_ready` |

两次相隔约 8 小时、方向相反的工作负载下结果一致，说明 28% 是稳定系统特性。

### 2.3 失配模型

Servo 每个周期用「实时关节状态 + `v × publish_period`」生成单点目标，下游 JTC/ServoJ
跟随存在约 `τ ≈ 0.37 s` 延迟，于是实测速度近似：

```text
v_realized ≈ v_cmd × publish_period / τ
```

两个数据点均吻合：`T=0.02 s → 5%`（0.102 mm / 2.0 mm），`T=0.10 s → 28%`（0.698 mm / 2.5 mm）。
尚未做 `T=0.20 s` 验证，见第 5 节。

有 3 cm 以上、且增益太小。

## 5. 后续可选实验（都需要重新做短脉冲复核）

1. **Servo 周期加倍**：`servo_publish_period:=0.20`，用同一条
   `tools/stage4_direction_pulse.py x+ --operator-ready` 复测。若位移从 0.70 mm 升到约
   1.4 mm，则第 2.3 节模型成立，链路损失可直接用周期补偿，属最干净的提速手段。
2. **提高上限**：`max_speed_mps` 0.005 → 0.010（规划中已允许的下一步）。实测 TCP 速度会到
   约 2.5 mm/s，肉眼明显；但超出第四步已验证包线，必须先补方向与停止复核。
3. **拍照与长帧间隔**：若提高到 10 FPS 或减少偶发长间隔，可把 `observation_stale_s`
   收回接近 0.25 s 的原始指标。

在没有完成第 1 或第 2 项之前，不要通过继续加大 `gain` 来提速：`gain ≥ 0.08` 后指令已
长时间处于 5 mm/s 饱和，继续加大只会让饱和区更宽，不会提高实际速度。

## 6. 当日实机验证结果（闭环 A/B）

三组真机闭环，起点都是把红块放在画面中心右侧、指令立即饱和到 5 mm/s：

| 配置 | 起始误差 | 前 10 s 收敛速率 | 进入中心区 | TCP 实测位移 / 指令积分 |
| --- | ---: | ---: | ---: | ---: |
| `gain=0.02`、`T=0.10`（原始） | 60.2 px | 0.59 px/s | 34.8 s 内未达成（仍差 39.7 px） | 13.1 / 56.2 mm = 23% |
| `gain=0.08`、`T=0.10` | 60.1 px | 1.65 px/s | 24.2 s | 23.5 / 103.2 mm = 23% |
| **`gain=0.08`、`T=0.20`（定版）** | 70.2 px | **2.51 px/s** | **20.5 s** | 29.9 / 86.0 mm = 35% |

- 相对原始配置，像素误差收敛速度提升 **4.3 倍**；三种配置的 `servo_status` 全程为 0，
  每次结束都回到 `monitoring_manual_ready`。
- 定版后又保持 39 s 稳定在 `23.0 ± 0.3 px`，无抽动、无漂移；`LOST_HOLD` 占比约 3%。

### 6.1 Servo 周期标定（0.005 m/s、0.5 s、名义 2.5 mm 短脉冲）

| `servo_publish_period` | 实测 TCP 位移 | 兑现率 | 最大 TCP 速度 | 证据 |
| ---: | ---: | ---: | ---: | --- |
| 0.10 | 0.698 mm | 28% | 2.2 mm/s | `pulse_recheck_x_plus_20260922.json` |
| **0.20** | **1.239 mm** | **50%** | **4.4 mm/s** | `pulse_T200_x_plus_20260922.json` |
| 0.30 | 1.393 mm | 56% | 4.9 mm/s | `pulse_T300_x_plus_20260922.json` |

`0.20 → 0.30` 只多 12%，却把目标流降到 3.3 Hz 的粗阶梯，因此**定版取 0.20**。
注意短脉冲的兑现率（50%）高于闭环实测（35%）：闭环里还包含 `LOST_HOLD` 零指令段、
加减速段和方向微调，不能直接用脉冲比例外推闭环。

### 6.3 剩余瓶颈与后续选项

- 闭环实际 TCP 速度上限约 **2.2 mm/s**（5 mm/s × 闭环兑现 35%），再要更快只剩两条路：
  1. `max_speed_mps` 0.005 → 0.010（规划允许的下一步；需要先改
     `tools/stage4_pulse_logic.py` 的 `MAX_SPEED_MPS`，并按同一流程复核方向与停止）；
  2. 继续压缩死区（`enter 24/18 → 12/9 px`），代价是机械臂更频繁地微调。
- 不要再加大 `gain`：0.08 已让指令长时间停在 5 mm/s 饱和，加大只会扩大饱和区。
- 第五步必测场景中还剩：第二块同色方块、持续遮挡终止、非零 `max_duration_s`、
  抓取/轨迹互斥、接近 `max_relative_xy_m` 边界、Servo 警告注入等。
