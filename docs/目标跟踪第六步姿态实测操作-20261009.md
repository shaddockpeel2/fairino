# 第六步姿态实测操作

本步记录方块姿态，不驱动机器人跟随。先在原位置 Demo 窗口按 X 停止，再在其启动终端 Ctrl-C 退出。以下命令可在 SSH 的同一个终端逐条执行，脚本会自动加载环境。先做静止和方块旋转，将数据分析清楚后再做机械臂示教旋转。

用户已将验收目标调整为可展示的近似姿态跟随，允许几度误差与响应延迟。以下任一命令可追加 `quality_profile:=demo`，使用 0.10 px 歧义阈值与 2 帧确认；不加仍是原保守检查。先退出旧检测/采样再启动，复用外部检测器时不会改变其阈值。此配置已经可用；后续死区、滤波与实际姿态跟随尚待开发，详见 [Demo 阈值分析](../evidence/target_follow/stage6/manual_20261009_101620/demo_threshold_analysis/README.md)。

```bash
export FR3C_FOLLOW_DOMAIN_ID=187
stage6_run_dir="/home/industio/fairino_ws/evidence/target_follow/stage6/manual_$(TZ=Asia/Shanghai date +%Y%m%d_%H%M%S)"
```

## 1. 静止采样

```bash
/home/industio/fairino_ws/scripts/target_follow/start_orientation_check.sh --no-view \
  scenario:=static duration_s:=30 output_dir:="$stage6_run_dir/static"
```

方块和机械臂保持静止，标签完整可见，等待程序自动结束。不要在这组里调整方块角度或机器人位置。记录时长包含启动等待，实际图像数据可能略短于 30 秒。

## 2. 方块旋转

```bash
/home/industio/fairino_ws/scripts/target_follow/start_orientation_check.sh --no-view \
  scenario:=target_rotation duration_s:=90 output_dir:="$stage6_run_dir/target_rotation"
```

机器人保持静止。等终端开始持续输出 `Orientation:` 后，先静止约 5 秒，再依次完成：

1. 标签平面内顺、逆时针缓慢转动约 5–10°，每次停留 3–5 秒，然后回原位。
2. 方块前后倾斜约 5–10°，停留后回原位。
3. 方块左右倾斜约 5–10°，停留后回原位。
4. 遮挡标签 1–2 秒，再放开并保持静止数秒，检查恢复。

尽量让方块中心位置接近原位，始终保持标签清晰可见。`valid` 表示当前姿态通过检查；`orientation_ambiguous` 或其他拒绝状态也需要保留，它们是分析可用范围的数据。持续无图像或无反馈时，先中止并检查启动日志，不必继续转动。

## 3. 机械臂示教旋转

```bash
/home/industio/fairino_ws/scripts/target_follow/start_orientation_check.sh --no-view \
  scenario:=robot_rotation duration_s:=60 output_dir:="$stage6_run_dir/robot_rotation"
```

固定方块，使用示教器低速分别做小角度姿态调整，每次约 2–3°，停留数秒，再回原位。保持标签在画面内，并留出夹爪、相机及工作台之间的空间。无需强求 TCP 位置完全不动；分析会同时使用实测法兰位姿。相机随机械臂改变视角时，换算后的方块基坐标姿态应基本稳定。

## 完成与数据位置

每组自动结束后会打印报告并返回终端提示符。有效报告应满足 `paired_observations > 0`，且 `duration_s` 接近设定时长；`trusted_orientation_observations` 可以是零，届时分析具体拒绝原因。程序未完成时不要关闭整个终端。Ctrl-C 可提前结束并保存已收到的数据。

每个子目录包含 `report.json`、`samples.jsonl`、`session.json` 和 `ros_logs/`。全部完成后执行：

```bash
echo "$stage6_run_dir"
```

将输出的目录路径发给我即可，我可以直接读取本机文件分析。只有定义 `stage6_run_dir` 而未传 `output_dir:=...` 时，记录仍保存到脚本打印的默认会话目录。

`samples.jsonl` 当前也记录已有的 `/target_follow/robot_feedback`，包括工具号、工件坐标号和对应变换，用于核查固定方块时的基坐标一致性；不会增加运动接口或 SDK 调用。2026-10-09 靠近相机后的数据发现跨观察位置的坐标差异，下一组优先按 [对照分析中的往返步骤](../evidence/target_follow/stage6/manual_20261009_101620/closer_camera_analysis/README.md#下一组固定方块机械臂往返) 在一次连续采样里验证。

需要现场图像时，在有显示环境的终端去掉 `--no-view`；窗口标题为 READ ONLY，T/S/X 不调用控制服务。采样完成、窗口关闭、Q/Esc 或 Ctrl-C 会结束本次启动的只读节点。

## 2026-10-09 提前退出问题

`20261009_100158_54440/report.json` 的记录时长只有约 0.12 秒，配对观测为零，因此不能用于姿态分析。查看器先退出触发整套关闭；本机 OpenCV 4.5.4 GTK3 不支持 `WND_PROP_VISIBLE`，返回 -1，旧代码将它误判为窗口已关闭。修复后改用该后端支持的属性判定窗口是否被移除。

同次关闭中，反馈节点在 SDK 连接期间收到中断，后续 ROS 初始化失败时可能跳过 `CloseRPC`，导致原厂后台线程仍使用已释放对象。现已将连接移到节点完成构造之后，确保连接中断或返回失败时都会清理。窗口问题依据本机验证及 [OpenCV 4.5.4 GTK 源码](https://github.com/opencv/opencv/blob/4.5.4/modules/highgui/src/window_gtk.cpp#L2001)；修复验证数据位于 `evidence/target_follow/stage6/window_fix_*`。
