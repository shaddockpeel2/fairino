# FR3C P1 欠速复核与修复路线

日期：2026-09-23。范围：现有真机证据离线复算；未启动或接管机械臂。

## 结论

P1 仍未通过。最有证据支持的解释是 **反馈位置锚定的单周期目标与执行端跟随动态不匹配**。
不能将本次 1.04% 指令窗兑现率解释为 Twist 被 `scale.linear=0.01` 再乘了一次，
也不能仅凭这次结果断言必须换 UDP/ServoCart。推荐先隔离验证 ServoJ 对连续参考轨迹的
跟随能力，再决定是否实现带跟随误差约束的参考积分后端。当前没有已验证的真机修复。

## 可复算的新证据

原始数据：`evidence/P1_execution/forward_020_xplus_0p5s.json`，不修改。
分析输出：`evidence/P1_execution/forward_020_reanalysis_20260923.json`。
分析模型：`evidence/P1_execution/reanalysis_robot_20260923.urdf`，由当前工作区 xacro 展开。
输出包含输入文件 SHA256、模型 SHA256、逐样本计算和对齐方式。

将 forward 六轴目标和最近收到的六轴反馈分别做 `base_link → grasp_frame` FK，
计算沿 x+ 的 `FK(q_target) - FK(q_actual)`，排除起始 0.1 s 后：

| 指标 | 结果 |
|---|---:|
| 5 mm/s × 20 ms 的理论单周期增量 | 0.1000 mm |
| 目标领先反馈的中位数 | 0.09927 mm |
| 目标领先反馈 P10 / P90 | 0.09224 / 0.10012 mm |
| 排除起始段后的配对样本 | 19 |
| 全部配对反馈接收年龄中位数 / 最大值 | 4.61 / 11.72 ms |
| 因缺少近期反馈而跳过的目标 | 0 / 25 |

这说明单周期目标距离基本正确。之前用“目标轨迹自身移动速度很低”推断输入缩放，
混淆了**目标相对反馈的距离**与**目标随时间的累计位移**。

原始记录中的最终沿轴位移仍为 0.155 mm（名义 2.5 mm），指令阶段位移 0.026 mm。
ServoJ interval P99/max 为 11.676/14.514 ms，没有出现足以单独解释几十倍欠速的
发送周期中断；但 RPC 成功和发包周期正常不等于控制箱实际执行及时。

限制：记录没有 Servo 内部状态采样时间、实际生效参数完整快照或控制箱内部参考轨迹。
这里按本机配置和证据 schema 的 joint1..joint6 顺序分析，模型是当前工作区重建，
不是采集时存档。接收时间对齐不能消除 SDK 状态缓存、DDS 和 TF 延迟；本次 0.5 s
短脉冲也不足以识别稳态增益或精确时间常数，不能把 1.04% 称为稳态速度兑现率。

## 源码解释

本机 Debian 包报告 `ros-humble-moveit-servo 2.5.10-1jammy.20260910.035247`。
核对同版本上游
[servo_calcs.cpp](https://github.com/moveit/moveit2/blob/2.5.10/moveit_ros/moveit_servo/src/servo_calcs.cpp)：

- `speed_units` 分支计算速度乘周期，不使用 `linear_scale`。
- `updateJoints()` 从实际状态更新内部关节位置；`internalServoUpdate()` 使用这个反馈基点。
- `applyJointUpdate()` 在该位置加本周期关节增量，再做平滑。

对应简化关系：`q_out[k] ≈ filter(q_actual[k] + qdot[k] × T)`。
当执行端追不上时，每周期重新贴着实际位置生成小目标，参考不会像连续轨迹一样向前积累。
这与本次约 0.1 mm 的实测目标领先量相符。它解释了为什么去掉 JTC 后仍慢，
但未单独证明慢响应来自控制箱滤波、ServoJ 参数、缓存延迟中的哪一项。
上游标签源码用于语义核对，不声称已验证本机二进制的全部发行补丁。

## 推荐修复顺序

1. **先做执行端隔离，避免选错架构。** 在 mock 中准备有界连续关节参考 ramp，
   从实测位置初始化，保持相同起始姿态、低速和短距离，用同一 ServoJ 路径比较
   “累计参考”与“反馈加单步”。任何后续真机 A/B 必须保留租约互斥、状态新鲜度、
   碰撞/限位/工作空间校验和超时停止，不能直接运行绕过现有保护的裸 SDK 脚本。
   同时补采命令生成、hardware write、控制箱反馈时间戳及参数快照。
2. **若连续参考能正常兑现，优先修复参考生成。** 建立专用的受约束关节速度到位置
   适配器，以经过 Servo 约束的速度在执行周期内积分参考；或在 Servo 内维护有界的
   预测参考状态。启动、租约切换与恢复时以实测位置重置。必须针对本机 Servo
   版本验证输出速度及停机语义，不能假设更改一个 YAML 字段就完成修复。
3. **累计参考必须有边界。** 限制位置跟随误差、参考领先距离、速度与加速度；
   一旦跟随误差持续超限，停止并锁存，禁止积累运动欠账。碰撞与限位检查要覆盖
   实际状态到待执行参考的区间，不能只检查某个孤立点。零命令、输入超时、取消、
   反馈陈旧和控制器释放均不得继续积分，也不能让旧远端目标无限追赶。
4. **若连续参考同样欠速，再优先处理厂商执行层。** 核对控制箱/SDK 版本、ServoJ
   推荐周期和参数、内部滤波/延迟，再进行厂商支持的 UDP 或 ServoCart 受控 A/B。
   当前证据不足以保证更换传输或笛卡尔接口有效。

注意：不能把 `q_out[k] - q_out[k-1]` 当成期望速度再积分——它已经包含本次欠速。
也不能在外部简单放大 `(q_out - q_actual)`，因为滤波、时间对齐和碰撞减速都会改变
它的含义。不能将虚构的参考状态发布到公共 `/joint_states` 来欺骗规划场景。

不推荐：提高 Twist 增益、增大 publish_period、将 scale.linear 改为 1 来试运气，
或把无界积分直接加进现有硬件接口。它们不能提供可验证的执行和停车行为。

另一个配置问题：当前 P1 launch 的提示称空 smoothing 插件名可禁用平滑；本版本
源码会无条件加载插件，空名称会导致加载失败。不能把此参数用作“关闭滤波”试验。
