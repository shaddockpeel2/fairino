### 1.3 已完成的恒定 Twist 实机隔离试验

成功证据：

`evidence/optimization/constant_twist_x_plus_20260923_1004.json`

试验条件：

- 完全绕过目标检测、视觉状态机和死区；
- 基坐标 `x+`；
- 恒定 `5 mm/s`；
- 持续 `2 s`；
- 理论位移 `10 mm`；
- 测试前同步了地面碰撞物；
- 测试后安全释放控制权并恢复 `monitoring_manual_ready`。

实测结果：

| 指标 | 结果 |
|---|---:|
| 指令期间 TCP 位移 | `1.61 mm` |
| 零命令后继续移动 | `0.39 mm` |
| 最终总位移 | `2.02 mm`，约理论值的 `20%` |
| JTC 参考关节速度中位数 | `0.0200 rad/s` |
| 实际关节速度中位数 | `0.00383 rad/s`，约参考值的 `19%` |
| MoveIt Servo 输出频率 | `10.01 Hz` |
| 带速度的 Servo 轨迹点 | `20/20` |
| ServoJ 调用间隔中位数 | `8.00 ms` |
| ServoJ 调用间隔 P99 / 最大值 | `13.70 / 28.90 ms` |
| ServoJ RPC 耗时中位数 | `3.79 ms` |
| ServoJ RPC 耗时 P99 / 最大值 | `9.64 / 13.79 ms` |
| Servo 状态 | 全程 `0` |
| 最终控制状态 | `monitoring_manual_ready` |

结论：视觉逻辑不是唯一根因。位置+速度轨迹和 JTC 三次插值已经生效，但仍存在
明显欠速、拖尾和周期长尾。不能靠更换 6D 感知算法解决执行层问题。

### 1.4 当前 V1 算法问题

当前 `control.py` 存在以下结构性限制：

1. 只用目标质心 `(u,v)`，最多直接约束两个视觉自由度；
2. 把画面中心隐式当成期望相机/工具相对位姿；
3. 没有目标速度状态，没有速度前馈和延迟预测；
4. 进入中心区或确认中心时直接把命令设为零；
5. 目标失效时也直接清零，没有区分正常减速、观测丢失停车和硬故障停车；
6. 状态机切换与机械层滞后叠加，容易形成走—停—拖尾—反向修正；
7. 2D JSON 观测接口无法自然扩展到带协方差和速度的通用目标状态；
8. Python Action 循环适合任务编排和安全监督，不适合承担最终高频实时伺服。

## 2. V2 架构决策

### 2.1 不再把“2D”和“3D/6D”做成两套系统

V2 从第一天使用统一的目标状态和 SE(3) 接口。所谓 2D、3D、6D只是
“本次目标有哪些可观测且允许控制的自由度”，通过 DOF mask 选择：

| 场景 | 推荐可观测/控制自由度 |
|---|---|
| 旧 HSV 质心兼容模式 | `x, y` |
| 桌面 RGB-D 方块 | `x, y, z, yaw` 或 `x, y, yaw` |
| 姿态固定、只追随位置 | `x, y, z` |
| AprilTag / 可靠模型位姿 | 完整 6D |
| 对称纯色方块 | 平移 + 可稳定观测的旋转，不强控等价姿态 |

纯色立方体具有旋转对称性。若感知无法区分多个等价姿态，控制器必须显式忽略这些
自由度或进行 symmetry-aware 误差计算，不能把姿态跳变直接送入机械臂。

### 2.2 成熟组件的职责边界

| 层 | 推荐实现 | 是否自行开发 |
|---|---|---|
| 目标检测/身份 | AprilTag、现有 HSV、RGB-D 几何、FoundationPose 等插件 | 只开发适配和项目目标逻辑 |
| 目标状态 | 统一 typed ROS message | 项目定义 |
| 估计与预测 | alpha-beta / 常速度 EKF 起步 | 项目集成和参数化 |
| 视觉控制律 | ViSP IBVS、PBVS 或 Hybrid | 优先复用 ViSP |
| 微分运动学和约束 | MoveIt Servo | 复用官方组件 |
| Servo 控制器 | ros2_control forward controller 起步 | 配置与少量桥接 |
| FAIRINO 实时执行 | ServoJ/ServoCart 适配、超时、故障和通信 | 必须项目验证 |
| 任务、安全与互斥 | Action、租约、看门狗、规划场景 | 复用并泛化现有代码 |

ViSP 参考：

- https://github.com/lagadic/visp
- https://github.com/lagadic/vision_visp
- https://github.com/lagadic/visp/blob/master/example/servo-universal-robots/servoUniversalRobotsIBVS.cpp

注意 ViSP 核心仓库为 GPL-2.0，并提供商业授权选项。商业闭源交付前必须完成许可证评估。

### 2.3 推荐总数据流

```text
目标状态提供器
  ├─ AprilTag provider（V2 基准）
  ├─ RGB-D cube provider（项目目标）
  ├─ FoundationPose provider（可选，取决于 GPU/许可证/性能）
  └─ legacy HSV provider（兼容和退化模式）
                  │
                  ▼
         TrackedObjectState
   pose + twist + covariance + stamp
       + track_id + confidence + DOF
                  │
                  ▼
       target_state_estimator
   时间同步、异常值拒绝、速度估计、预测
                  │
                  ▼
        visual_servo_controller
   ViSP PBVS/IBVS/Hybrid + DOF mask
   目标速度前馈 + 位姿反馈 + 限幅
                  │ TwistStamped
                  ▼
           MoveIt Servo C++
   关节限位、奇异点、碰撞、平滑
                  │ Float64MultiArray
                  ▼
    fairino3mt_servo_position_controller
      ForwardCommandController(position)
                  │ position interface
                  ▼
          FairinoHardwareInterface
   固定周期积分/保持、命令超时、故障锁存
                  │
                  ▼
       ServoJ（优先验证 UDP 能力）
```

规划抓取链保持不变：

```text
MoveIt 规划轨迹 → fairino3mt_execution_controller（JTC）→ ServoJ
```

JTC 和 Servo forward controller 必须互斥激活，不能同时占有六轴 position interface。

### 3.3 控制状态

建议统一状态，不再把“中心区”作为核心状态：

```text
IDLE
ACQUIRING_TARGET
ACQUIRING_CONTROL
TRACKING
SETTLING
OBSERVATION_LOSS_STOP
SAFETY_STOP
RELEASING_CONTROL
FAULT_LATCHED
```

正常达到目标时进入 `SETTLING`，通过限加速度/限急动度把速度连续降到零；不要直接
从非零命令跳到零。

观测丢失、碰撞、急停应分级：

| 类型 | 行为 |
|---|---|
| 正常收敛/目标停下 | 有界减速，保持闭环 |
| 短时观测丢失 | 在严格最大盲行距离内用预测并减速 |
| 持续观测丢失/时间戳过期 | 安全减速并释放控制权 |
| 碰撞、硬奇异点、急停、控制器故障 | 立即进入硬停止/厂商停止路径并锁存故障 |

安全故障优先级高于平滑性；不能为了“看起来不抖”弱化硬停止。

## 4. 视觉伺服控制策略

### 4.1 第一推荐：PBVS/Hybrid，IBVS作为基准

### PBVS

输入：当前目标相对相机/工具的 6D 位姿和期望相对位姿。  
优点：目标状态接口自然、容易加入目标速度前馈和延迟预测、容易按自由度屏蔽。  
缺点：依赖目标姿态质量、相机内外参和深度质量。

### IBVS

输入：AprilTag 四角、点、线、面积等图像特征。  
优点：成熟、闭环直接建立在图像误差上，对部分标定误差更稳健。  
缺点：只有质心时约束不足；可能存在耦合、局部极值和深度估计问题。

### Hybrid / 2.5D

组合图像特征和部分三维位姿。V2 最终产品优先考虑 Hybrid，但第一轮不要同时实现三种。

推荐顺序：

1. AprilTag 四角 IBVS，验证成熟库、坐标和执行链；
2. AprilTag PBVS，验证统一目标状态；
3. 比较两者静态收敛、动态跟踪、遮挡和标定敏感度；
4. 依据结果选择 PBVS 或 Hybrid 作为主控制器。

### 4.2 PBVS 参考控制律

符号在实现时必须写入代码注释和单元测试，避免变换方向歧义。

设：

- `T_camera_target(t_m)`：图像采集时刻测得的目标位姿；
- `T_target_tool_desired`：任务期望的目标到工具变换；
- `T_base_tool(now)`：当前实际工具位姿；
- `V_target`：目标估计 twist；
- `tau`：从采集到命令实际生效的测量延迟。

先预测目标状态，再计算 SE(3) 对数误差：

```text
T_target_predicted = predict(T_target(t_m), V_target, now + tau - t_m)
e_se3 = Log(T_desired_relative^-1 * T_current_relative)
V_tool = V_target_feedforward + K * mask(e_se3)
```

具体伴随变换、twist 表达坐标系和正负号由 ViSP API/所选约定确定，必须用仿真和
四方向/六自由度小脉冲验证，不能只凭公式手写。

### 4.3 状态估计与预测

第一版不需要直接上复杂 MPC。建议：

1. 静态目标：只做异常值拒绝和低通；
2. 动态目标：常速度 alpha-beta 或 EKF；
3. 使用真实时间戳统计端到端延迟；
4. 预测到 `now + measured_command_latency`；
5. 目标启停时限制预测时间，避免遮挡期间持续外推；
6. 速度前馈只在速度估计置信度满足阈值时开启。

验收通过后，若目标速度高、约束强或需要在线截获，再评估 QP/MPC。当前慢速桌面
方块不需要先引入 MPC。

## 5. 执行层重构决策

### 5.1 JTC 的去留

`joint_trajectory_controller` 本身没有通用错误，它适合执行有限、带时间参数的规划轨迹。
问题是当前视觉 Servo 每 `100 ms` 用一个新单点轨迹覆盖旧轨迹，实际系统只能兑现约
20% 指令，并在零命令后拖尾。

决策：

- 规划、抓取、放置、码垛继续使用 `fairino3mt_execution_controller`；
- 视觉伺服新增独立 `fairino3mt_servo_position_controller`；
- 两个控制器通过 controller_manager 和现有租约桥互斥；
- V2 Servo 模式中禁止向 JTC 话题发布单点轨迹。

### 5.2 P1 首选链路

MoveIt Servo Humble 支持：

```yaml
command_out_type: std_msgs/Float64MultiArray
publish_joint_positions: true
publish_joint_velocities: false
command_out_topic: /fairino3mt_servo_position_controller/commands
```

ros2_control 建议新增：

```yaml
controller_manager:
  ros__parameters:
    fairino3mt_servo_position_controller:
      type: forward_command_controller/ForwardCommandController

fairino3mt_servo_position_controller:
  ros__parameters:
    joints: [joint1, joint2, joint3, joint4, joint5, joint6]
    interface_name: position
```

具体 Humble 插件类型和参数必须通过本机：

```bash
ros2 control list_controller_types
ros2 pkg prefix forward_command_controller
```

确认后再写入配置，不从 Rolling/Jazzy 文档盲抄。

### 5.3 输出周期试验矩阵

不要直接把 125 Hz 写死为最终答案。先固定同一恒定 Twist，比较：

| 变量 | 候选值 |
|---|---|
| MoveIt Servo `publish_period` | `0.020`, `0.010`, `0.008 s` |
| `low_latency_mode` | `false`, `true` |
| smoothing | Butterworth 开/关或两组系数 |
| 输出 | JTC 基线、Float64 position forward |

每组必须记录：

- Twist 输入频率；
- MoveIt Servo 输出频率和字段；
- controller command；
- desired/actual joint state；
- TCP 轨迹；
- ServoJ 调用间隔和 RPC 耗时；
- 起动时间、稳态兑现率、零命令后停止距离；
- Servo 状态、控制权和故障清理。

### 5.4 FAIRINO 通信升级分支

当前仓库使用的接口形态对应 V3.9.2，ServoJ 通过 SDK/RPC 阻塞调用。官方后续版本记录
显示 V3.9.4 为 ServoJ/ServoMoveStart 等增加了 UDP 通信类型选项。

在修改 SDK 或控制器固件前，必须向法奥确认：

1. 当前控制箱软件、机器人固件、C++ SDK 的准确版本；
2. FR3-C 是否支持该 UDP 模式；
3. UDP 模式的推荐周期、丢包处理、超时停止和线程模型；
4. SDK 与控制箱升级兼容矩阵及回退方法；
5. ServoJ、ServoCart 的推荐用途；
6. `cmdT=0.008` 与文档其他推荐范围不一致的正式解释。

未确认前不得替换仓库中的 `libfairino.so` 或刷新控制器。

### 5.5 ServoCart 分支

FAIRINO ServoCart 支持基坐标/工具坐标下绝对或增量六维笛卡尔命令。它可以作为独立
A/B 基准，判断 JTC/MoveIt 映射是否是主要瓶颈，但不作为第一默认产品链，因为直接
绕过 MoveIt Servo 后需要自行补齐：

- 关节限位；
- 奇异点处理；
- 自碰撞和环境碰撞；
- 工作空间；
- 速度、加速度和急动度；
- 命令超时和控制权互斥。

只有在 MoveIt Servo + forward controller 仍无法满足，并且 ServoCart 明显更平滑时，
才考虑实现带同等安全约束的 `fairino_cartesian_servo_adapter`。

## 8. 控制权、安全和故障要求

现有 `trajectory_control_bridge.py` 的租约思路应保留并泛化。

### 8.1 控制所有者

```text
IDLE
TRAJECTORY
SERVO_TRACKING_STARTING
SERVO_TRACKING
SERVO_TRACKING_STOPPING
FAULT
```

控制器切换应满足事务语义：

1. 确认旧控制器停止；
2. 确认六轴 command interface 已释放；
3. 同步实际关节位置到新命令初值；
4. 激活新控制器；
5. 启动 Servo；
6. 获得第一条合法命令前保持当前位置；
7. 任一步失败都执行回滚；
8. 回滚失败进入 `FAULT`，禁止新的自动运动。

### 8.2 命令超时

至少有三层超时，但职责不同：

- 目标状态超时：停止目标预测并进入观测丢失停车；
- MoveIt Servo 输入超时：停止生成非零关节流；
- 硬件命令超时：不允许永久保持最后一个运动趋势，进入安全保持/停止。

必须记录究竟是哪一层触发，不能都归类为 `target_stale`。

### 8.3 边界

V2 恢复并强化当前被削弱的边界：

- 相对任务起点最大 XYZ 位移；
- base_link 工作空间多面体/盒；
- 最小桌面高度；
- 姿态偏差；
- 关节软限位；
- 奇异值/条件数；
- self/world collision；
- 最大线速度、角速度、加速度、角加速度和急动度；
- 最大盲行距离。

## 14. 最终架构结论

本项目不应继续沿“2D 成功后复制一套 3D/6D”的路线堆叠功能。

正确的 V2 路线是：

1. 先修复实时执行链；
2. 用统一 6D 目标状态接口解耦感知和控制；
3. 通过 DOF mask 支持二维、三维、四维和六维任务；
4. 使用 ViSP 等成熟视觉伺服控制律；
5. 保留 MoveIt Servo 的运动学和安全约束；
6. 为连续伺服使用专用 controller，不再反复覆盖 JTC 单点轨迹；
7. 让 AprilTag、RGB-D、FoundationPose 或 HSV 只是可替换的目标状态 provider；
8. 让现有控制权租约、安全停止、手眼标定和证据体系成为 V2 的可靠外壳。

V1 不删除，但停止作为产品主线。V2 的第一验收对象不是视觉效果，而是恒定命令下
机械臂能否连续、准确、可预测地运动和停止。
