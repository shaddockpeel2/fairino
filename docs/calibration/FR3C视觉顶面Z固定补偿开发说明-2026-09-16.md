# FR3C 视觉顶面 Z 固定补偿开发说明（2026-09-16）

## 1. 背景与实测依据

使用 `color_top_tcp_contact.json` 在 5 个桌面 XY 位置分别采集颜色/深度顶面与 TCP 实触顶面。视觉顶面相对 TCP 接触点高 `3.595～5.364 mm`，平均高 `4.637 mm`，中位高 `5.150 mm`。单组视觉位置最大偏离仅 `0.16～0.35 mm`，深度有效率为 `97.1%～99.4%`；该现象以稳定的系统偏差为主，不是颜色识别抖动。

当前无法仅凭这 5 组数据严格区分深度绝对距离、手眼 Z 平移和顶面分位提取各自的贡献。因此不改写手眼外参或 TCP，而是在感知输出边界增加一个明确、可关闭、可追溯的固定补偿。

## 2. 参数与符号约定

参数：

```yaml
top_pose_z_compensation_m: -0.004
```

计算：

```text
corrected_top_z = raw_top_z + top_pose_z_compensation_m
```

负值表示沿 `base_link` Z 向下修正。默认 `-0.004 m` 采用比五点中位值更保守的 4 mm，允许范围为 `[-0.020, +0.020] m`；设为 `0.0` 即关闭。

组合启动时可临时覆盖，无需编辑 YAML：

```bash
scripts/run_moveit_camera_rviz.sh detection_mode:=colors \
  top_pose_z_compensation_m:=-0.004
```

修改参数后必须重启感知节点；它不是运行中动态参数。

## 3. 生效范围

补偿在 RGB-D 点云转换到 `base_link`、完成顶面质量检查之后应用，随后统一用于：

- `/perception/blue_cube_localizer/top_pose`；
- `status.center_base_m` 和稳定窗口；
- 四色方块的桌面高度/底面间隙判定；
- RViz 方块 Marker；
- P5 抓取、下降和附着物初始位置。

状态同时保留：

- `raw_center_base_m`：补偿前顶面中心；
- `center_base_m`：补偿后、供任务使用的顶面中心；
- `top_pose_z_compensation_m`：本帧实际使用的补偿值。

点云厚度、深度有效率、候选轮廓尺寸和手眼/TCP 在线一致性检查均不被补偿修改。

## 4. 与放置阶段的关系

补偿不直接修改分拣放置公式。放置 TCP 高度仍为：

```text
区域平面 Z + release_bottom_gap_m + 方块高度 - grasp_depth_m
```

默认值下，任务仍命令方块底面在区域平面上方 5 mm 释放。

但此前视觉顶面高约 4～5 mm，会让抓取 TCP 同样高约 4～5 mm，实际夹持点相对任务模型偏浅；运输到固定放置 TCP 高度后，实物方块底面就会比模型预测更低，因此出现“5 mm 命令间隙但几乎贴面”的现象。视觉顶面下修 4 mm 后，抓取 TCP 相应下降，实际夹持深度更接近 `grasp_depth_m` 的模型假设，从而间接修复放置高度。

## 5. 验证与回退

1. 重启后检查状态同时出现原始值、修正值和 `-0.004` 参数；两种 Z 应严格相差 4 mm。
2. 先以 `FR3C_FIRST_GRASP_EXECUTE=false` 完整规划，确认修正后的抓取下降路径不与桌面碰撞。
3. 只放一个 30 mm 方块，以低速执行抓取和放置，现场测量释放前方块底面间隙。
4. 若仍偏高或偏低，只以 1 mm 步长调整该参数；不得同时修改 TCP、手眼和平面 Z，否则无法归因。
5. 出现碰撞风险、抓取过深或桌面判定异常时，立即停止执行并设置 `top_pose_z_compensation_m:=0.0` 回退。

该补偿是现场测量支持的工程修正，不替代后续不同相机距离、姿态和刚性接触探针的绝对标定试验。
