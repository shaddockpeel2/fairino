# P3 蓝色方块定位使用说明

本文对应单个静止、边长 30 mm 的蓝色方块定位。定位节点不发布机械臂命令，持续输出方块顶面中心候选；P5 只在 `/start` 调用瞬间复制当前 `valid=true` 的稳定位置。

## 1. 设计边界

- 输入固定为 D2C 后的 `/camera/color/image_raw`、`/camera/depth/image_raw` 及各自 `CameraInfo`。原始未配准深度不能替换。
- 先做 HSV 蓝色分割，再做面积、长宽比、凸度和矩形度筛选；只允许一个候选。
- 深度只取候选轮廓的腐蚀内部，经过 RGB 畸变模型到 D2C 深度畸变模型的像素映射后反投影，避免直接取轮廓中心单像素。
- 使用彩色图时间戳查询 `base_link <- camera_color_optical_frame`，机械臂在采样窗口内必须静止。
- 五点 TCP 接触复核确认视觉顶面稳定上偏后，节点默认把顶面 Z 加上 `top_pose_z_compensation_m=-0.004`。状态保留补偿前的 `raw_center_base_m` 和任务实际使用的 `center_base_m`；设为 `0.0` 可关闭，详细依据与放置阶段影响见[视觉顶面 Z 固定补偿开发说明](calibration/FR3C视觉顶面Z固定补偿开发说明-2026-09-16.md)。
- 在线 `flange_link -> camera_link` 必须与已验收手眼 YAML 一致；仅用于 RViz 的安装预览 TF 会被拒绝。
- 在线 `flange_link -> grasp_frame` 必须与当前 TCP YAML 一致。2026-09-11 根据桌面接触时 178 mm 模型仍短约 6 mm 的观察，切换到固定点求解结果 `[-0.847397, 3.027928, 184.614459] mm` 后，用户通过法兰按钮拖拽到桌面接触并确认 RViz 与实物严密对齐；该值现作为首次 RGB 抓取采用值。节点会检查模型是否漏用或重复叠加 TCP。
- 纯色正方体没有可观测的绕 Z 轴方向。输出姿态来自显式参数 `fixed_yaw_rad`，不得描述成视觉估计方向。
- 8 个合格样本满足抖动门限后发布稳定位置；此后视觉继续判断，后续稳定窗口会更新保存位置。
- 单帧误检只令当前 `valid=false`，不会立刻清空之前的合格样本。合格样本间隔超过 0.75 s 或位置跳变超过 20 mm 时才重新建立窗口，防止混合两个目标位置。
- P3 保存“最近稳定位置”和“当前是否有效”两个概念。即使保存位置仍在发布，当前画面不可靠时 `valid` 也会变为 false，运动节点不得使用旧值启动。
- P5 接受 `/start` 后使用内部位置副本；腕部相机随后移动以及 P3 的更新都不会改变该次抓取目标。
- 一轮提升完成后，操作者放好方块并结束法兰按钮拖动，等待 P3 对桌面上的新位置重新变为 `valid=true`，即可再次调用同一个 `/start`；无需 reset P3 或重启抓取栈。

## 2. 启动前提

当前已验收手眼文件为：

```text
/home/industio/fairino_ws/evidence/P13/recalib_40pose_20260914/flange_to_dabai_dcw2.yaml
```

`camera_moveit_demo.launch.py` 现已把这份标定作为默认值；显式命令如下：

```bash
publish_calibrated_tf:=true \
hand_eye_file:=/home/industio/fairino_ws/install/fairino3mt_v6_moveit2_config/share/fairino3mt_v6_moveit2_config/config/dabai_dcw2_handeye.yaml
```

确认在线变换：

```bash
ros2 run tf2_ros tf2_echo flange_link camera_link
```

其平移和旋转必须与 YAML 一致。节点本身还会进行数值核对，默认容差为 0.5 mm 和 0.002 rad。

## 3. 启动定位

在按新默认值重启组合栈、机械臂完全停稳后执行首次抓取专用入口：

```bash
source /opt/ros/humble/setup.bash
source /home/industio/fairino_ws/install/setup.bash
ros2 launch fairino3mt_v6_moveit2_config first_grasp_perception.launch.py \
  fixed_yaw_rad:=0.0 top_pose_z_compensation_m:=-0.004
```

该入口默认同时注入已验收的 `dabai_dcw2_handeye.yaml` 和已标定的 `ydi_j22_tcp.yaml`。通用的 `fr3c_camera blue_cube_localization.launch.py` 仍要求显式传两份文件，避免相机底层包反向依赖机器人配置。

主要接口：

| 接口 | 类型 | 含义 |
| --- | --- | --- |
| `/perception/blue_cube_localizer/status` | `std_msgs/String` | JSON 状态、拒绝原因、样本数和测量统计 |
| `/perception/blue_cube_localizer/valid` | `std_msgs/Bool` | 当前观测窗口稳定且数据新鲜时为 true |
| `/perception/blue_cube_localizer/top_pose` | `geometry_msgs/PoseStamped` | `base_link` 下最近保存的稳定方块顶面中心；使用者必须同时检查 `valid` 和时间戳 |
| `/perception/blue_cube_localizer/marker` | `visualization_msgs/Marker` | RViz 中 30 mm 方块模型，中心位于顶面下方 15 mm |
| `/perception/blue_cube_localizer/debug_image` | `sensor_msgs/Image` | 候选轮廓、像素中心和拒绝原因 |
| `/perception/blue_cube_localizer/reset` | `std_srvs/Trigger` | 调试/换场景时手动清除保存位置和样本；P5 不会自动调用 |

查看状态；只有需要人为清空历史位置时才复位：

```bash
ros2 topic echo /perception/blue_cube_localizer/status
ros2 service call /perception/blue_cube_localizer/reset std_srvs/srv/Trigger '{}'
```

## 4. 现场验收

1. 在 RViz 加入 Marker，主题设为 `/perception/blue_cube_localizer/marker`；加入 Image，主题设为 `/perception/blue_cube_localizer/debug_image`。
2. 先记录静止中心位置的 3 次稳定更新结果，再把方块放到视野内两个周边位置，确认发生位置跳变后会重新积累并更新。
3. 每个位置用独立量具或低风险高净空 TCP 对点测量 XY；Z 必须明确比较顶面而不是方块中心。
4. 收紧 `workspace_x/y/z` 到实测桌面区域。当前默认值只是防止数量级错误，不是 P5 的最终工作区门限。
5. P5 接入前检查 `valid=true`、`stable=true`、`tracking=true`、新鲜时间戳和固定 yaw 配置。P5 会在 `/start` 时保存 status 和 top_pose 的一次性副本。

不得通过放宽手眼一致性容差来完成正式验收。开发时使用宽容差得到的基座坐标只能用于验证代码路径，不能用于运动。
