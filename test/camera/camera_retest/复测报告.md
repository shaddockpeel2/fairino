# Astra Stereo S U3 深度相机复测报告

测试日期：2026-09-09（Asia/Shanghai）  
验证等级：L4，真实相机上电、无机械动作  
环境：Conda `v11`，Orbbec SDK 1.5.7 / Python bindings 1.1.4

## 结论

相机本体能够稳定输出彩色、原始深度和软件 D2C 对齐深度，内参也能正常读取；未发现“深度单位错 1000 倍”或明显的整幅彩深错位。当前最值得处理的是工作距离和时间同步：

1. 设备是 **Orbbec Astra Stereo S U3**，内部名 `SV1301S_U3`，不是 Gemini。
2. 深度值为 `16UC1`，`getValueScale() = 1.0`，即一个原始 LSB 对应 **1 mm**。
3. 初次近距离场景中心约为 **238 mm**，低于该型号 250 mm 的官方起测距离；中心 100×100 区域有效像素仅约 **13.8%**。这会表现为大片 0 值、轮廓破碎和深度不可信。
4. 静态复采在约 **0.75 m**：D2C 中心 100×100 区域有效率 **98.75%**，帧中值标准差 **1.99 mm**，峰峰值 **7 mm**；稳定像素的时间标准差中位数 **2.50 mm**、P95 **6.98 mm**。该距离下可用于抓取前期验证。
5. 软件 D2C 后深度从 640×400 变为 **640×480**，深度内参变成彩色相机内参；对齐深度必须使用 `camera_color_optical_frame`。不能把原始 640×400 深度简单 resize 到彩色尺寸。
6. 彩色帧的相机设备时间戳在 120/120 帧中均为 **0**；深度设备时间戳正常。SDK 硬件帧同步接口返回不支持。应使用两路 `systemTimeStamp()`/ROS 主机时间做近似同步。
7. 最终静态采样中，彩色减深度的主机时间偏差：原始流中位数 **19 ms**、最大绝对值 **37 ms**；D2C 流中位数 **22 ms**、最大绝对值 **36 ms**。静态画面无明显问题，但运动物体或机械臂运动时会产生动态彩深错位。

## 设备与流

- VID/PID：`0x2bc5 / 0x0614`
- 序列号：`AY23B520016`
- 固件：`RD3013`（底层日志另报 FW 5.8.23(14)）
- 连接：USB 3.0
- 彩色：640×480 @ 30 FPS，MJPG，解码为 BGR8
- 原始深度：640×400 @ 30 FPS，16UC1，毫米
- 软件 D2C 深度：640×480 @ 30 FPS，16UC1，毫米
- SDK `enableFrameSync()`：不支持

## CameraInfo 要点

原始彩色：

- `fx = fy = 454.5934`
- `cx = 328.5454, cy = 243.9850`
- 分辨率 640×480

原始深度：

- `fx = fy = 478.3199`
- `cx = 322.1782, cy = 198.0380`
- 分辨率 640×400

软件 D2C 深度：

- 分辨率 640×480
- K/P 与彩色相机一致
- `frame_id` 应为 `camera_color_optical_frame`

完整 K、D、R、P 在 `results/camera_info_raw.json` 和 `results/camera_info_aligned_d2c_software.json`。

## 彩深对齐观察

软件 D2C 叠加图中，桌沿、椅子扶手及人体轮廓没有整幅固定方向的大偏移，说明标定参数与软件投影总体有效。对齐后全画面有效率从原始深度约 **70.02%** 降至 **53.65%**，主要来自两相机视场差异、遮挡边界和无深度区域；它不是单位错误。

当前画面不是专用标定靶，且彩深主机时间差可达一帧左右，因此这里只能排除明显错位。若要验收像素级对齐，应把哑光平面和带清晰边缘的方盒固定在 0.5–1.0 m，静止采集，并在多个深度处检查轮廓重投影误差。

## 抓取使用建议

- 把主要抓取平面放在 **0.30 m 以上**，工程上建议先从 **0.40–1.0 m** 验证；不要把 0.25 m 规格边界当作稳定工作距离。
- 对深度 0 值做无效值处理，不要参与点云、法向或抓取位姿计算。
- 对运动场景用主机时间做 ApproximateTime/最近邻配对；当前相机建议同步容差先设为 40 ms，并监控实际偏差。若抓取过程中机械臂或目标移动较快，需要停稳后取帧，或更换支持硬件同步的 RGB-D 相机。
- 发布对齐深度时，让 Image 与 CameraInfo 使用同一个彩色 optical frame 和对应时间戳。
- 正式抓取前，用已知尺寸/已知距离的哑光靶做 0.4、0.6、0.8、1.0 m 四点绝对误差测试；本次只有稳定性统计，没有外部真值尺，因此不能给出绝对准确度结论。

## 复现

运行 `camera_retest.py` 会连续采集原始与软件 D2C 各 120 帧，并更新 `results/` 中的 JSON、CSV 和 PNG。测试期间应固定相机并清空运动物体，否则帧间标准差会包含真实运动。
